# Growdu 音色

后续视频旁白统一使用这套音色。**规范见 [`../形象与音色规范.md`](../形象与音色规范.md) §2**。

## 定稿参数

```json
{
  "voice_id": "Chinese (Mandarin)_Radio_Host",
  "voice_name": "电台男主播",
  "pitch": -1,
  "speed": 1.33,
  "emotion": "neutral"
}
```

对标参照是一段**定标参照稿**（本机素材，不入库）。实测基频偏差 **+0.1 半音**、
F2 偏差 +31 Hz、动态跨度 107 Hz vs 参照 102 Hz。
参照稿的位置随使用者而定；量它的办法见下面的「这把尺子」。

## 试听样本

试听样本是使用者的本机素材（音频不入库），参数与结论如下：

| 文件 | 配置 | 说明 |
| --- | --- | --- |
| `voice_sample_radio_s133_pm1.mp3` | pitch −1 / speed 1.33 | **定稿**，完整口播稿 |
| `voice_sample_radio_s135_pm2.mp3` | pitch −2 / speed 1.35 | 备选一，动态跨度最接近参照 |
| `voice_sample_southern_s150.mp3` | 南方小哥 / speed 1.5 | 备选二，F1 吻合但听感过于平直 |

## 合成

每期的旁白是**本机产物**：TTS 合成的输出未必逐字节相同，
不入库；口播稿与契约入库，缺了旁白可以按口播稿重新合成。

```bash
cd video/voice
python3 scripts/synthesize_narration.py --text "大家好，我是growdu。"
python3 scripts/synthesize_narration.py --script 字幕.md --out narration.mp3
```

依赖 `mcode-tools` CLI（先加载 `mcode-tools-master` skill）。

## ⚠️ 多音字：这个音色会把词首的「行」念成 xíng

**实测**（2026-11-13）：「行锁」的「行」在 5 个样本里 **5/5** 念成 xíng；
「同一行」「每一行」「每行」「哪一行」「行号」都念 háng（0/5 出错）；
「一行」不稳定（5 个样本里 1 个念 xíng）。

**判据不靠 ASR**：ASR 会按上下文归一化——同一段音频，孤立听它写 `xing2 suo3`，
放进整句里又写 `hang2 suo3`。所以用声学特征量：
`[ɕ]`（xíng）的摩擦噪声集中在 4–6 kHz，`[x]`（háng）在 2–3 kHz。

```bash
cd video/voice
# 量一个词的首字声母（会合成探针，需要联网）
python3 scripts/check_pronunciation.py --word 行锁 --samples 5
# 判据的两端：原词念 xíng、替身念 háng
make -C pipeline pronunciation
```

**绕法**：换**等音字**——连接器封装会丢掉 MiniMax 的 `pronunciation_dict`
（`行锁/pinganpingan` 实测仍念成 `xing2 suo3`），`<phoneme>` 标签会被念出来，
括号里的拼音也会被念出来。

| 原词 | 替身 | 为什么等音 |
| --- | --- | --- |
| 行锁 | 航锁 | 航 = háng，无歧义，声母 [x]、韵母 [ɑŋ]、阳平；整句只差 0.093 s |
| 一行 | 壹行 | 壹 = yī，与「一」同声同调；行跟着读成 háng（实测 5/5） |

规则表在 `scripts/pronunciation.py`，`synthesize_narration.py` 送进引擎前套用，
**口播稿、字幕表、画面契约一个字都不改**，观众听到的仍是「行锁」「一行」。
每次合成还会把**真正送进引擎的那份文本**留底成 `*.spoken.txt`（媒体产物，不入库）。

> 「一行」只在**独立成词**时替换——「每一行」「哪一行」「同一行」里它是词的一部分，
> 而那三个词本来就念 háng，碰了就把对的改成错的。

## ⚠️ 换稿必须重新定标

`pitch` / `speed` 是相对参照稿标定的。口播稿换了（字数、断句不同），语速和
音高分布都会变，直接套用会偏。

重新定标方法（规范文档 §2.1）：

1. 测参照稿的基频 F0 中位、F1/F2 共振峰、频谱重心、语速
2. 用候选音色合成同一段文本，跑同样的四项测量
3. 按 `|ΔF0半音|×3 + |ΔF1|/30 + |ΔF2|/120 + |Δ重心%|/5 + |Δ语速%|/4` 排序
4. 在真实口播稿上做 speed × pitch 网格微调，收敛到时长与语速都对得上

### 这把尺子：`scripts/measure_voice.py`

```bash
cd video/voice
# 量参照稿（路径随使用者而定）
python3 scripts/measure_voice.py --path <参照稿>.mp3 --chars 226
# 量候选稿，并与参照稿逐项比
python3 scripts/measure_voice.py --path 候选.mp3 --chars 255 \
    --ref <参照稿>.mp3 --ref-chars 226
```

**只认差值**：本脚本的测量定义与当初定标时未必一致，绝对值不能直接对规范
§2.1 表里的数（脚本头部的表列了各处口径差异）。参照稿与候选稿用同一把尺子量，
看差多少。

## 定标的四条结论

这四条是方法性的，跟具体哪一期无关：

1. **「字/秒」这个比值会被稿子里的拉丁词抬高或拉低。** 字数口径按字符数算，
   一个拉丁字母被当成一个字，可它念起来比汉字快得多，于是比值失真。
   **这是口径的偏差，不是语速真的变了。**
2. **合成不是确定性的。** 同参数连合成三次，时长相差 ±3.3 %、语速 ±0.24 字/秒、
   F0 ±0.69 半音。所以定标要挑「量出来最贴参照的那一条实例」，
   别把参数当成能复现出同一条音频的承诺。
3. **两项可靠指标冲突时，语速先保。** 可靠的就两项：语速与基频。
   两者打架时先保语速——它直接决定口播念不念得完。
4. **F1/F2 对选参没有影响。** 它由声道长度决定，同一个音色下不随 pitch / speed 变，
   只在换音色时才有区分度。
