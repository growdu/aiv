# 形象与音色规范

> 这份规范是**规则模板**。
> **规则**是框架的（代码照着判），**例子**是你的（照着抄会连着你的形象一起抄走）。
> 身份类的东西——站名、品牌词、落版——一律从 `video/config.toml` 读。

后续视频统一使用**同一套**「模型形象」与「音色」。本文记录**规范本身**（入库、可评审），
图像与音频成品留本机（`character/`、`voice/`，不入库）。

| 类别 | 是什么 | 换人用要不要改 |
| --- | --- | --- |
| **规则** | 配饰规格、合成方式、盖铭牌的做法、眼镜的验收判据 | 不用改——代码照着判 |
| **形象** | 你长什么样：物种、配色、服装 | 换成你自己的；**素材路径从 `video/config.toml` 的 `[assets.mascot]` 来** |
| **音色** | 你怎么说话：音色、语速、音高 | 换成你自己的 |

**为什么这么分**：流水线只认三个接口——「透明底 PNG 在哪」「品牌词是哪个」
「音色参数是什么」。它不认「小象」，也不认「电台男主播」。
形象与音色是使用者的资产（版权、口味都是他的），规则是框架的资产
（两台机器要出一样的片）。

> **素材从哪来**：`video/config.toml`
>
> ```toml
> [brand]
> name = "Growdu"      # 落版与片尾字幕上的名字
> token = "growdu"     # 品牌词：画面里出现它就算品牌标识
>
> [assets.mascot]
> image = "character/mascot.png"   # 立绘（透明底 PNG）
> plain = ""                       # 无标牌立绘（可选）
> ```
>
> **素材缺失不是错误**：没配就是没配，形象不画，流水线照样出片。
> 配置里写明了路径但文件不在才是问题——那说明配错了。

## 一、形象规范

### 1.1 角色设定

**规则**：形象是一个**拟人化的讲解者**，定位是「专注某个技术方向的独立开发者」。
规格表里**配饰行是规则，其余行是例子**——例子照着改就行，规则照着判。

| 项 | 规格 |
| --- | --- |
| 渲染风格 | 3D 卡通渲染，产品级质感，柔和均匀棚拍光 |
| 主体特征 | *示例*：浅蓝灰皮肤、圆大眼、粉色面颊、小巧象牙、头顶一撮呆毛 |
| 服装 | *示例*：深藏蓝技术工装马甲 + 胸口琥珀黄圆柱数据库磁盘图标 |
| 配饰 | **规则**：黑色头戴式耳机 + 麦克风臂；**深藏蓝 `#2B4C7E` 方形细边框眼镜**（镜片透明）；胸口白色铭牌 |
| 铭牌 | **规则**：铭牌上必须有品牌词（取 `video/config.toml` 的 `[brand].token`，本仓库当前是 `growdu`）——空着不行；但文字由代码用真实字体渲染（见 §1.4） |
| 人格 | 气质与内容由《人格规范》定：冷静克制、工程师、秩序感、专注、可靠（见 [人格规范](人格规范.md) §1.1） |
| 背景 | 纯白 `#FFFFFF`，无投影或极淡接触阴影 |
| 画布 | 1920×1080 / 24fps，与流水线一致 |

**眼镜为什么是硬要求**：镜框色写死在 `character/scripts/add_glasses.py` 的
`GLASSES_COLOR` 里，规范与生成 prompt 必须写的是同一件事——
规范和 prompt 漂移了，下一次重生成就会得到一只没戴眼镜或戴错色的形象。
`pipeline/tests/test_glasses.py` 盯着这两边一致，还盯着本机素材的**像素**里
真的有这副眼镜（判据见 §1.5）。

### 1.3 与代码场景的合成方式

透明底 PNG 贴到 cairo 画布即可，文字区保持右侧留白：

```python
# 参考 pipeline/pyv/render.py 的 _frame_bytes 与 character.py 的 pil_to_cairo
surface = cairo.ImageSurface(cairo.FORMAT_ARGB32, 1920, 1080)
ctx = cairo.Context(surface)
ctx.set_source_rgb(1, 1, 1); ctx.paint()
# 形象：等比缩放到画布高 66%，锚点左下 (0.05*W, 0.90*H)
ctx.set_source_surface(img_surface, int(W * 0.05), int(H * 0.90 - img_h))
ctx.paint()
```

配色、字体、文字排版沿用 `pipeline/pyv/palette.py`（主色 `#2B4C7E`、强调色 `#F5A623`）
与 `pipeline/pyv/fonts.py`（字体族名），保证形象与代码画面属于同一套视觉系统。

**字体是跨平台解析的**：默认用仓库内置的字体子集
`AIV Sans CJK SC`（上游 Noto Sans CJK SC，SIL OFL 1.1，允许随软件分发），
两台机器装同一份文件 → **文案、版式与步进宽度完全一致**。
系统字体（macOS 的 `PingFang SC`、Linux 的 `Noto Sans CJK SC`）只是退路：
没装内置字体时会退到它们，那时字形就随机器而异了。

**像素仍然不跨平台一致**：cairo 在 macOS 走 CoreText、Linux 走 FreeType，
栅格化不同。验收按「布局一致 + 同平台逐像素一致」——跨机靠**同一份字体
文件**保证版式（步进宽度、收字号结果）一致，逐像素的活只在同平台里做。

**跨机的版式一致是量出来的**，不是嘴上说的：布局指纹（见《上机指南》）
记下每一行字的落笔坐标、字号、步进宽度与轮廓包围盒。这四类量是**字体的
性质**——实测（2026-11-16，Linux/FreeType vs macOS/CoreText，同一份字体
文件）跨机最大差：坐标 0.000、字号 0.027、步进 0.812、轮廓 0.711。

**但这条要成立有两个前提**：cairo 在 Linux 上默认开着 hinting（轮廓吸附像素
网格、度量取整，步进能差 68px），而只装常规字重时粗体是各后端**合成**的
（轮廓能差 3.14px）。所以内置字体**两个字重都入库**，并且**统一关掉
hinting**——那样跨机版式才真的只由字体文件决定。

### 1.4 铭牌上的品牌词怎么来的

**规则：铭牌必须显示品牌词（`[brand].token`），但文字不能由模型生成。**

模型生成的中英文会乱码——生成 6 姿态设定表时，铭牌上的字出现过
`giowdu` / `grawdu` 等变形。主形象那次碰巧写对了，但「碰巧」不能当规范用：
下次重新生成，铭牌上的字随时可能又变成别的。

所以生成之后统一做一次后处理（`character/scripts/stamp_badge.py`）：

1. **自动定位铭牌**——不硬编码坐标，重生成后依然有效。四道关卡，缺一不可：

   | 关卡 | 判据 | 挡掉什么 |
   | --- | --- | --- |
   | 区域 | 只在**马甲区域**里找白块 | 白底图里的大片背景 |
   | 区域 | 马甲区域取「最大马甲连通块」的包围盒 | 眼镜镜框与马甲同色，用「所有马甲像素」的包围盒会把搜索区域撑到脸上（§1.5） |
   | 尺寸 | 宽 ≥ 画布 3.5%、高 ≥ 1.5% | 镜腿上零碎的小白牌 |
   | 位置 | 上沿低于主体高度的 45% | 眼镜上的白牌（实测在 30% 上下，铭牌在 62%~68%） |
   | 纯白 | 区域内「三通道都 ≥ 240」的像素 ≥ 55% | 形象的奶油色脚趾（实测铭牌 85%+、脚趾 21%） |

   剩下的候选里，四周一圈马甲色占比最高的那个就是铭牌。这个占比只当兜底门槛，
   因为实测它在 0.27 ~ 0.47 之间波动（铭牌有时紧贴马甲边沿，旁边是角色的浅色身体）。
   **那一圈的宽度必须越过铭牌自带的深色描边**（`VEST_RING_WIDTH = 10`）：铭牌是
   3D 塑料牌，边缘自带一圈深色厚度，4px 宽的环整个落在那圈描边上，量到的占比
   近乎为零——真实铭牌反而被判成「没找到铭牌」，字就盖不上（实测点赞姿态：
   4px 环 0.016、6px 环 0.053、10px 环 0.268）。
2. **把铭牌刷成纯白**，抹掉模型写的任何字
3. **用当前字体写上品牌词**（深藏蓝 `#1B2A47`，字号按铭牌尺寸自动适配；
   字体族名由 `pyv/fonts.py` 解析，不写死）

文字来源于是从「模型碰运气」变成「代码确定」。

这与 `brand/scripts/fix_plates.py` 记录的同一类问题——**AI 生成的文字不可信，
所有文字用真实字体渲染**。区别在于：fix_plates.py 是把画面上的字重排，
这里是凭空写出一个模型没写对的字。

*示例*（本仓库当前素材的实测值）：主形象铭牌框 `(1118, 1319, 1265, 1381)`（147×62）；
点赞姿态 `(1116, 1285, 1257, 1341)`；挥手姿态 `(1193, 1180, 1323, 1244)`。

**模型不一定会画铭牌**：有一版挥手姿态就把胸口的白铭牌省了（只剩数据库图标），
所以 prompt 里要写死「马甲上部必须有一块白色矩形铭牌」，生成后还要目视确认。

`brand/scripts/render_brand.py` 在渲染前会自动给两个姿态素材盖章，
所以片头/片尾里的铭牌也一定带着正确的品牌词。

**要一份没有铭牌的素材**（平台判「过度营销信息」时用）：
`character/scripts/clear_badge.py` 产出。之所以能抹得掉，
正是因为铭牌是脚本印上去的，脚本也就知道它在哪。

### 1.5 眼镜是怎么加上去的

**规范：配饰里有一副深藏蓝 `#2B4C7E` 方形细边框眼镜，镜片完全透明。**

- 为什么是深藏蓝：和马甲同色，形象与代码画面属于同一套视觉系统（§1.3）。
- 为什么镜片必须透明：形象的两只大眼睛是画面最核心的表情来源，镜片一有
  反光或变色，眼睛就废了。

**不能用代码在 3D 渲染图上贴眼镜。** 3D 渲染的眼镜要有镜框厚度、高光、
镜腿在耳朵处的遮挡关系、镜片在皮肤上的微弱反光——二维贴片做不出来，
贴上去一眼假。所以做法是**以现有素材为参考图做图生图**：角色、姿态、光照、
构图全部照抄，只多一副眼镜。参考图选「素材自己」而不是「形象原型」，
是为了把角色漂移压到最小。

流程（`character/scripts/add_glasses.py`）：

1. **图生图**——现有素材作参考图，prompt 只加「深藏蓝方形细边框眼镜、
   镜片透明」，并强约束「除眼镜外一切不变」
2. **擦镜框杂物**——模型有个反复出现的毛病：戴上方形眼镜后，会在镜框或
   镜腿上贴一小块**白色小铭牌**（实测上面写着品牌词）。所以再走一次局部
   修补，专门把这块白牌擦掉。用模型擦而不是代码涂，是因为代码涂出来的是
   一块平色，一眼假；模型能按周围的镜框与皮肤重新长出边缘
3. **抠透明底** + **盖铭牌章**（§1.4）

两个坑，都是这轮踩出来的：

- **铭牌检测被眼镜污染**：眼镜镜框和马甲是同一个深藏蓝。眼镜一戴上，
  「画面里所有马甲色像素」的包围盒就被撑到整个上半身，检测器会在脸上
  找到一块高光当成铭牌——实测把品牌词盖到了鼻梁上的一小条反光里；
  更狠的一次是模型在镜片上贴了块白牌，那块白牌四周全是镜框色，
  「马甲占比」比胸口那块真铭牌还高，直接把铭牌顶掉了。
  修法见 §1.4：区域改用「最大马甲连通块」，再加尺寸下限、位置下限、纯白度三道关卡。
- **铭牌四周的「马甲占比」会剧烈波动**（实测 0.17 ~ 0.74）：所以真正的
  判据是尺寸 + 长宽比，「马甲占比」只当兜底门槛。

**验收不靠肉眼，靠像素**。`pipeline/tests/test_glasses.py` 量的是脸区里的
**深藏蓝掩膜**，两个数：

| 判据 | 门槛 | 为什么 |
| --- | --- | --- |
| **列跨度**（深藏蓝像素从最左列到最右列，占主体宽的比例） | ≥ 40% | 镜框横跨两只眼睛；实测三张素材 54%~61%。没有眼镜时脸区里根本没有深藏蓝，跨度会塌到 0 |
| **像素占比**（深藏蓝像素占脸区面积的比） | ≥ 0.5% | 保证镜框**有厚度**，不是一根线；实测 0.96%~2.3% |

用列跨度而不是「最长水平连续段」是有原因的：后者只在头是正的时候成立——
歪头的素材上镜框上沿是**斜线**，任何一行都截不出长段，可眼镜明明在。
列跨度对倾斜免疫。

**改动范围只有 3D 卡通形象。** 站点的 logo / 头像都不戴眼镜——
那是站点自己的图，与角色形象无关。

### 1.6 形象接入的唯一入口

`pipeline/pyv/character.py` 是形象接入的统一入口，场景不再自己拼路径。
素材位置由 `video/config.toml` 决定：

| 素材 | 配在哪 | 缺了会怎样 |
| --- | --- | --- |
| 立绘（透明底） | `[assets.mascot].image` | 不画形象，**不报错** |
| 无标牌立绘 | `[assets.mascot].plain` | 换不了素材，仅此而已 |
| 落版头像 | `[assets.avatar].image` | 落版不带头像 |

**形象只做静帧，不做部件切分动画。** 仓库早期版本试过把形象按颜色连通块切成
头 / 双耳 / 双臂，用旋转 + 位移驱动挥手与点头。那套阈值和绝对坐标都是为 2D
扁平图硬编码的，3D 渲染的渐变与高光会直接破坏分割，为 3D 重写切分算法的成本
远高于收益。所以形象一律走**静帧素材 + 位移 / 缩放 / 淡入**，动效用整体变换补。
该模块已随 2D 形象一起移除（§4）。

降级规则：

| 优先级 | 素材 | 位置 | 动效 |
| --- | --- | --- | --- |
| 1 | 3D 形象（透明底） | `video/config.toml` 的 `[assets.mascot].image`（媒体产物，不入库） | 静帧 + 位移 / 缩放 / 淡入 |
| 2 | 都没有 | — | 不画形象，不报错 |

降级的原因是**媒体产物不入库**：新克隆的机器上没有形象素材，
流水线照样要能跑完——没有形象只是画面里少一只吉祥物，不能因此报错。

**素材缺失不是错误，但显式指定错了是。** 显式指定的路径不存在时报错：
那是指错了，不是没有。

## 二、音色规范

### 2.1 参照音色的实测特征

音色不是拍脑袋定的，是**量出来的**：对一段参照录音做声学测量，
再在候选音色里按同一套指标排序。

| 指标 | 判读 |
| --- | --- |
| 基频 F0 中位 | 男声区间，且偏低沉 |
| F0 p5 – p95 | **动态幅度大**，有强弱起伏 |
| 第一共振峰 F1 | 男声区间下限 |
| 第二共振峰 F2 | 略低于男声典型值 |
| 频谱重心 | 偏暗、不尖锐 |
| 语速 | 偏快 |

结论：**成年男声，偏低沉、偏暗，语速偏快，情绪起伏明显**——技术讲解口吻，
不是播音腔也不是广告腔。

*示例*（本仓库当前参照录音的实测值）：29.27 s / 单声道 / 32 kHz；
F0 中位 116.7 Hz；F0 p5–p95 87–188 Hz（跨 102 Hz）；F1 273 Hz；F2 961 Hz；
频谱重心 1222 Hz；语速 7.72 字/秒。

量测与排序的脚本是 `voice/scripts/measure_voice.py`，
用法与各期定标结论见 [voice/readme.md](voice/readme.md)。

### 2.2 选定音色

**规则**：在候选音色里实测合成一批中文男声候选，用同一套指标
（F0 半音差 + F1/F2 绝对差 + 频谱重心 + 语速 + **F0 动态跨度**）排序，
再在真实口播稿上做 speed × pitch 网格微调，最后定稿。

*示例*（本仓库当前的定稿）：

```json
{
  "voice_id": "Chinese (Mandarin)_Radio_Host",
  "voice_name": "电台男主播",
  "pitch": -1,
  "speed": 1.33,
  "emotion": "neutral"
}
```

**音色参数是使用者的选择**，不在 `video/config.toml` 里（那里只管素材路径）；
它由 `voice/scripts/synthesize_narration.py` 写死在本仓库的定稿值上。

### 2.3 备选

*示例*：

| 音色 | pitch | speed | 说明 |
| --- | --- | --- | --- |
| `Chinese (Mandarin)_Radio_Host` | −2 | 1.35 | 备选一：F0 动态跨度 103 Hz，与参照最接近；F2 偏差更小（+16 Hz） |
| `Chinese (Mandarin)_Southern_Young_Man` | 0 | 1.5 | F1 完全吻合（+0 Hz），但 F0 动态只有 40 Hz，**听感过于平直**，不建议 |

音频样本留本机（`voice/`），不入库。

### 2.4 调用方式

```bash
mcode-tools connector call connector__matrix__synthesize_speech --args '{
  "text": "大家好。今天我们聊一聊数据库内核。",
  "voice_id": "Chinese (Mandarin)_Radio_Host",
  "pitch": -1,
  "speed": 1.33,
  "emotion": "neutral",
  "output_file": "narration.mp3"
}'
```

参数速查：

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `pitch` | **−1** | 半音。降到 −2 更低沉，但 F0 略低于参照 |
| `speed` | **1.33** | 语速倍率。1.5 在真实稿上偏快 12% |
| `emotion` | `neutral` | 讲解场景用中性；需要强调时改 `happy` / `surprised` |

**注意**：`pitch` 与 `speed` 的最优值是相对参照稿标定的。换了口播稿（字数/断句不同），
应重跑 §2.1 的测量并重新定标，不要直接套用。

### 2.5 与旧品牌片音的关系

`brand/scripts/make_audio.sh` 用的是 macOS `say`（童声 + 升 1.5 半音），
和本规范不一致，**只服务旧的品牌片**。当前片头/片尾的旁白已经按 §2.2
定稿音色合成（`brand/audio/voice_intro.mp3` / `voice_outro.mp3`）。

### 2.6 多音字：这个音色会把词首的「行」念成 xíng

**实测结论**（`voice/scripts/check_pronunciation.py` 量摩擦噪声谱心）：

| 词 | 实测读音 |
| --- | --- |
| 行锁 | **xíng** ❌ |
| 一行 | xíng / háng 混 |
| 同一行 / 每一行 / 每行 / 哪一行 / 行号 | háng ✅ |
| 并行 / 串行 / 执行 | xíng ✅ |

「行」在**词首**构成复合词时一律念 xíng，在**词尾**（数量词组、动宾结构里）
大多念 háng——但「一行」会漏。

**绕法**：连接器封装会**丢掉** MiniMax 的 `pronunciation_dict`
（`行锁/pinganpingan` 实测仍念成 `xing2 suo3`），`<phoneme>` 标签会被念出来，
括号里的拼音也会被念出来。唯一可靠的办法是**换等音字**：

| 原词 | 替身 | 为什么等音 |
| --- | --- | --- |
| 行锁 | 航锁 | 航 = háng，无歧义，声母 [x]、韵母 [ɑŋ]、阳平；整句只差 0.093 s |
| 一行 | 壹行 | 壹 = yī，与「一」同声同调；行跟着读成 háng（实测 5/5） |

**只作用于合成文本**：口播稿、字幕表、画面契约一个字都不改，观众听到的仍是「行锁」「一行」。
规则表在 `voice/scripts/pronunciation.py`，由 `voice/scripts/synthesize_narration.py`
在送进引擎前套用；每次合成还会把**真正送进引擎的那份文本**留底成 `*.spoken.txt`。

**新词上线前必须先量读音**：`make pronunciation` 会合成探针并断言
「行锁 = xíng、航锁 = háng」；口播稿里出现没归档的「行」字词时，
`pipeline/tests/test_voice_pronunciation.py` 会直接报错。
