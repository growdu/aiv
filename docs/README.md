# docs/ —— 母稿层（内容真相）

> **这是什么**：**已过审**的文档母稿。一条文档只有过了 `review/` 的判据才会被放进来；
> 进到这里就代表「内容真相已定」，下游（编译器 → 各平台）都从这里取。

---

## 一、目录结构

```
docs/<分类>/<二级内容>/<期号>.md        文档流母稿
docs/<分类>/<二级内容>/_index.md         分类页（目录导航）
```

- **一级目录 = 分类**（如 `distributed/`、`engineering/`、`source-tracks/`）。
- **二级目录 = 二级内容**（可选，分类不够用时分一层）。
- **一篇文档 = 一个文件**，文件名就是它的期号。
  **目录就是接口**（见 [`../review/specs/2026-11-18-目录即接口与分类增设.md`](../review/specs/)）：
  一篇稿子的位置决定它的身份，不另建映射表。
- `drafts/` 与 `docs/` 是**同形镜像**——形状不转换，稿子从哪棵树来就放回哪棵树。
- 每一层目录还要有一份 `_index.md`（分类页），编译器靠它推导分类链——
  目录链断了就是编译错误。文章**不能**也叫 `index.md`：那会跟分类页撞地址。

> `docs/` 现在有内容了（2026-11-23 起）：`distributed/` 这条线的第一篇
> 《CAP 讲的不是「三选二」》，外加它那两级分类页。
> 存量内容不回炉、不搬运——新稿子按这套结构长。
> 两个**保留名**不会被当成稿子编译：`docs/images/`（图片仓库）与
> 任何一层的 `README.md`（模块说明，比如本文件）——见
> [`../tools/build-content-units.py`](../tools/)。

## 二、改这里的规矩（必守）

- **改动稿先落 `../drafts/`**：改 `docs/` 里已有的一篇，先在 `drafts/` 改同名那一份，
  过审才覆盖这里。**`docs/` 里任何时刻都是「已过审的版本」。**
- 框架代码（`../tools/`、`../platforms/`、`../publish/`）不受此限——它们是代码，不是内容。

## 三、AI 如何使用本目录

- **不要直接增删 `docs/` 里的文件**。要新增/修改内容：去 `../drafts/` 起稿，走审校。
- 读一篇母稿：按上面的路径直接读 `<分类>/<二级内容>/<期号>.md`。
- 想知道「一篇稿子的身份/分类怎么定的」：看 [`../AGENTS.md`](../AGENTS.md) §三文档流 与
  [`../review/specs/`](../review/specs/) 里的目录协议。
- 编译成平台内容单元是 [`../tools/build-content-units.py`](../tools/) 干的，**不是本目录的事**。
- **验收命令**：`cd .. && python3 -m pytest tests/ -q`（身份守卫、编译器、退出码）。
