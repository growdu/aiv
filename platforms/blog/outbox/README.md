# 发布快照（outbox/）

这里是**每个平台的发布账本**：每一篇已经进过那个平台的文章，
留一份快照在 `platforms/<plat>/outbox/` 里。

## 快照是什么

一个内容单元在一个平台上的发布状态，就是一个 JSON 文件。
六个平台用**同一套字段**（`publish/publishkit/manifest.py` 写的那套）：

| 字段 | 意思 |
| --- | --- |
| `content_id` | 内容单元 id（相对 `content/units/` 的路径，不带 `.md`） |
| `platform` | 平台 id |
| `kind` | `document` / `video`——站点两种都收（视频单元是口播稿，也是文章） |
| `status` | `drafted` / `packaged` / `published` / `failed` |
| `title` | 发出去时的标题 |
| `published_url` | 发出去之后的地址；站点的地址规则在 `site/src/lib/urls.ts`（文档走 `/docs/<id>/`，视频走 `/videos/<slug>/`） |
| `reason` | 没发出去时为什么（人读的） |
| `updated_at` | 快照落盘的时间 |

## 文件名

`<content_id>__<平台 id>.json` —— 例如
`source-tracks/postgresql/getting-started/postgresql基操__blog.json`。

**文件名就是幂等键**，跟另外五个平台同一个约定。
同一个 `content_id` 在同一个平台上只该有一份快照：重跑一遍发布，
撞到已有的快照就说明「这篇发过了」，不重复发。

> 这条跟另外五个平台有一个**前提差别**：那五个是「一篇一篇发」，
> 发过的不能重发。站点是**整站重建**——一次 push 把全站重来一遍，
> 同一篇文章当然会被重新渲染、重新部署。
> 所以站点这边的快照记的不是「发过没有」，而是
> **「这一篇当前在站上是什么状态」**。它是账，不是锁。

## 仓库里为什么是空的

**空的，而且是刻意的。**

快照是**账**——某个使用者的发布记录。
它记的是「谁、在什么时候、把哪一篇发到了哪个平台」，
所以它天然跟着内容走，不跟着框架走：
框架仓库里放的是**机制**（这份 README、字段约定、幂等键规则、
读账的代码），账本本身由使用者自己攒。

框架仓库里的六个 `outbox/` 目录都是空的（只留一个 `.gitkeep` 把目录占住，
免得目录在 clone 之后消失）。要发第一条的时候，代码会把目录建出来。

> ⚠️ 别把快照当成配置摆进去试。
> 快照一旦落盘，就是「这篇已经发过了」的断言——
> 调度器读到它就会跳过这一篇（`status = failed` 除外）。
> 放一份假的进去，等于替某个内容单元说了「发过了」。

要回填历史快照，是一次**成批的、可重放的**动作，
不是随手加一个文件——每一份都得对得上它当时那篇文章的 `content_id`。
