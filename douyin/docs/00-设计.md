# 抖音 adapter 设计规格

> **状态**：2026-11-15 已实测（草稿能力已验，见「通知措辞」一节）。
>
> **上游契约**：[../../publish/spec/07-视频发布契约.md](../../publish/spec/07-视频发布契约.md) §6.6。

## 一句话

抖音**有**公开发布接口，但开放平台的内容发布能力（scope `video.create.bind`）
要求**党政机关或事业单位**主体——本账号是个人主体，批不下来。
所以这一档是 `manual`：自动出包，人工点发布。

## 产物结构

| 文件 | 内容 |
| --- | --- |
| `video.mp4` | 成片的软链（成片是本机产物，不复制） |
| `cover.jpg` | 抽一帧，**与成片同比例** |
| `cover_3x4.jpg` | **竖封面槽位**（1080×1440，3:4 居中裁切） |
| `cover_4x3.jpg` | **横封面槽位**（1200×900，4:3 等比缩放留白） |
| `title.txt` | 标题（首屏钩子，**≤ 30 字**——平台硬上限） |
| `description.txt` | 正文（≤ 500 字，编辑预算） |
| `topics.txt` | `#话题 #话题` |
| `text.txt` | **开放平台 API 档那一个 `text` 字段**：标题、正文、话题拼好的整段。网页后台**不用**它 |
| `publish.md` | 照着做就能发完的清单 |
| `meta.json` | 机器可读的状态 |

**网页后台是两个框，不是一个。** 「作品标题」（≤ 30 字）与「作品描述」
（≤ 1000 字）是两个独立字段，各带一个字数计数器（2026-11-15 实测）。
标题**不进描述框**——照着开放平台文档把整段 `text` 贴进描述框，
标题会在正文里重复一遍。所以网页档填两个框，API 档才用 `text.txt`。

**封面比例不猜，但也不只给一张。** 抖音的封面规格没有公开文档，
但**后台把比例标在槽位上了**（2026-11-15 实测）：**竖封面 3:4** 与
**横封面 4:3** 两个槽位，只给一张时后台的「发文助手」提示
「横/竖双封面缺失」。所以出包出**三张**：原比例那张（向后兼容）、
3:4 裁切那张、4:3 留白那张。

**两个槽位要分别上传两张图，不是上传一张就行。** 2026-11-15 实测：
点「设置封面」进弹窗，顶部是「设置竖封面 / 设置横封面」两个页签，
每个页签各有自己的「上传封面」拖拽区，右侧的手机预览分别标着
「竖封面预览（3:4）」和「横封面预览（4:3）」——切页签时画布内容会跟着换，
但两个槽位各自保存自己那张。两张都传完，主页面两个槽位都出缩略图，
「发文助手」从「横/竖双封面缺失」变成「封面效果检测通过」。
上传区有一句实测提示：「图片分辨率需大于 1000*752」——
我们出的 1080×1440 与 1200×900 都满足。

**横封面用留白，不用裁一刀。** 竖版成片（9:16）裁成 4:3 只剩中间一条横带，
画面里的字会被拦腰截断——横槽位本来就是给横版视频准备的，竖片填它只能留白。

## 出包前的三道闸

| 闸 | 谁出 finding | 管什么 |
| --- | --- | --- |
| 文案层 | `pyv.epmeta.check_meta` | 各段自己的上限（title / description / 话题） |
| 技术层 | `pyv.preflight.check_video` | 成片的技术门槛（编码、时长、体积、音频） |
| **抖音专属** | `douyin.contract` | **拼装后的 `text` 总长** 与 **站外引流** |

后两条不能并进前两层：

- `pyv.epmeta` 逐字段查，查不出「三段加起来超了 1000 字」；
- `pyv.epmeta` 不知道抖音禁站外引流——那是平台规则，不是元数据格式。

| 级别 | 行为 |
| --- | --- |
| `error` | **报错并停止**，不出包 |
| `warning` | **告警但继续**，并写进 `publish.md` 的「预检告警」一节 |

超限一律报错，**不静默截断**——让作者改元数据，而不是悄悄裁一刀。

## 站外引流这道闸拦什么

拦的是**形态**，不是白名单：

| 类别 | 例子 |
| --- | --- |
| 网址 | `https://growdu.cn/…`、`www.growdu.cn` |
| 域名 | `example.com`、`foo.xyz`（按形态收；文件后缀与产品词除外） |
| 微信 | 「加微信」「加V」「vx」「wx」「VX: abc」 |
| QQ | 「QQ」「qq123456」「扣扣」 |
| 电话 | `13800138000`、`138-0013-8000`、「手机号」「电话」「联系」 |

**「私信」不在表里**——抖音私信是站内功能，不是站外引流，不能误伤。

**规则按形态写，就得每种形态都拦得住。** 大小写算同一种（`VX:` 与 `vx:`
都是微信号）；手机号不能靠 `\b` 断（中文与数字之间没有词边界，
「手机号13800138000」在 `\b1[3-9]\d{9}\b` 下根本匹配不上）。

误伤也是错：正文里写文件名（`README.md`）、写模型名（`gpt-4o.mini`）、
写库名（`wxPython`）都不该被拦。所以域名那条放行**肯定不是域名的后缀**
（文件后缀 + 产品词），微信那条前后用字母数字挡一下。

真遇到了误伤就把那句话挪到别处去，**不要把闸拆了**：闸拆了之后，
下一次就没人拦了。

## 回填：必须有发布包

`mark published` 与 `mark drafted` **都要求发布包存在**。没有包就没有
「发出去的是哪一版」——回填出来的「已发布」指向一个空的 `package_dir`，
下一个人照着快照去找，什么都找不到，而「已发布」已经记上去了。
所以缺包时**报错退出**：不写状态、不写快照。

**失败的回填不许留下状态。** 顺序是「先把会失败的事做完，都成了才落状态」：
先读元数据、再写发布包，最后才写状态与快照。反过来（先存状态再做事），
中途失败就留下一条假的「已发布」。

**`drafted` 不带 `--url`，并且要清空 `published_url`。** 草稿还没发出去，
没有公开链接；留着旧链接会让人以为这条已经发出去了。

**公开链接从创作者后台拿，形如 `https://www.douyin.com/video/<作品id>`。**
作品 id 在后台的「内容管理 → 作品」里点进那条作品的详情页就能看到——
地址栏是 `creator-micro/work-management/work-detail/<作品id>?enter_from=content`，
中间那段数字就是作品 id（2026-11-15 实测：作品 id 7708359383492218122 对应
`https://www.douyin.com/video/7708359383492218122`，GET 返回 200）。
清单里那步「回填 `mark published --url`」的链接就来自这里。

**草稿可能在你没点「发布」的时候被别人发出去。** 2026-11-15 实测：
存完草稿约一小时后，作品已经躺在「内容管理 → 作品」里、状态是「已发布」——
是另一个会话在同一个账号后台点的。所以**快照要以「内容管理」里的实况为准**：
发现平台已发布，就 `mark published --url <链接>` 补回来，别让快照一直说
「已存草稿」。

## 幂等

内容层键是**成片的 sha256**：成片重出（换了旁白、修关键帧）就重新出包。
文案每次都按当前元数据重写——成片没变 ≠ 文案没变。

**复用不是「目录还在就算数」。** 复用之前要复查包里每一件东西都还在
（软链可能悬空——成片被挪走或删了；别的文件也可能被人删）。少任何一件
就重出——否则命令报「成功」，而那个包根本发不出去。

**封面每次重抽。** 复用时封面也得重抽一次：包里那张是上一次抽的，
而元数据里的取帧点（`cover_at`）可能改了。封面与 `meta.json` 记的取帧点
对不上，人按清单选封面就会选错那一帧。

## 通知措辞

「发布包已生成，**待你上传**」与「已发布」是两句话，不许混。

这一档**有 `drafted`**（2026-11-15 实测出来的，不是拍脑袋设的）：
后台点「暂存离开」之后，草稿真的存下来了——实测重新进入编辑页，
视频、标题（15/30）、描述与话题（143/1000）、两张封面全在原处。

⚠️ **但抖音没有「草稿箱」列表。** 实测：内容管理 → 作品的筛选只有
「全部 / 已发布 / 审核中 / 未通过」，**没有草稿一栏**；上传页
（`content/upload`）也没有草稿列表，只有一条
「你还有上次未发布的视频，是否继续编辑？」的提示。
所以 `drafted` 的准确含义是「草稿已暂存在后台，等人从平台的『继续编辑』入口去发表」，
不是「草稿在某个草稿箱里可以逐条翻」。
（同时能留几条草稿**没实测**，只验过一条。）

**草稿有两个入口，都要走平台自己给的按钮。** 2026-11-15 实测：
①上传页提示里的「继续编辑」（点进去 URL 带 `?enter_from=draft`）；
②首页 →「作品发布」卡片 →「继续编辑」（辅助提示是
「你有一个上次未发布的作品」，URL 带 `?enter_from=home_draft`）。
**别直接打开草稿编辑页的 URL**——实测直接开 `?enter_from=draft`
得到的是空编辑器（0/30、0/1000、无视频）。

**草稿会消失，别当保险箱。** 2026-11-15 实测到一次：中途首页的
「继续编辑」入口消失了，直接开草稿编辑页 URL 是空的。
所以存完草稿要**当场**确认入口还在、点进去能看到本条内容，
不能「存了就当成了」。

「已存草稿，**待你点发表**」——不能写成「待上传」（草稿已经在平台上了，
说成待上传会让人**再传一遍**），也不能写成「已发布」（会让人以为发出去了）。

**清单的措辞要跟着状态走。** `publish.md` 是人真正会打开的那份文档——
它写着「待你上传」而 `meta.json` 写着「已存草稿」，人就会**再传一遍**，
在平台上多出一条重复的作品。所以：

- 出包时按**当前状态**写清单（复用包的状态可能是「已存草稿」）；
- `mark published` / `mark drafted` 改了 `meta.json`，**顺带改写清单的抬头与状态说明**
  （`package.rewrite_status_block`）。

抬头与状态说明被一对 HTML 注释夹住（`<!-- status-note:start -->` /
`<!-- status-note:end -->`），改写只动这两处，步骤正文不动。
三边（`douyin` / `channels` / `bilibili`）同一套写法，不许漂。

## 依赖

`pyv` 住在 `aiv/pipeline/` 下面，没有装成 wheel，所以 `douyin/__init__.py`
把它挂上 `sys.path`。adapter 只**读** `pyv.epmeta` 与 `pyv.preflight`，
不 import 契约层或 `weixin/` 的任何包，也不修改 aiv 侧的文件。

与 `channels/`、`bilibili/` 平级、互不引用。

**这一节记录的是「点发布」那一步的事实**，以及它对上面 §「通知措辞」里

## 一、页面形状（三个框，不是两个）

| 框 | 选择器 | 计数器 |
| --- | --- | --- |
| 作品标题 | `input[placeholder*="填写作品标题"]` | `18/30` |
| 作品描述 | `div[contenteditable=true]`（富文本编辑器） | `141 / 1000` |
| 话题 | **不是独立框**——`#话题` 写在描述框里，编辑器把它变成标签 | （算在描述里） |

**描述框必须逐字敲。** 它是 editor-kit 的富文本框，`fill()` 与
`insert_text()` 都不生效——只有真实的按键事件才会让编辑器收下文字、
才会把 `#openGauss` 变成话题标签。标题框是普通 input，`fill()` 就行。

## 二、发布接口

点「发布」时平台自己发：

```
POST https://creator.douyin.com/web/api/media/aweme/create_v2/
→ {"extra": {...}, "item_id": "7709123013601463579", "status_code": 0}
```

**`status_code` 不是 0 就当失败**——平台这时也会给一个 `item_id`，
但那条作品没发出去（没过审或被拦），不能拿它当「已发布」。

点完之后**页面跳回上传页**（`/creator-micro/content/upload`）。

## 三、更正：封面那一节的三个说法

2026-11-15 那轮写的是「竖封面 3:4 槽位、横封面 4:3 槽位，
两张分别上传」。2026-11-17 实测下来，三处要改：

1. **裁剪框恒为 4:3，两个槽位都是。** 竖封面槽位里传 `cover_3x4.jpg`，
   平台照样按 4:3 裁一刀——裁掉底部那行「号码顺序永远单调」。
   换句话说：**按 4:3 裁的话，传 `cover_4x3.jpg` 才不丢内容**
   （它是 4:3 满图，裁剪框正好等于整图）。
2. **这一版没设上封面。** 上传后裁剪弹窗能看到我们的图（ReactCrop 里是
   `1080×1440` 原图与 `1080×810` 的 4:3 裁剪结果），但**保存之后封面编辑器的
   画布是空的**，两个槽位一直停在「选择封面」，点「完成」也不生效。
   画布编辑器（fabric canvas）这条路**自动化走不通**——
   文件选择框与拖拽（drop 事件）两条路都试过，画布都没接住图。
   **所以这一期是无自定义封面发的**：平台用成片里的帧当默认封面，
   后台的「发文助手」提示「横/竖双封面缺失」——那是建议，不是拦截。
   人工补封面走「内容管理 → 作品 → 编辑作品」。
3. **「AI 智能推荐封面」一直没出图。** 面板一直写「生成中」，
   后台报 `content_cover_recommend_createBach` error_code 5005。

## 四、更正：上传成功 ≠ 表单出现

**表单先出来，视频上传后失败。** 实测两次：
第一次是把成片喂进去、表单出现、标题框可见——这时候页面右上角才冒出
「上传失败，重新上传」。**表单出现不等于上传成功**，
执行器要同时盯「标题框出现」与「页面上没有『上传失败』」。

更要命的一条：**在封面编辑器里操作会把已经传好的视频上传搞挂。**
第一轮就是这么变成「上传失败」的——传了封面、裁了剪，页面右上角就变成
「上传失败，重新上传」。所以**顺序必须是：传视频 → 等上传成功 → 填文案 →
（要发表就）点发布**，中间不要碰封面。

## 五、其它实测事实

- **发布设置默认就是对的**：同时发布「不同时发布」、谁可以看「公开」、
  保存权限「允许」、发布时间「立即发布」。
- **正文里不要带 `growdu.cn`**（这一版的描述里就没有）。
- **作品状态在内容管理里是「审核中」**，不是「已发布」——
  平台审核期间只有自己可见。回填快照按「已发出去了」记，
  但**状态要去内容管理里看实况**（与 §「回填」里说的一样）。
- 作品列表页是 `GET /creator-micro/content/manage?tab=works`，
  标题后面最近的那个状态词就是这条的状态（`已发布` / `审核中` / `审核未通过`）。
- 登录态在**主 Chrome 的 Default profile** 里（77 个 douyin cookie），
  复制一份 profile、用 `--remote-debugging-port` 起浏览器、脚本挂 CDP 上去就行。
