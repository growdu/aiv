# 草稿箱

新写的稿子先落这里，审完也留着。它是**两条流水线的共同入口**。

**它在 `docs/` / `video/` 的上游**——确切的两条流是：

```
① 文档流   draft ──▶ review ──▶ docs  ──▶ 第三方平台（文档类）
② 视频流   draft ──▶ review ──▶ video ──▶ 第三方平台（视频类）
```

> **一条总规则**：往后的**新增**和**修改**都在 `drafts/` 里做，
> 过完 `review/` 才进 `docs/` 和 `video/`。
> `docs/` 里那一份始终是**已过审的版本**——
> 改动稿在 `drafts/` 期间不覆盖它。

**目录即接口**：这个目录里的**目录结构就是接口**。

```
drafts/<分类>/<二级内容>/<期号>.md
  ↑ 一级目录 = 一个分类      一篇文档 = 一期
    二级目录 = 一块二级内容
```

`docs/` 与 `video/` 是**同形**的两棵树。分类不声明三遍——
它**只存在于目录里**（详见
`review/specs/2026-11-18-目录即接口与分类增设.md`）。

---

## 一、⚠️ 在这里建目录之前，先读这一段

> **在 `drafts/` 下建目录，是一个策展动作，不是一个文件操作。**

建一级目录 = **新增一个对外可见的分类**；
建二级目录 = **新增一块二级内容**。
它带来三件不会自动消失的事：

1. **URL 命名空间是永久的。** 分类页一旦生成，地址就是它的身份；
   改名等于让所有指向它的链接失效（站外也失效）。
2. **三边要同形。** `docs/` 与 `video/` 要跟着长出同形的一层；
   只长一边，这棵树就不同形，坐标就对不上。
3. **要登记映射。** `platforms/blog/site/data/learning-path.json`
   得给这个目录一条规则。
   **空分类不被任何守卫管**——它没有文章，也就没有「文章必须归到某条赛道」
   这条断言兜着。

所以规矩是：

- **先把稿子放在既有分类里**，确认它确实撑得起一个分类了，再开目录；
- **开目录要过审**——分类审校六问见
  [`review/specs/2026-11-18-目录即接口与分类增设.md`](../review/specs/2026-11-18-目录即接口与分类增设.md) §四；
- **一次只开一层**，别顺手开三级；
- **开完记得在 `learning-path.json` 登记**（全流程唯一的跨层手写处）。

## 二、起点：主题

流水线的起点不是文件，是**一段话**——**主题**：

> 用户产生 idea 的时候，输入的那段话。

比如「链接重写为什么老出错」——
这一段话就是主题。它记着**核心思想**：想讲什么、给谁看、想解决什么问题。

**主题不是一层，也不是一个目录。**
它不建自己的目录、不产出自己的内容单元、不进站。
它是流水线的**一个输入参数**，最终落进那份稿子的 front matter：

```yaml
---
topic: "链接重写为什么老出错"
---
```

自动生成工具读的就是这个字段；手动写的时候，它是这一份稿子的起点说明。

## 三、主题 → 草稿：两条走法

```
                     主题（一段话）
                          │
              ┌───────────┴───────────┐
              ▼                       ▼
         手动编写                  自动生成
     （人坐下来写）           （工具读 topic 起草）
              └───────────┬───────────┘
                          ▼
              drafts/<日期>-<主题>.md      ← 草稿箱
                          │
                     总审核 review/
                          │
        ┌─────────────────┴─────────────────┐
        ▼                                   ▼
      docs/                               video/
   （文档流母稿）                      （视频流母稿）
```

两条走法产出的是**同一种东西**：一份带 front matter 的 markdown 底稿。
写完都进草稿箱，都过同一道总审核。

> **主题不决定它进哪条线。** 一段主题可能同时是「一篇站点文章」和
> 「一期视频」的起点——那是**两份底稿**（母稿唯一：文档流与视频流各有一份，
> 互不派生）。

## 四、草稿箱的流程

**新增和修改走同一套。**

1. 要写的稿子、或要改的稿子，都先放进 `drafts/`（文件名带日期与主题）。
2. 过总审核：文章看 `review/`，视频稿看 `video/review/` 的口径要求。
3. 通过后**复制**一份进 `docs/`（站点文章）或 `video/`（视频母稿）。
4. 底稿留在 `drafts/`，**不再参与任何派生**。
5. 平台版由 `platforms/<plat>/` 各自出包，落在 `platforms/<plat>/outbox/`。

**修改已有内容时**多一条：改动稿留在 `drafts/`，**不直接改 `docs/`**。
`docs/` 里那一份要等 review 通过才被覆盖——
所以任何时刻 `docs/` 都是「已过审的版本」，`drafts/` 是「在改的版本」。

> **第 3 步是「复制这一个文件」，不是「整棵树同步」。**
> 整树同步会把还没过审的稿子一起带进 `docs/`。
>
> **「这一个文件」的精确说法是「一个复制单元」**——单元可能是 1 个文件，也可能是
> 1 个目录（bundle 形态的稿子自带它的图片）。扁平稿如果引用了同目录的图片，
> 图片要跟着一起复制，否则图裂。
> 单元的判定规则见
> [`review/specs/2026-11-18-草稿层与母稿层的接口协议.md`](../review/specs/2026-11-18-草稿层与母稿层的接口协议.md) §五。

## 五、`_` 是保留前缀

**以 `_` 开头的目录不是分类。**

```
drafts/_video/<分类>/<合集>/<文档>/<档位>/
```

| 它**不是** | 它**是** |
| --- | --- |
| 一个分类 | 视频线的草稿区 |
| 会生成 URL | 不生成任何 URL |
| 要登记 `learning-path.json` | 不登记 |
| 会进 `docs/` | 只进 `video/episodes/`（且只在过审之后） |

**`_` 前缀是整层的保留命名空间**——将来别的线要用草稿区，也走 `_` 前缀，
不跟「分类」抢名字。

### 视频线的草稿：与期坐标逐段对应

期坐标是四段：**分类 / 合集 / 文档 / 档位**。
草稿坐标在前面加一段 `_video`，**其余逐段对应**：

| | 坐标 |
| --- | --- |
| 草稿 | `drafts/_video/分类/合集/文档/档位/` |
| 期 | `video/episodes/分类/合集/文档/档位/` |

三档（`short` / `mid` / `full`）是**三份独立的草稿目录**，不是一个目录里的三个文件——
每一档有它自己的口播稿、契约与发布单。

**骨架 `skeleton.yaml` 在文档级，不在档位目录里**——三档共用一份：

```
drafts/_video/分类/合集/文档/skeleton.yaml     ← 骨架（一份，三档共用）
drafts/_video/分类/合集/文档/short/            ← 一期（short 档）
drafts/_video/分类/合集/文档/mid/              ← 一期（mid 档）
drafts/_video/分类/合集/文档/full/             ← 一期（full 档）
```

### 过审 = 只复制，之后还有三步要人做

**过审**把草稿**复制**进母稿层——**草稿仍在原地**（§四 第 4 步）。

复制只搬**入库事实**：文档搬那个 `.md`；一期搬 `口播稿.md`、`contract.json`、
`publish.json`。**旁白、时间轴、渲染帧不搬**——那是产物，跟着走会撞守卫。

**复制完还有三步得人自己做**（工具不做，也不假装做了）：

1. **建/更新审校记录**——文档看 `review/<镜像路径>.md`，视频看期目录下的 `review.md`；
2. **补两个 INDEX**——`review/INDEX.md` 与 `video/review/INDEX.md` 各加一行
   （守卫要求它们与磁盘上的集合相等）；
3. **提交**——文档流的守卫要求 `docs/` 里每一篇都有 `status: 已合入` 的记录。

创作平台的「过审」按钮做的就是**复制**这一步，并把这三步原样念给你听。

> **索引页与 bundle 稿这一版不过审**——索引页照抄会造站内死链，
> bundle 稿要引用解析器。形状对不上就别硬过。

## 六、底稿不进派生

真相只在文档流：文章线的母稿在 `docs/`，视频线的母稿在 `video/`。
草稿箱留的是同一份内容的历史副本，不是第二个产地——
文章线的下游一切从 `docs/` 的母稿重建，视频线的下游一切从 `video/` 的母稿重建。
留底稿是为了看出「当初交上去的是什么、审校改了什么」，不是为了让稿子有两个地方可以改。

**主题也一样。** 主题留在底稿的 `topic:` 字段里，供复盘时看「当初为什么想写这个」。
它不参与派生——下游重建的是母稿，不是主题。
