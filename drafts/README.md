# 草稿箱

新写的稿子先落这里，审完也留着。它是**两条流水线的共同入口**。

---

## 一、起点：主题

流水线的起点不是文件，是**一段话**——**主题**：

> 用户产生 idea 的时候，输入的那段话。

比如「Hexo 的站点构建里，链接重写为什么老出错」——
这一段话就是主题。它记着**核心思想**：想讲什么、给谁看、想解决什么问题。

**主题不是一层，也不是一个目录。**

它不建自己的目录、不产出自己的内容单元、不进站。
它是流水线的**一个输入参数**，最终落进那份稿子的 front matter：

```yaml
---
topic: "Hexo 的站点构建里，链接重写为什么老出错"
---
```

自动生成工具读的就是这个字段；手动写的时候，它是这一份稿子的起点说明。

## 二、主题 → 草稿：两条走法

```
                     主题（一段话）
                          │
              ┌───────────┴───────────┐
              ▼                       ▼
         手动编写                  自动生成
     （人坐下来写）           （工具读 topic 起草）
              └───────────┬───────────┘
                          ▼
              drafts/<日期>-<主题>.md      ← 草稿箱
                          │
                     总审核 review/
                          │
        ┌─────────────────┴─────────────────┐
        ▼                                   ▼
      docs/                               video/
   （文档流母稿）                      （视频流母稿）
```

两条走法产出的是**同一种东西**：一份带 front matter 的 markdown 底稿。
写完都进草稿箱，都过同一道总审核。

> **主题不决定它进哪条线。** 一段主题可能同时是「一篇站点文章」和
> 「一期视频」的起点——那是**两份底稿**（母稿唯一：文档流与视频流各有一份，
> 互不派生）。这一点跟平台层无关：平台是下游的事，
> 主题只管「想讲什么」。

## 三、草稿箱的流程

1. 新写的稿子放 `drafts/`，文件名带日期与主题。
2. 过总审核：文章看 `review/`，视频稿看 `video/review/` 的口径要求。
3. 通过后**复制**一份进 `docs/`（站点文章）或 `video/`（视频母稿）。
4. 底稿留在 `drafts/`，**不再参与任何派生**。
5. 平台版由 `platforms/<plat>/` 各自出包，落在 `platforms/<plat>/outbox/`。

## 四、底稿不进派生

真相只在文档流：文章线的母稿在 `docs/`，视频线的母稿在 `video/`。
草稿箱留的是同一份内容的历史副本，不是第二个产地——
文章线的下游一切从 `docs/` 的母稿重建，视频线的下游一切从 `video/` 的母稿重建。
留底稿是为了看出「当初交上去的是什么、审校改了什么」，不是为了让稿子有两个地方可以改。

**主题也一样。** 主题留在底稿的 `topic:` 字段里，供复盘时看「当初为什么想写这个」。
它不参与派生——下游重建的是母稿，不是主题。

真正的稿子会从两处进来：

- **新写的**——按上面「主题 → 草稿」；
- **改了要重发的**——把 `docs/` 里的母稿拿过来改，
  改完的那份留在 `drafts/`（`docs/` 那份是真身）。
