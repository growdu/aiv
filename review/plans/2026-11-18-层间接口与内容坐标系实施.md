# 层间接口与内容坐标系 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把《层间接口与内容坐标系》里定的四维坐标（方向 / 系列 / 期号 / 档位）真正落到仓库里：内容单元从 hexo 的目录搬出去成为共享仓库，赛道按方向改名并预置 Ceph，视频产物键带上档位，平台侧声明可发哪几档，站点长出「方向页 / 系列页」三层。

**Architecture:** 五段推进，每段结束时仓库都是可构建、可测试的绿状态。段与段之间只有依赖顺序，没有交叉。**M0 是地基**（内容单元仓库 + 站点构建链归位 + URL 重定向机制），**M1/M4/M5 是坐标**（赛道改名 / 契约扩字段 / 母稿改字段），**M3 是视频三档**（档位进产物键 + 讲稿骨架），**M6/M7/M8 是平台**（`tiers` 声明 / 视频发布路径重构 / YouTube），**M9 是站点展示**。

**Tech Stack:** Python 3.11+（标准库：`tomllib`、`pathlib`、`json`、`re`）、Hexo 5 + Node 22、pytest、GitHub Actions。

**Spec:** `review/specs/2026-11-18-层间接口与内容坐标系.md`（坐标与接口）、`review/specs/2026-11-18-顶层设计与目录调整.md`（D9 / D10 站点构建链归位）。**执行者必须同时读这两份**——本计划不重复论证。

## Global Constraints

这些约束**每个任务都隐含适用**，不再逐条重复。

- **不写 `Co-Authored-By`**：本仓库的提交一律不带该 trailer。
- **推送前先 `git fetch`**：有并行的 Claude 会话在推 `master`。推之前必须 `git fetch origin && git status` 确认没被改写；若远端被改写，合并后**重跑全套验证**再推。
- **完整 CI 等价链**：`build-series-page.py` 少跑一步会让 `/videos/` 整体消失，凭空多出约 1596 条假死链。验证时必须跑满：`build-content-units.py` → `build-video-pages.py` → `sync-hexo.py` → `build-learning-path.py` → `build-publish-index.py` → `build-podcast-index.py` → `build-series-page.py` → `build-podcast-feed.py` → `patch-theme.py` → `copy-vendor.py` → `hexo generate`。
- **pytest 一律在仓库根目录跑**（先 `cd` 到仓库根，再 `python3 -m pytest …`）。**不要换个目录跑**：`tools/sync-hexo.py` 里的 `DOCS = "docs"` 是**相对当前目录**的，换目录跑会让 `tests/test_site_root_prefix.py` 假红（`1 failed`）。
- **pytest 分套跑**：`tests/` 与 `publish/tests/` 可以合跑（`python3 -m pytest tests/ publish/tests/`）；`video/pipeline/tests/`、`platforms/toutiao/tests/`、`platforms/wechat/tests/` **各自单独跑**——这几个目录之间有同名测试文件（`test_contract.py` / `conftest.py` / `test_capability.py`），合跑会报 `import file mismatch` 直接中断收集。
- **`video/pipeline/tests/` 那 1 个红是既有问题**：`test_publish_copy.py::test_publish_copies_match_the_canonical_docs`——`video/` 正本与 `docs/life/aiv/` 发布副本漂移（改了 `video/` 里的文档没跑 `python3 video/scripts/sync_publish_docs.py`）。实施前在 `master` 上也是红的，本计划不碰它，但**收尾时必须确认还是这同一个红**，不是新冒出来的。
- **一次只改一件事**：每个任务结束时 `python3 -m pytest tests/ publish/tests/ -q` 必须与基线同绿（基线：`939 passed, 4 skipped`）。`video/pipeline/tests/` 另跑，基线是 `1271 passed, 23 skipped, 1 failed`——**那 1 个红是既有的**（`test_publish_copy.py::test_publish_copies_match_the_canonical_docs`，`video/` 正本与 `docs/life/aiv/` 发布副本漂移），实施前在 `master` 上也是红的，本计划不碰它，但收尾时必须确认还是这同一个红。
- **本计划明确批准改动 `tests/test_learning_path.py`**（Task 9 给 `status: planned` 赛道开口子）。这是唯一一处被批准改动的既有测试文件，其余 `tests/` 只许改路径引用。
- **不改行为**：搬移类任务（D9/D10）只改路径，不改逻辑。搬完之后验收标准是「站点照样构建出来」，不是「脚本重写了一遍」。

def test_units_images_dir_never_collides_with_a_unit():
    units = UNITS_DIR

所以白名单要**分成两段**：

| 段 | 含义 | 谁写 | 本次变化 |
| --- | --- | --- | --- |
| `PASSTHROUGH_FIELDS` | 作者说了算，原样搬 | 作者 | 19 → 19（`series` 出，`episode_label` 进） |
| `DERIVED_FIELDS` | 机器说了算 | 编译器 | 0 → 3 |
| `CONTENT_UNIT_FIELDS` | 内容单元允许出现的全部字段 | — | **19 → 22** ✓ |
