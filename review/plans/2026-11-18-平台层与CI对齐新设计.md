## Global Constraints

- **纪律：只改说法与引用，不改站点行为。** 这一轮**不动** `site/src/` 里的任何渲染代码，
  **不动** `site/tools/` 的三个脚本的逻辑。Astro 站点现在是绿的（61 页 / 26 个用例绿），
  这一轮之后必须**还是**绿的。
- **只动 `platforms/blog/` + CI + 两份目录速查。** 别模块（`publish/`、`platforms/wechat/`）
  的欠账**不在这一轮**——它们是别的模块的活，见规格 §14.5。
- **不许留下「指向不存在文件」的引用。** 这一轮的验收标准之一就是：
  `grep -rn "hexo\|matery\|sync-hexo\|adapt-units" platforms/blog/` 只剩历史叙述里的必要提及。
- **pytest 在模块目录里跑**：`cd platforms/blog/site && python3 -m pytest tests/ -q`。
- **不碰 `growdu.cn`。** 部署是上线那一轮的活；这一轮只出构建与校验。
- **提交信息不带 `Co-Authored-By` trailer。**

## Task 1: 平台层常量与说明（`platforms/blog/__init__.py`）

- [x] **Step 1: docstring 改成新链**
- [x] **Step 2: 常量对齐**
  - 加 `DRAFTS_DIR`（草稿层，`drafts/`）——`check` 要能区分「在改」与「已过审」。
  - 加 `CONTENT_UNITS_DIR`（`content/units/`，构建产物）。
  - `MAX_CATEGORY_DEPTH`：**重新定值**。旧的 5 是「赛道→系列→阶段→文章」的 URL 段数，
    那是旧目录树的现状；新链里 URL 是 `/docs/<内容单元 id>/`，
    深度 = 目录层数 + 1。**实测当前 `docs/` 最深 4 段 → URL 5 段**，所以 5 仍然成立，
    但**理由要换**（不再是旧树的现状，是新 URL 形状下的一条线）。
  - `EXCLUDED_DIR_NAMES`：**删掉**。它抄的是 `sync-hexo.py` 的排除名单，
    那个脚本随旧站点撤掉了；新编译器 `tools/build-content-units.py` **不排除任何目录**。
    留着就是一条**假的保证**（`check` 会说「构建会排除它」，其实不会）。
    新的真实规则是：**目录链断了 = 编译直接失败**（`read_index_chain` 抛 `CompileError`），
    所以「有人在 `docs/` 下建了 `tests/`」不会静默发布，而是**构建断掉**。

## Task 2: `cli.py` 的两个子命令重写

- [x] **Step 1: `status` 改成新设计的站点状态**
  - 平台身份与限额（照旧，那是 `capability.toml` 说了算）；
  - **站点现在的样子**：多少内容单元、几条赛道、每条赛道多少内容、构建产物多少页；
  - 数据来源：`content/units/`（构建产物）+ `site/data/learning-path.compiled.json`。
- [x] **Step 2: `check <content_id>` 改成新设计的入站检查**
  - 定位母稿：`docs/<id>.md`（已过审 → 会进站）或 `docs/<id>/index.md`（bundle 形态），
    都找不到就去看 `drafts/`（在改，还没过审 → **不进站**，要说清楚）。
  - **编译器的四条硬要求**（`tools/build-content-units.py` 的口径）：
    ① 标题（front matter `title` 或正文首个 H1）② 描述（front matter `description` 或正文首段）
    ③ 日期（front matter `date` 或 git 历史）④ 目录链每一级都有 `_index.md`。
  - **它在站上的 URL**：按 `site/src/lib/urls.ts` 的规则算（分类页抹 `_index` 尾巴，
    视频抹 `video/` 开头）。
  - **学习流归属**：查 `learning-path.compiled.json` 的 `assignment`。
    没归上 → **构建会断**（漏归类不许静默）。
  - 删掉「构建会排除它」那条检查（前提没了，见 Task 1）。
- [x] **Step 3: 两种形态同时存在的检查**
  - 旧 `sync-hexo.py` 有「flat 优先」的规则；新编译器**没有**这个概念
    （它 glob 全部 `*.md`，两种形态是两个不同的单元 id）。所以这条检查要改成
    **如实描述**：`docs/a/b.md` 与 `docs/a/b/index.md` 同时存在 →
    两个内容单元，URL 不同，不是死内容。**别再判它错。**
- [x] **Step 4: 手测**
  - `cd platforms && python3 -m blog.cli status`
  - `python3 -m blog.cli check source-tracks/postgresql/getting-started/postgresql基操`
  - `python3 -m blog.cli check video/row-lock`
  - `python3 -m blog.cli check 不存在的一篇`
