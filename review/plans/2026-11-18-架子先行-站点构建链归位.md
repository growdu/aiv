# 站点构建链归位（架子先行）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把站点的构建链从仓库根搬进 `platforms/blog/site/`，把内容单元的落点定在 `content/units/`，
提交一个**行为一字未变**的目录骨架；此后各模块（四维坐标、档位体系、各平台适配）可以各自独立推进。

**Architecture:** 仓库根只留平台无关的东西。站点（第六个平台）的构建链整体住进
`platforms/blog/site/`；内容单元住进 `content/units/`，是所有平台共用的那一半，站点通过
一个**适配步骤**把它接回自己的 `source/_posts/`。全程**只改路径，不改逻辑**。

**Tech Stack:** git mv（保历史）、Python 3（构建脚本）、Hexo 5 + Matery（站点）、GitHub Actions（CI）

**Spec:** `review/specs/2026-11-18-顶层设计与目录调整.md` §2.1 / §4.2（D9、D10）
（配套的细节规格 `review/specs/2026-11-18-层间接口与内容坐标系.md` 是**下一阶段**的事）

**前序计划:** `review/plans/2026-11-18-层间接口与内容坐标系实施.md`（24 任务）——那是**架子之后**的细节计划。
本计划先行落地；那个计划的 Task 1（内容单元编译器抽取）因本计划而**推迟**。

## Global Constraints

- **纪律：只改路径，不改逻辑。** 搬移不是重写。被搬的脚本**代码一行不改**，只改「在哪儿」和「怎么被找到」。
  唯一允许改的代码是**路径常量**与**引用**。任何「顺手改一下行为」都算越界。
- **验收看的是「站点照样构建出来」，不是「脚本重写了一遍」。** 搬完之后的站点产物
  （页面数、URL、死链数）必须与搬之前一致。
- **pytest 一律在仓库根目录跑**（先 `cd` 到仓库根，再 `python3 -m pytest …`）。
  `tools/sync-hexo.py` 里的 `DOCS = "docs"` 是**相对当前目录**的，换目录跑会让
  `tests/test_site_root_prefix.py` 假红。
- **pytest 分套跑**：`tests/` 与 `publish/tests/` 可以合跑（`python3 -m pytest tests/ publish/tests/`）；
  `video/pipeline/tests/`、`platforms/toutiao/tests/`、`platforms/wechat/tests/` **各自单独跑**
  ——这几个目录之间有同名测试文件，合跑报 `import file mismatch` 直接中断收集。
- **基线**（实测，2026-11-18，仓库根目录跑）：
  | 套件 | 基线 |
  | --- | --- |
  | `tests/` + `publish/tests/` | **939 passed, 4 skipped** |
  | `video/pipeline/tests/` | **1271 passed, 23 skipped, 1 failed** |
  | `platforms/toutiao/tests/` | 394 passed, 2 skipped |
  | `platforms/wechat/tests/` | 504 passed, 1 skipped |
  `video/pipeline/tests/` 那 1 个红是**既有的**（`test_publish_copy.py::test_publish_copies_match_the_canonical_docs`，
  `video/` 正本与 `docs/life/aiv/` 发布副本漂移），实施前在 `master` 上也是红的，本计划不碰它，
  但**收尾时必须确认还是这同一个红**。
- **本地构建不等于完整 CI 流水线。** 少了 `build-series-page.py` 这一步，`/videos/` 会整个消失，
  凭空多出约 1596 条假死链。验站点必须**跑满 CI 的全部步骤**（见 Task 6）。
- **不要用裸 `git stash` / `git stash pop`**——stash 栈在所有 worktree 之间共享。
- **提交信息不要带 `Co-Authored-By` trailer。**
- **主仓库 `/work/ai/blog` 在 `master`，有并行的 Claude 会话在推。** 本分支的推送必须先 `git fetch origin`。

## Review Focus

规格暗示、但没有哪一步的测试覆盖的五种输入/情形——按最容易咬人的排序：

1. **站点首页/某篇文章的 URL 在搬移前后必须一模一样。** 搬移只改文件在哪儿，不改
   `permalink: :year/:month/:day/:title/` 的结果。验法：搬前记下 `public/` 里全部页面的路径清单，
   搬后再记一次，两份清单**逐行相同**。
2. **`content/units/` 里的内容单元 id（相对 `content/units/` 的路径去掉 `.md`）不能变。**
   `publishkit` 的 `content_id`、期号区块、发布索引全靠它。搬前记下 id 清单，搬后比对。
3. **`docs/` 里的母稿一篇都不许动。** 搬移前 `git diff --stat docs/` 必须是空的。
4. **站内死链数不能变。** `check-built-links.py` 在搬前后的报告必须一致。
5. **CI 的三个地方必须同时改**：hexo 的工作目录、`npm install` 的目录、产物 `public/` 的路径。
   漏一个，站点发不出去——而且本地 `hexo generate` 照样绿。

- [x] **Step 1: 写 `adapt-units.py`**

```python
#!/usr/bin/env python3
"""把内容单元仓库（`content/units/`）接到站点的源目录（`source/_posts/`）。

站点是内容单元的**一个消费者**，不是一个所有者。内容单元住在 `content/units/`
（平台无关，所有平台共用）；站点要渲染它们，得先有一份自己的副本。

这个脚本现在只做**逐字节复制**——它不改 front matter、不改链接、不加字段。
站点的专属字段（`layout`、`permalink` 之类）是 sync 编译时写进内容单元的，
以后要拆成「平台无关的字段」+「站点适配时加的字段」，那是**下一个模块**的事，
不在这一步做。

用法：`python3 platforms/blog/site/tools/adapt-units.py`
"""
import shutil
import sys
from pathlib import Path

_REPO_ROOT = Path(__file__).resolve().parents[4]
sys.path.insert(0, str(_REPO_ROOT / "tools"))
from paths import CONTENT_UNITS, SITE_POSTS  # noqa: E402


def main() -> int:
    if not CONTENT_UNITS.is_dir():
        print(f"内容单元仓库不存在：{CONTENT_UNITS}", file=sys.stderr)
        return 1
    # 先清干净再拷——站点的那份是**副本**，每次构建都从内容单元仓库重来。

    shutil.copytree(CONTENT_UNITS, SITE_POSTS)
    n = sum(1 for _ in SITE_POSTS.rglob("*.md"))
    print(f"已接入 {n} 个内容单元 → {SITE_POSTS}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```
