# 内容分类与结构重构：把 574 篇排成五条赛道

日期：2026-11-17
起因：作者拍板 —— 「需要对当前博客下的内容进行分类，确认哪些是真正要对外发布的，
哪些是辅助发布的，同时所有的内容都需要分门别类，循序渐进」，并追加「这些分类都太大了，
最外层应该尽量少的分类，然后再进行二级、三级分类，比如采用系列、合集的方式」。

---

## 一、问题

站内 **574 篇文章**，分在 **40 个平铺分类**里。这套分类有三个毛病：

1. **太大** —— `数据库` 154 篇、`数据库深入` 94 篇、`Linux` 38 篇、`AI` 29 篇挤在一个
   分类页里，读者点进去只看到一堵墙。
2. **混着不该给外人看的东西** —— `docs/blog/` 下的《仓库架构》《重构方案》《部署到服务器》
   《同步到公众号方案》，跟《PostgreSQL 源码剖析》以**普通文章的身份**摆在同一个货架上；
   `docs/edit/` 的 pandoc/texlive 安装笔记、`docs/ai/ai_video/` 的产品设计稿、
   fastup/nxp 测试报告同理。读者在分类栏点进去看到的是「怎么给这个博客装 pandoc」。
3. **没有渐进** —— 上一轮做出来的 `data/learning-path.json`（8 赛道 × L1–L8）**只驱动了
   首页和一个 `/learning/` 页**，它没有反过来约束站点导航。分类是**检索**用的，
   不是**导航**用的；读者从一篇文章落地之后，站点没有告诉他「下一篇该读什么」。

第四个问题更隐蔽：**私有文件混在内容里**。`docs/page/self.jpg`、`docs/page/resume_files/`
是个人隐私，和文章躺在同一个目录树里。

## 五、迁移机制

### 5.1 物理重排会踩的坑（已逐个查证）

| 坑 | 位置 | 后果 | 对策 |
| --- | --- | --- | --- |
| **文章 URL 全变** | Hexo `processor/post.js:49` 强制 `data.slug = info.title`，slug 取自 `source/_posts/` 下的**完整路径** | 574 篇文章 URL 全改 | 仓库已有 `write_redirects()`，把 `REDIRECTS` 表从 16 条扩到 574 条 |
| **所有文章的日期被改写** | `tools/sync-hexo.py:606` `git_date()` 用 `git log --all --reverse -- <当前路径>`，而 `git mv` 后当前路径的最早提交就是搬运那一次 | 不只是表里那 30 篇 —— **574 篇全部**日期变成搬运日，一齐跳到「最近发布」顶部；重定向页也会写到错误的旧 URL | 见 §5.2 第 3 条：把每篇文章的原始日期按**新路径**固化进 `DATE_OVERRIDES` |
| **`infer_topics()` 前缀规则失效** | `tools/sync-hexo.py:520+`（认 `cluster/DCF/` 这类前缀） | 首页专题分组错乱 | 改成认新目录 |
| **`FEATURED_POSTS` 路径失效** | `tools/sync-hexo.py:80` | 首页推荐位空掉 | 同步改写 |
| **`META_CATS` 需要重定** | `tools/sync-hexo.py:1964` = `("blog","tools","page")` | 这个元组的作用是**把某些目录排除出文章索引**（404 页的搜索索引 + 最近发布，见 `sync-hexo.py:2329`），**不影响它们是否被发布成文章页** | 迁移后 `blog/`、`page/` 都不存在了，这两项可以删掉；**`notes/` 千万不要加进去** —— 手记是留站给读者看的，加进去等于让读者搜不到手记里的文章 |
| **分类页 URL 变** | `/categories/<旧名>/` | 旧分类页 404 | `write_category_redirects()` 已存在，补表 |
| **`_index.md` 级联名** | 每目录一个 | 新目录没有显示名 | 每个新目录写 `_index.md` |
| **12 个测试硬编码 `docs/` 路径** | `tests/` | 测试红 | 逐个改 |
| **`EXCLUDED_DIR_NAMES` 撞名** | `tools/sync-hexo.py:44`（含 `tests`/`plans`/`build`/`out`/`pipeline`） | 新目录名若撞上会被整棵排除 | 新目录名避开这些词（已避开） |
| **内链与图片** | 620 篇里 1082 条站内链接（794 同目录 + 288 上级相对 + 4 绝对） | 跨子树引用断 | 同子树整体搬；跨子树的引用在迁移后跑 `tools/check-built-links.py` 复查 |

### 5.2 迁移怎么做

1. **`data/tree-migration.json`** —— 人工策展的迁移表：
   - `dir_map`：旧目录前缀 → 新目录（`"db/postgresql/learning-path/"` → `"source-tracks/postgresql/getting-started/"`）
   - `file_map`：逐文件的例外（文件名不跟目录走的，比如 `docs/base/*.md` 这种一个目录里混着
     多个主题的，需要逐篇指定）
   - `out_map`：要移出 `docs/` 的目录与文件 → `internal/` 下的目标位置
   规则来源：`data/learning-path.json` 的 62 条规则 + 新树的三级映射。

2. **`tools/migrate-tree.py`** —— 执行迁移（幂等，可重复跑）：
   - 按 `dir_map` / `file_map` 逐个 `git mv`（**必须用 `git mv`**，保留文件历史）
   - 按 `out_map` 把内部文档移到 `internal/`
   - 顺手生成三张补丁：`REDIRECTS`（旧路径 → 新路径）、`DATE_OVERRIDES`（改写后的键）、
     `CATEGORY_REDIRECTS`（旧分类 → 新分类）
   - 修 `FEATURED_POSTS`、`infer_topics()` 的前缀规则、`META_CATS`

3. **重定向的日期依赖（最容易漏的一条）**：`write_redirects()` 用 `git_date(new_file)`
   取日期来拼旧 URL 的日期段（`sync-hexo.py:1921`）。而 `git_date()`（`sync-hexo.py:606`）
   的兜底是 `git log --all --reverse -- <当前路径>` —— **`git mv` 之后，这个路径的
   最早提交就是「搬运」那一次**，于是日期变成搬运日。
   后果是双重的：① 文章日期全变，574 篇一齐跳到「最近发布」顶部；② 重定向页被写到了
   **错误的旧 URL**（日期段对不上），旧链接照样 404。

   **对策（唯一正确解）**：迁移时把**每一篇被搬文章的原始日期**固化进 `DATE_OVERRIDES`，
   **键用搬完之后的新路径**（`git_date` 查表用的就是当前相对路径）。
   这样 `git_date(new_file)` 返回原日期 → 日期段不变 → 旧 URL 重定向页落回正确位置。
   迁移前必须先把每篇文章的原始日期抓出来（`git log --all --reverse --format=%ai -- <旧路径>`）
   存成一张表。**这是迁移脚本第一件要做的事，也是验收项。**

   **已实测（2026-11-17）**：568 篇文章的原始日期**全部可取，零遗漏**（`git log --all
   --reverse -- docs/<路径>`），可以直接生成完整的 `DATE_OVERRIDES` 表。
   但要注意这个分布：其中 **290 篇共用同一个日期 `2025-04-16`**（当年批量导入的时间戳），
   年份分布 2025 年 305 篇 / 2026 年 263 篇。**日期机制一旦在搬运中失灵，
   全站一半的文章会同时跳到同一天** —— 首页与「最近发布」会变成同一天的 290 篇刷屏。
   这比零散的日期错乱更难肉眼发现，也更难回滚，所以这条必须做成**自动断言**
   （迁移前后逐篇比对日期，不一致就退出码 1），不能靠人工抽查。

## 七、与视频流水线的关系

本轮**不挂**。视频与多平台（抖音 / 公众号 / B站）的状态以后再接，接的时候：

- 每篇文章的「已出精简视频 / 已出完整视频 / 已同步平台」状态从
  `publish/outbox/` + `aiv/contracts/` 读
- 新树里每个**系列**（不是每篇）是视频生产的单位 —— 一个系列对应一期视频
- 现有 `series` 字段（播客系列，如「数据库内核机制」六期）与新树的「系列」概念**重名但不同义**，
  接视频时需要先决定是合并成一个概念，还是改名（如 `collection`）

## 八、风险

| 风险 | 缓解 |
| --- | --- |
| 574 条重定向表写错一个键 → 一篇文章 404 | 迁移脚本自动生成，不手写；`check-built-links.py` 复查 |
| 外部链接（知乎、公众号、GitHub 引用旧 URL）全部 404 | 重定向页带 `meta refresh` + `canonical`，外链能跳；**但外链的读者体验是「跳一下」，需要同步通知已知的引用源** |
| `git mv` 574 次，中途失败留下半搬状态 | 迁移脚本幂等 + 可重跑；每块一个 commit，出错能单独回滚 |
| 搬完发现某个旧目录混着多个主题（如 `docs/base/`） | `file_map` 逐文件指定，一张表解掉 |
| 日期被改写 → 「最近发布」被 574 篇霸占 | `DATE_OVERRIDES` 验收项；或把全部文章日期固化进迁移表 |

## 九、留给下一个人的活
