# 站点换 hexo 实施计划

> **Spec:** [`review/specs/2026-11-20-站点框架换成hexo.md`](../specs/2026-11-20-站点框架换成hexo.md)
> —— **§十三 的四条是拍板结果，不再讨论**；规格与实现的出入记在规格 §十四。

**Goal:** 把 `/work/ai/blog-bak` 那套已经优化过的 Hexo + matery 站点整体搬进
`platforms/blog/site/`，替换掉现在的 Astro 实现，并做成**通用框架**
（框架源码里没有一个实例名、一个实例地址、一个人设）。

**Architecture:** 站点是一个**通用框架**，不是一个站。

```
docs/ ──根 tools/build-content-units.py──▶ content/units/
              │                                    │
              │            site/tools/build-posts.py │  + build-learning-path.py
              │                                    │  + apply-site-config.py
              │                                    │  + rewrite-links.mjs
              │                                    ▼
              │        source/_posts/**  source/docs/**  source/learning/**
              │        source/_data/{site,learning,urls}.json
              │                                    │
              └────────────── hexo generate（themes/matery）──▶ dist/
```

**Tech Stack:** Hexo 7.3.0 + matery 主题、Node 22、Python 3.12（pytest、PyYAML）、
remark/unified（AST 级链接重写）。

## Global Constraints

1. **存量不回炉。** `docs/` 现在是空的，这一轮**不写任何内容**——所有新用例一律在
   `tmp_path` 里自己造语料。
   > 「一条用例如果依赖「仓库里曾经有有的内容」，它迟早会因为内容被清掉而变成假红。
   > 新的用例一律在自己造语料。」
2. **验收按模块拆开。** 站点模块一条命令，跑在自己的目录里：
   `cd platforms/blog/site && npm run build && python3 -m pytest tests/ -q`。
3. **框架源码里不许出现站名。** 值全在使用者那一侧（`site/data/site.json`）。
   这条由 `tests/test_site_config.py` 守着。
4. **地址形状只有一处。** `site/tools/urls.py` 读仓库根的 `rules/urls.json`；
   规则表不在时用同样的默认值兜底。**地址仍是 `/docs/<id>/`**（作者拍板）。
5. **正文一个字都不改。** `build-posts.py` 只改 front matter、拷贝正文；
   链接重写是**渲染层**的事，且**在 AST 上改**。
6. **不许退回正则改写链接。** 旧 hexo 时代的正则重写器会把正文里的方括号
   （`[s, s+D)`）吃成上千字的巨型链接——这条仓库已经吃过亏。
7. **提交粒度：** 一个 Task 一次提交（Task 内可多次）。提交信息用中文，
   **不加 `Co-Authored-By`**。
8. **每次提交前跑一遍受影响模块的套件**，红的必须归零。
9. **文档跟着代码走：** 行为变了就改对应的 README / 规格，别留过时的说法。

### Task 6: 内容管线（渲染）

**Files:**
- Create: `platforms/blog/site/tools/rewrite-links.mjs`
- Create: `platforms/blog/site/scripts/mermaid.js`
- Create: `platforms/blog/site/tools/copy-vendor.py`

**链接重写走 AST**：remark 解析出链接节点，按节点位置**外科式**替换原文的
那一小段。目标不存在就**原样留下**（于是 404）——补一个缺失的页面时
不用去改引用它的那些链接。

**mermaid 走 hexo 过滤器**：两道——
`before_post_render`（围栏还在时）与 `after_post_render`
（`<pre><code class="language-mermaid">`）。

> ⚠️ **不要用 `marked:renderer` 过滤器。** hexo 内核的 `backtick_code_block`
> 是个 `before_post_render` 过滤器，在 `syntax_highlighter: prismjs` 时
> **先把围栏变成高亮 HTML**，marked 的 `code()` 渲染器根本看不到围栏。
> 实测：用 `marked:renderer` 写 mermaid 过滤器，产物里出来的是
> `<pre class="language-mermaid">`（不是 `<div class="mermaid">`）。
> 博客-bak 那套两道过滤器的写法是对的。

**资源本地化**：`copy-vendor.py` 把 `node_modules` 里的第三方库拷进
`source/lib/`，主题从 `/libs/` 出——**不走 CDN**。

**验收：** `test_mermaid_render.py`、`test_perf_optimizations.py`、
`test_pages.py`（死链）。

## Review Focus

规格说了「要怎样」但没说的几件事——每一条都写成了守卫。做的时候别跳过。

1. **mermaid 过滤器挂在哪个时机上。** 用 `marked:renderer` 写，产物里出来的是
   `<pre class="language-mermaid">`——hexo 内核的 `backtick_code_block`
   抢先把它变成高亮 HTML 了。→ `test_mermaid_render.py`（node 夹具跑真过滤器）。
2. **`<nav>` 在内容模板里。** Materialize 按元素名给 `nav` 上样式
   （`nav{height:64px;...}`）——正文中间会横一条 64px 的红条。
   → `test_content_nav_not_materialize_navbar.py`。
3. **框架源码里漏一个站名。** 改配置没改全，页脚还挂着旧站名——
   这类漏**最难发现**，因为它编译得过去、测试也过得去。
   → `test_site_config.py`（扫主题模板 + 脚本 + 工具）。
4. **链接重写退回正则。** 正文里任何不成对的方括号（`[s, s+D)`）都会让它
   一路吃到后面某个链接的右括号，渲染出一个上千字的巨型蓝色链接。
   → `test_pages.py` 的死链检查 + `test_posts.py` 的正文逐字比对。
5. **`tools/urls.py` 的 `parents` 算错一层。** 指到 `platforms/` 去了，
   `rules/urls.json` 读不到，**默认规则静悄悄地生效**。
   → `test_posts.py` 的地址形状断言（它用的是真规则表）。
