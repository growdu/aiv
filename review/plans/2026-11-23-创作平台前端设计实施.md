**Goal:** 给仓库的内容生产线做一个**本地单用户的创作平台**：人在浏览器里选稿、编辑、看审校信号、预览产物、点「过审」与「出片」，而所有真相仍然在 CLI 和文件里。

**Architecture:** 两个新模块，中间只有**一条 HTTP 缝**。

- **`api/`**（仓库根级）= HTTP 门面，FastAPI + uvicorn。它**不含业务规则**，只做三件事：读文件、调 CLI、起后台作业。作业调的命令与手敲命令行**逐字等价**（反目标 A3）。
- **`front/`** = Vue 3 + Vite 的**纯客户端**。它不 import 任何后端模块（连 `api/` 都不 import），只发 HTTP。
- **`drafts/` 是平台唯一的写点。** 「保存」写 `drafts/`；「过审」是**另一个动作**，把草稿**复制**进母稿层（`docs/` 或 `video/episodes/`），复制之后**不写审校记录、不补 INDEX、不 commit**——那三步留给人。

**Tech Stack:** Python 3.12（FastAPI 0.115、uvicorn 0.34、pytest ≥8）、Vue 3 + Vite + TypeScript + vitest + `@vue/test-utils`（Node ≥20；站点用的是 Node 20 + hexo 7.3）、TOML、JSON、GNU Make。

**Spec:** [`review/specs/2026-11-23-创作平台前端设计.md`](../specs/2026-11-23-创作平台前端设计.md) —— §四 的 12 条决定与 §九 的 3 处范围裁剪是**权威**，本计划逐条实现。

## Global Constraints

这几条对每个 Task 都成立。**每条都照抄规格里的原话或仓库里的既有规矩，不许自行发挥。**

1. **层间零 import。** `front/` 零 import（连 `api/` 都不 import，只发 HTTP）；`api/` **不 import** `publish/publishkit/`（规格 D12）、**不 import** 任何 `platforms/<plat>/` 包（出包一律走 subprocess）、**不 import** 站点模块。`api/` 是**唯一**允许 import `tools/` 与 `video/pipeline/pyv/` 的新模块。
2. **身份缝。** `api/` 与 `front/` 的源码里不许出现站名、品牌名、具体平台名。值全在使用者一侧：`platforms/blog/site/data/site.json`、`video/config.toml`、`platforms/<plat>/capability.toml`。平台 id 是**扫目录**得到的，不是写死的。
3. **验收按模块拆开。** `api/` 一条 `cd api && python3 -m pytest tests/ -q`；`front/` 一条 `cd front && npm run test`。**不搞整站合跑**，不在 `contracts.yml` 里合跑。
4. **保存只写草稿箱。** `PUT /api/drafts/{id}` 只写 `drafts/`。**前端绝不提供直接写 `docs/`、`video/` 的入口。**
5. **「过审」= 只复制。** 只复制**入库事实**（`口播稿.md` / `contract.json` / `publish.json` / `skeleton.yaml` / 文档的 `.md`）。**不复制** `narration.mp3`、`storyboard*.json`、`frames/`——它们撞 `video/pipeline/tests/test_assets_are_tracked.py` 的 `EPISODE_PRODUCT_PATTERNS` 与 `video/.gitignore`。复制**不是移动**：草稿留在 `drafts/`。复制之后**不写审校记录、不补 `review/INDEX.md` 与 `video/review/INDEX.md`、不 commit**——那三步由人做。
6. **审校与出片只在母稿层跑。** `pyv/episodes.py:46` 的 `EPISODES_DIR` 写死成 `video/episodes/`，草稿态根本跑不了。所以「出片」= **先 promote 再跑 make**；草稿层只做编辑 + 通用机械检查。
7. **目录即接口。** 期列表 = 扫 `video/episodes/*/*/*/{short,mid,full}/`（`pyv/episodes.py::known_eps_at` 认「深度 4 且末段是档位名」）。**没有登记表。**
8. **只做框架，不做内容。** `api/` 与 `front/` 里不放任何具体内容；测试夹具放 `api/tests/fixtures/`，**不进 `docs/`、不进 `drafts/`**。
9. **subprocess 的 argv 必须逐个传参，绝不拼 shell 字符串。** 期路径含中文与空格（例：`postgresql/getting-started/postgresql基操/short`），拼了就会被 shell 拆词，跑去的是另一期。
10. **退出码两层。** `exit_code` 是原始码，`exit_label` 是尽力而为的标签。原始码本身有损：`pyv/cli.py` 用 `1` 同时表示「用法错」和「内容错」，`review-check.py` 恒返回 `0`，`make` 缺 `EP=` 退 `2`。**不准把 `1` 说成「用法错」**；不认识就标 `unknown`。
11. **信号不是门禁。** `pyv/cli.py::cmd_review` 恒返回 0（注释原文「信号不是门禁：命中信号不返回非零退出码」）；`tools/review-check.py` 的 docstring 写着同一句话。**文档流的 `counts.error` 恒为 0**——它只会发 `warn` 与 `info`。**平台不得发明一道仓库没有的闸**：`gate` 只看审校记录的**状态**。
12. **平台名不写进路由。** 路由只按**资源**分（`/api/drafts`、`/api/episodes`…）。期路径是**四层** `<分类>/<合集>/<文档>/<档位>`，相对 `video/episodes/`；路径参数都带斜杠 → FastAPI 用 `{param:path}`。
13. **不改现有流水线的行为。** `api/` 只**调** `pyv` / 编译器 / 各平台 CLI，不改它们。
14. **路由注册顺序有讲究。** `/api/drafts/draft`（AI 起草，第一版 501）必须**注册在** `/api/drafts/{draft_id:path}` **之前**，否则 `{draft_id:path}` 会把它吃掉。

## 三处「规格的字面写法 vs 本计划的落地」

规格留了三个自由度，这里把选择定下来并说明理由。评审时照这三条看。

| # | 规格怎么说 | 本计划怎么落地 | 为什么 |
| --- | --- | --- | --- |
| 1 | §6.1：`GET /api/artifacts/{artifact_id}`「按 `artifact_id` 查表返回，不接受任意路径」 | `artifact_id` **就是产物在仓库根下的相对 posix 路径**（如 `video/out/系列-合集-文档-档位.mp4`）；路由用 `{artifact_id:path}`；取用前必须过**白名单根 + 仓库根**双重校验，失败一律 404 | 建进程内注册表会让重启后所有 id 失效，产物是磁盘上的事实，路径就是它唯一的稳定标识。**防穿越靠校验，不靠不认路径** |
| 2 | §6.1：`GET /api/drafts`「列出草稿箱里的全部单元（带 `kind`）」 | 只列 `kind ∈ {document, skeleton, episode, index, bundle}` 的单元；`README.md`（说明文件）与形状对不上的东西（`unknown`）**不列** | 说明文件不是可编辑单元；形状对不上的东西列出来也点不动。但**索引页与 bundle 稿要列**——它们存在，只是**不给过审按钮**，界面上标原因 |
| 3 | §6.3：「同一期同时只允许一个作业在跑；重复提交返回已有 `job_id` 而不是排队」 | 去重键 `key` = 作业身份（期路径 / 文档 id / 平台 id）。`submit(kind, argv, cwd, key=…)` 命中同 key 的**在跑**作业就**返回那一个**，不新起 | 与规格一致；额外把「排队」也去掉了——排队会让用户以为在跑，其实没有 |

## Review Focus

规格暗示、但**没有一条 Task 的测试覆盖**的五种输入/状况，按「最可能咬人」排序。**每一条在下面都有对应的 Task 与测试**，实现时不要漏。

1. **期路径含中文与空格**（`postgresql/getting-started/postgresql基操/short`）。合理的人期望：出片跑的是**这一期**，不是被 shell 拆词后的另一期。→ Task 6 的 `test_the_argv_is_passed_as_a_list_not_a_shell_string`。
2. **草稿目录里躺着 `narration.mp3` / `storyboard.json` / `frames/`**。合理的人期望：「过审」只复制**入库事实**，产物不跟着进母稿层（跟过去会撞 `EPISODE_PRODUCT_PATTERNS` 守卫，仓库直接红）。→ Task 4 的 `test_promote_copies_only_the_tracked_facts`。
3. **产物 id 里带 `../../etc/passwd` 或绝对路径**。合理的人期望：**404**，一个字节都不读。→ Task 10 的 `test_an_artifact_id_cannot_escape_the_whitelisted_roots`。
4. **前端只提交了改动的那一个文件**（body 的 `files` 只有一个键）。合理的人期望：服务端**只写 body 里给的键**，其余文件原样不动，也不许借文件名写出 `drafts/` 之外。→ Task 3 的 `test_write_touches_only_the_keys_in_the_body`。
5. **同一期连点两次「出片」**。合理的人期望：**只有一个** `make` 在跑，第二次返回同一个 `job_id`，不并行跑两个渲染流水线。→ Task 6 的 `test_resubmitting_the_same_key_returns_the_running_job`。
