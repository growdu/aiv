# 学习路径：把 577 篇文章排成一条能读下去的路

日期：2026-11-17
起因：作者拍板 —— 「当前学习路径还不能涵盖所有的内容，需要对所有的文章进行整理分类，
形成循序渐进的文档」。

---

## 一、问题

站内 **577 篇文章**，分在 **43 个分类**里。但分类是**检索**用的，不是**导航**用的：

- 首页首屏的 9 个徽章只盖到 9 个分类；
- 最大的几个分类（`数据库` 154、`数据库深入` 94、`Linux` 38、`AI` 29）**连入口都没有**；
- 读者从一篇文章落地之后，站点没有告诉他「下一篇该读什么」；
- 全站唯一一条成体系的路是 PostgreSQL 源码修炼之路（14 章），只覆盖 216 篇里的一部分。

**分类 ≠ 路径。** 分类回答「这一篇属于哪」，路径要回答「按什么顺序读，读完能做什么」。

## 二、拍板（作者选的三条）

| 问题 | 选择 |
| --- | --- |
| 产出形态 | 一个 `/learning/` 总览页 + 每条赛道一页；首页首屏加「从这里开始」入口 |
| 赛道划分 | 43 个分类收成 **8 条赛道**，分类/标签仍作为文章属性保留，另加「赛道 + 阶段」这一层 |
| 生成方式 | 脚本生成 + 覆盖守卫（`tools/build-learning-path.py` + `tests/test_learning_path.py`） |

## 四、做法

### 4.1 规则与代码分开

- `data/learning-path.json` —— **人工策展的部分**：8 条赛道，每条赛道几个阶段，
  每个阶段一条条匹配规则。改这个文件就能改路径，不用改代码。
- `tools/build-learning-path.py` —— 干活的：读文章、按规则归类、生成页面。

匹配键：`path_prefix` / `path_regex` / `path_exact` / `category` / `tag` /
`title_contains` / `any` / `all` / `catch_all`。

### 4.2 语料从哪来

生成器读 `source/_posts/`（sync 之后的产物，front matter、扁平化路径、日期都是对的，
不必重算第二遍 permalink）。

但**守卫测试不能依赖构建产物** —— `site-guard.yml` 不构建。所以规则表另有一条
不依赖产物的语料：`docs/` 里的文章（按 sync 的展平规则算出路径）+ `aiv/pipeline/Makefile`
里登记的 6 期视频内容单元。两条语料在构建时对账（`corpus_mismatch()`），
对不上就报错 —— 展平规则漂了会立刻响。

### 4.3 踩过的三个坑

1. **先判阶段再判赛道**：赛道里的兜底阶段会把后面赛道的文章全吞掉，
   574 篇全落进第一条赛道。改成**先定赛道、再在赛道内分阶段**。
2. **阶段之间不互斥**：一篇 learning-path/01 同时进了 L1 和 L8。
   改成阶段内贪心分配（先命中先占位）。
3. **`catch_all` 写在中间阶段**：`ai-tools` 的 L3 兜底把 `ai/ai_video/` 吃了，
   L4 空掉。**所有 `catch_all` 全部删掉**，改用 `fallback_stage`，
   并把「`catch_all` 只能写在最后一个阶段」钉成测试。

### 4.4 顺手改掉的三处策展问题

- 6 期视频内容单元原本落在「博客与自媒体 · 视频生产线」，但它们讲的是
  行锁 / 并行解码 / WAL 顺序 / CSN 全序 / 结构化 DDL / 并行 apply ——
  是数据库内核内容，**移到 db-internals** 的对应阶段。
- `tools/` 下 21 篇通用工具（shell、vim、doxygen、clash、code-server……）
  原本挂在「AI 与工具」赛道下 —— 它们跟 AI 没关系，**移回 engineering**，
  按「基础 / 工程化 / 容器 / Web」分进四个阶段。
- `ai/18_`、`ai/19_` 两条「AI 是你的杠杆」因为规则里多了个 `$` 锚点，
  掉进了兜底阶段；顺手把这条赛道的阶段改成
  「理解 AI → AI 工具箱 → 把 AI 变成杠杆 → AI 视频平台设计」。

### 4.5 渲染时才发现的两个 Markdown 坑

分类对了不等于页面能用。这两个坑都是在**渲染产物**里看出来的 ——
生成器自己看不出来，守卫测试也拦不住（它们盯的是分类，不是 HTML）。

1. **标题里的 YAML 转义把链接写坏了**。sync 把标题写成 YAML 双引号串，
   引号被转义成 `\"`（`title: "...数据库\"脱颖而出\""`）。生成器原先用
   `.strip('"')` 取标题，末尾就多出一个孤零零的反斜杠 ——
   Markdown 链接文字以 `\` 结尾时，marked 会把 `]` 一起吞进去，
   整行退化成纯文本，页面上那篇文章**点不开**。
   修法：生成器借 sync 的 `_front_matter_title()`（**解标题只有一份实现**）。
2. **标题里自带 Markdown 链接会渲染出嵌套 `<a>`**。有一篇的标题是
   `[kali](https://so.csdn.net/...)搭建docker`，原样放进链接文字，
   里层的链接被重新解析一遍，渲染出 `<a>` 套 `<a>` —— 非法 HTML，
   浏览器会把里层链接提出来，外层的文章链接就断了。
   修法：链接文字里的 `\ [ ] ( ) ` * ` 全部转义。

两个坑都补了守卫：标题里不该有反斜杠、链接文字里不该有裸的 Markdown 语法字符。

## 六、守卫（`tests/test_learning_path.py`）

1. 每篇文章都归到了**恰好一条**赛道的一个阶段（不许漏、不许重）；
2. 生成的赛道页里，每篇文章**恰好出现一次**；
3. 兜底阶段吸收 **0** 篇（加文章就得写规则）；
4. 规则文件结构合法：赛道 id 唯一、阶段 id 递增、`fallback_stage` 存在；
5. `catch_all` 只允许出现在最后一个阶段；
6. 站内链接必须带挂载点前缀（主站 `/`、镜像站 `/blog/`）；
7. 生成器在两个 CI job 里都跑，且排在 sync 之后、generate 之前；
8. 首页面板只能读 `site.data.learning`，不许再写死赛道清单；
9. 生成的数据每条赛道都要备齐 id/标题/图标/简介/文章数/链接，阶段数加起来 = 文章数；
10. 标题按 YAML 解析（不许照抄带转义的原文），链接文字里的 Markdown 语法字符全部转义。

## 七、没做的事

- **不改 front matter**：没有给文章加 `difficulty` / `stage` 字段 ——
  阶段由规则表推导，加字段就要维护两处真相。
- **不做逐篇难度评级**：「循序渐进」落在**赛道和阶段**这一层，
  阶段内部按「编号系列在前、其余按时间」排。
- **不动 `/categories/`**：分类页继续是检索入口，学习路径是导航入口，两者并存。
