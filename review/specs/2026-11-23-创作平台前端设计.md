# 创作平台（`front/` + `api/`）设计

> **这是什么**：给本仓库的内容生产线做一个**本地单用户的创作平台**——
> 人在浏览器里编辑稿子、看审校信号、预览产物、迭代重跑。
>
> **这不是什么**：不是给观众看的门户页（那是 `platforms/blog/site/`），
> 不是内容管理后台（没有账号、没有多租户、不能上公网）。
>
> **状态**：设计已定稿，未开工。实现前先读本文 §三（约束）与 §十（验收）。

---

## 一、为什么要有它

### 1.1 今天的实际操作是这样的

改一篇稿子，要在这五个地方来回切上下文：

| 步 | 在哪 | 用什么 |
| --- | --- | --- |
| 改稿 | `drafts/` | 编辑器 |
| 看审校说了什么 | `drafts/` 侧 | `python3 tools/review-check.py <path> --json` |
| 出片 | `video/episodes/<期路径>/` | `make EP=... all`（几分钟） |
| 看产物 | `out/`、`build/` | 文件管理器 + 播放器 |
| 看出包到哪了 | `platforms/*/outbox/*.json` | `cat` |

**没有一处能同时看到「稿子长什么样 / 审校说了什么 / 产物长什么样」。**
创作平台要补的就是这一个「一处」。

### 1.2 现状里客观存在的缺口（都是查证过的事实，不是推测）

| 缺口 | 事实 |
| --- | --- |
| 没有 HTTP 服务 | 全仓 grep 不到 fastapi/flask/express/uvicorn 的生产代码；`http.server` 只出现在各平台的**测试替身**里 |
| 两条线的审校不是一个东西 | 文档流跑 `tools/review-check.py`，视频流跑 `pyv review`；规则号不同、定位字段不同、门禁语义不同（见 §6.2） |
| 草稿箱只有一种形状 | `drafts/README.md` 只定义了**文档流**的形状（`drafts/<分类>/<二级>/<期号>.md`）；视频线的草稿落哪没定过 |
| 产物只能去文件系统翻 | `out/`、`build/` 里是什么，只有跑过 `make` 的人知道 |
| `video/episodes/` 是空的 | 现在建期目录=登记，所以真跑起来之前没有存量数据可看 |
| 站点 dev server 起不来 | `platforms/blog/site/package.json` 有 `"server": "hexo server"`，但 `hexo-server` **不在依赖里、不在 lock 里、不在 `node_modules` 里** |

## 二、目标 / 非目标 / 反目标

### 2.1 目标

- **G1 一处看两条流**：文档流与视频流在同一个界面里，共享同一套审校表与同一套操作。
- **G2 编辑只落草稿箱**：平台里的「保存」写 `drafts/`，不碰 `docs/`、`video/`。
- **G3 审校统一成一张表**：两条线的信号长得一样（同一套字段、同一套 severity 词表），
  在同一个视图里排在一起。
- **G4 能看见产物**：视频看**成片 + 中间大产物**（旁白音频、时间轴、渲染帧、成片 mp4）；
  文档看**站点真页面**（hexo dev server 嵌 iframe）。
- **G5 长任务有进度**：点「出片」之后能看到日志在滚、成片什么时候好。

### 2.2 非目标（第一版明确不做）

- **N1** 账号、鉴权、多用户、权限、云端部署。工具只监听 `127.0.0.1`。
- **N2** AI 起草。**接口位留着**（`POST /api/drafts/draft`），第一版返回 `501 未启用`。
  稿子由 Claude Code 写进 `drafts/`（仓库现状就是「AI 协作者是入口」）。
- **N3** 真实平台上传。发布仍然是 `manual` 档，平台只负责**出包**与**读出包状态**。
- **N4** 单帧分镜的细化预览。第一版只看成片与中间大产物。
- **N5** 改动现有流水线的**行为**。`api/` 只**调** `pyv` / 编译器 / 各平台 CLI，**不改**它们。
- **N6** 替人做审校判断。平台展示信号与状态，不替人判「能不能过」。

### 2.3 反目标（做到这些就算失败）

- **A1** `front/` 里出现后端逻辑，或 `front/` import 了任何后端模块。
- **A2** 平台能直接把稿子写进 `docs/` 或 `video/`（绕过审校）。
- **A3** 平台跑出来的结果与命令行跑出来的不一致（流水线是唯一的真相）。

## 三、约束（仓库硬规矩，违反即失败）

| 约束 | 出处 | 在本设计里的含义 |
| --- | --- | --- |
| **层间零 import** | `AGENTS.md` §4.2 | `front/` 零 import（连 `api/` 都不 import，只发 HTTP）；`api/` 是缝的拥有者，是**唯一**允许 import `tools/` 与 `video/pipeline/pyv/` 的地方 |
| **不 import 契约层** | `video/pipeline/pyv/epmeta.py` 的先例 | `api/` **不 import `publish/publishkit/`**。能力声明、限额、退出码词表都是**读 TOML/JSON + 抄词表 + 用测试钉住**，与 `epmeta.py` 的做法一致 |
| **身份缝** | `AGENTS.md` §4.2、`tests/test_instance_identity.py` | `front/` 与 `api/` 源码里不许出现品牌名、站名、具体平台名。值从 `video/config.toml`、`platforms/blog/site/data/site.json`、`platforms/<plat>/capability.toml` 取。守卫要覆盖 `.vue` / `.ts`（现有守卫的 `CODE_SUFFIXES` 里没有 `.vue`） |
| **验收按模块拆开** | `AGENTS.md` §4.2 | `api/` 一条 `cd api && python3 -m pytest tests/ -q`；`front/` 一条 `cd front && npm run test`。不搞整站合跑 |
| **改动稿先落草稿箱** | D11、`drafts/README.md` §四 | 「保存」写 `drafts/`；「过审」是独立动作，把草稿复制进母稿 |
| **目录即接口** | `AGENTS.md` §三 | 期列表 = 扫 `video/episodes/*/*/*/{short,mid,full}/`（`pyv/episodes.py::known_eps_at` 认「深度 4 且末段是档位名」）；没有登记表 |
| **只做框架，不做内容** | — | `front/`、`api/` 里不放任何具体内容；期目录、稿子都是用户自己的。测试夹具放 `api/tests/fixtures/` |

## 四、已定的决定

下面 12 条是本次讨论拍板的，不再讨论。每条后面标了为什么。

| # | 决定 | 为什么 |
| --- | --- | --- |
| D1 | **纯本地单用户工具** | 账号/鉴权/并发/部署全都不做，范围砍掉一个量级 |
| D2 | 视频预览 = **成片 + 中间大产物**（旁白、时间轴、渲染帧、成片 mp4） | 单帧分镜留给以后；第一版先能验「片子对不对」 |
| D3 | 文档预览 = **hexo dev server 嵌真页面**（`http://127.0.0.1:4000/docs/<id>/`） | 所见即所得，复用现有 hexo 工具链，不造第二个渲染器 |
| D4 | 前端 = **Vue 3 + Vite** | 与仓库现有 Node 工具链一致（站点是 Node 20 + hexo 7.3） |
| D5 | 后端门面 = **根级 `api/` 模块**，FastAPI + uvicorn | 门面同时罩住文档流（`tools/`）与视频流（`pyv`），名字中性；`video/api/` 名不副实（它罩不住文档流） |
| D6 | `front/` 是**纯客户端**，只认 HTTP | 「层间零 import」成立；以后别的客户端也能用 `api/` |
| D7 | 审校**两条线统一**，顺序是**先文档流、后视频流** | 仓库既有约定（`review/specs/2026-11-18-草稿层到视频层的接口协议.md`）：文档先过审，视频稿才从 `docs/` 派生 |
| D8 | 视频线的草稿落 **`drafts/_video/<分类>/<二级>/<文档>/<档位>/`** | 与期坐标**逐段对应**（期坐标 = 分类/二级/文档/档位，前三层正是母稿路径去掉 `.md`），映射是「加个前缀」，不需要登记表。母稿层 `video/` 保持「已过审的版本」；草稿箱仍是两条流的**共同入口**（一个箱子，不是两个） |
| D9 | **「过审」= 只复制** | 复制进母稿层后，审校记录、`review/INDEX.md`、`video/review/INDEX.md` 与 git commit **全部由人做**。平台只提示「接下来请人工建记录、补 INDEX、提交」 |
| D10 | **审校与出片只在母稿层跑** | `pyv` 的期根写死成 `video/episodes/`（`episodes.py:46` `EPISODES_DIR = AIV_ROOT/"episodes"`），草稿态根本跑不了。平台的「出片」按钮 = **先 promote（复制）再跑 make**。草稿层只做编辑 + 通用机械检查 |
| D11 | 文档预览 = **给 site 补 `hexo-server` 依赖** | `hexo-server` 没装，`npm run server` 现在跑不起来。补依赖拿热重载，代价是改 `package.json` + lock + CI |
| D12 | `api/` **不 import `publish/publishkit/`** | 照 `pyv/epmeta.py` 的先例：能力声明是数据文件，**读**它，不 import。顺带避开一个坑：`publishkit/episode.py` 里的 "episode" 是**文档流的期号 slug**，不是视频的四层期路径，两套坐标同名，import 进来一定会踩 |

> **D8 的补充**：`_video/` 是**保留前缀**，标记成「不是分类」——
> 它不进 `docs/`、不生成 URL、不登记 `learning-path.json`，
> 所以 `drafts/README.md` §一 的三条后果（URL 命名空间永久 / 三边要同形 / 要登记映射）
> **一条都不触发**。代价：仓库里第一次出现 `_` 前缀目录（此前只有 `_index.md`），
> **这个约定必须写进 `drafts/README.md`**，否则下一个人会把它当成一个分类。
> 这是本设计产生的一条**待还账**（见 §九）。

## 六、`api/` 的接口面

### 6.1 路由

所有路径以 `/api` 开头。**平台名、品牌名一律不写进路由。**
路径参数都带斜杠（FastAPI 需要 path converter），期路径还含中文与空格——
**subprocess 的 argv 必须逐个传参，绝不拼 shell 字符串**。

#### 稿件（草稿箱）

**草稿是平台的唯一写点**，所以编辑接口全部挂在这里。
一个草稿是**一个复制单元**（`review/specs/2026-11-18-草稿层与母稿层的接口协议.md` §五）：

| `kind` | 草稿路径（相对 `drafts/`） | 单元里有什么 |
| --- | --- | --- |
| `document` | `<分类>/<二级>/<期号>.md` | 1 个 markdown（正文 + front matter + `topic:`） |
| `skeleton` | `_video/<分类>/<二级>/<文档>/` | 1 个 `skeleton.yaml`（文档级，三档共用） |
| `episode` | `_video/<分类>/<二级>/<文档>/<档位>/` | `口播稿.md` + `contract.json` + `publish.json` |

`kind` 由**路径形状**决定，不另存字段。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/drafts` | 列出草稿箱里的全部单元（带 `kind`）。**排除 `README.md`**（说明文件，不进母稿）；`_index.md` 单列（索引页第一版不支持过审，见 §九 Q2）；bundle 形态的目录稿也单列（第一版不支持过审，见 §九 Q3） |
| `POST` | `/api/drafts` | 新建**空白**草稿（`document` 或 `episode`；`episode` 要期坐标） |
| `GET` | `/api/drafts/{draft_id}` | 读一个草稿单元：`{path, kind, files}`，`files` 是「文件名 → 内容」的映射 |
| `PUT` | `/api/drafts/{draft_id}` | **写回草稿单元**（body: `{files: {…}}`）。只写 `drafts/`，不碰母稿 |
| `POST` | `/api/drafts/{draft_id}/promote` | **过审**：把草稿单元复制进母稿。见 §七 7.3 |
| `POST` | `/api/drafts/draft` | **AI 起草——第一版返回 501 `未启用`**（接口位留着，见 §二 N2） |

> **为什么不按「文档 / 视频」分两套编辑接口**：编辑的落点只有草稿箱一个，
> 分两套只会让「保存到底写到哪」出现两个答案。两条线的差别体现在
> **单元里有哪些文件**（`files` 的键），不是体现在接口上。

#### 配置与身份

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/config` | 站名 / 简介 / 导航 / 品牌名（读 `platforms/blog/site/data/site.json` 与 `video/config.toml`）。前端不写死任何身份 |

#### 平台能力

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/platforms` | 各平台的能力声明（`capability.toml`：id/name/kind/automation/limits/media/tiers）+ 发布规格（`publish-spec.json`：required/text_limits/list_limits/int_fields/int_domains/required_when） |

前端用它做字数计数与字段校验，**不 import 任何平台相关的东西**。

#### 审校（两条线统一，见 §6.2）

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/review/overview` | 两条线的进度表合并（`review/INDEX.md` 7 列 + `video/review/INDEX.md` 8 列，**列名不一样**，要各自解析后投影成公共子集） |
| `GET` | `/api/review/documents/{doc_id}` | 文档流审校（`tools/review-check.py --json --docs-root=docs/` + `review/` 里的审校记录状态） |
| `GET` | `/api/review/episodes/{episode}` | 视频流审校（`pyv review text --json` + `pyv review video --json` + 该期 `review.md` 的状态） |
| `POST` | `/api/review/episodes/{episode}/run` | 起作业跑一遍审校（作业模型见 §6.3） |

#### 文档流

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/documents` | 列出 `docs/` 里的母稿 |
| `GET` | `/api/documents/{doc_id}` | 读一篇母稿 |
| `POST` | `/api/documents/{doc_id}/rebuild` | 起作业：见 §六.4 的编译次序 |
| `GET` | `/api/documents/{doc_id}/preview` | 返回预览 URL（`http://127.0.0.1:4000/docs/<id>/`） |

#### 视频流

这一组**只读母稿层 + 起作业 + 读产物**。编辑不在这里（编辑走 `/api/drafts/…`）。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/episodes` | 期目录树（系列→合集→文档→档位），扫目录得到，无登记表 |
| `GET` | `/api/episodes/{episode}` | 一期的全部内容：口播稿、契约、发布元数据、产物清单 |
| `GET` | `/api/episodes/{episode}/draft` | 这一期对应的草稿单元（`drafts/_video/<分类>/…/<档位>/`）；不存在返回 404，**由前端引导去新建** |
| `POST` | `/api/episodes/{episode}/build` | 起作业：**先 promote 再出片**，见 §六.4 |
| `POST` | `/api/episodes/{episode}/package` | 起作业：各视频平台出包，见 §六.4 |
| `GET` | `/api/episodes/{episode}/artifacts` | 中间大产物清单 + 可用时的可访问 URL |

`{episode}` 是**期路径**（四段，`<分类>/<合集>/<文档>/<档位>`），不是期号、也不是文档路径——
这条规矩在整个仓库是一致的（`AGENTS.md` §五）。

> **一期与它的草稿一一对应**：期路径 `<分类>/<合集>/<文档>/<档位>`
> ↔ 草稿路径 `_video/<分类>/<合集>/<文档>/<档位>`。前缀是固定的 `_video/`，其余逐段相同。

#### 产物取用

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/artifacts/{artifact_id}` | 取一个产物文件（mp4 / mp3 / png / json），按 `artifact_id` 查表返回，**不接受任意路径**（防目录穿越） |

产物清单由 `GET /api/episodes/{ep}/artifacts` 给出，每个产物带一个 `artifact_id`。
**不接受用户传的路径**——只认白名单目录（`out/`、`build/`、期目录下的 `frames/`），
且解析后必须仍在仓库根内。

#### 出包状态

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/publish/outbox` | 全部 `platforms/*/outbox/*.json` 快照，**投影公共子集**（各平台快照的键数不一样：头条 9、视频 10、公众号 11、站点 README 写 8） |

#### 作业

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/api/jobs/{job_id}` | `{id, kind, status, exit_code, exit_label, started_at, finished_at, log[]}` |
| `GET` | `/api/jobs/{job_id}/events` | SSE，实时推日志行与状态变化 |

`status` ∈ `queued` / `running` / `succeeded` / `failed`。

**退出码要带两层**：`exit_code` 是原始码，`exit_label` 是尽力而为的标签。
因为原始码本身是有损的——`pyv/cli.py` 用 `1` 同时表示「用法错」和「内容错」
（例如「口播稿 N 句与字幕表 M 行不一致」），`review-check.py` 恒返回 `0`，
`make` 缺 `EP=` 退 `2`。标签不准就标 `unknown`，不要把 `1` 说成「用法错」。

### 6.2 统一审校模型

两条线的原始输出（**照抄现状，不改**）：

```jsonc
// tools/review-check.py --json
{ "docs": [ {
    "source": "…", "pillar": "…", "slug": "…", "kind": "…", "title": "…",
    "stats": { "chars": 0, "paragraphs": 0, "h2": 0, "code_blocks": 0, "tables": 0, "images": 0, "mermaid": 0, "links": 0 },
    "depth": { … }, "depth_ok": true,
    "signals": [ { "rule": "AIF-01", "severity": "warn", "line": 42, "excerpt": "…", "detail": "…" } ]
} ] }
```

```jsonc
// pyv review text|video --json
{ "episode": "…", "layer": "text",
  "counts": { "error": 0, "warn": 0, "info": 0 },
  "signals": [ { "rule": "VT-05", "layer": "text", "severity": "warn", "target": "第3句", "excerpt": "…", "detail": "…" } ],
  "notes": [ "…" ] }
```

**词表已经是同一套**（`error` / `warn` / `info`），差别在**定位字段**：
文档流给 `line`，视频流给 `target`。

`api/` 归一成这个形状：

```jsonc
{
  "subject": { "kind": "document" | "episode", "id": "…", "path": "…" },
  "layer": "document" | "text" | "video",
  "counts": { "error": 0, "warn": 0, "info": 0 },
  "signals": [
    { "rule": "AIF-01", "layer": "document", "severity": "warn",
      "target": "第 42 行", "line": 42, "excerpt": "…", "detail": "…" }
  ],
  "notes": [],
  "gate": { "status": "待审", "blocking": true, "reason": "…" }
}
```

归一规则（`api/` 的事，**不改两个工具**）：

1. 文档流的信号补 `layer: "document"`，`target` 由 `line` 派生成「第 N 行」，`line` 保留原值；
   视频流的信号 `line` 补 `null`，`target` 原样。
2. `counts` 一律三档：error / warn / info。
3. **`gate` 是两条线唯一的真差异，必须如实表达，不要抹平**：
   - **信号本身不是门禁**——这是仓库两边都写着的：
     `pyv/cli.py::cmd_review` 恒返回 0，注释原文「信号不是门禁：命中信号不返回非零退出码」；
     `tools/review-check.py` 的 docstring 也写着「信号不是门禁……一篇老文章的历史问题
     不该永久卡住流水线」。**平台不得发明一道仓库没有的闸。**
   - `gate` 只看**审校记录的状态**：
     - 文档流：状态 ∈ `待审 / 审校中 / 建议中 / 已确认 / 已合入`（`tests/test_review_records.py` 钉死），
       `blocking` = 状态 ∉ {`已确认`, `已合入`}。
     - 视频流：第一版取该期 `review.md` 的状态字段；没有 `review.md` 就算「待审」，
       `blocking` = 没有 `review.md`。（视频线**没有**五态状态机，见 §九 Q1）
   - **注意**：文档流的 `counts.error` **恒为 0**——`review-check.py` 只会发 `warn` 与 `info`
     （`Signal("AIF-01","warn",…)` … `Signal("MET-02","info",…)`），从不发 `error`。
     真正有 `error` 的只有视频线（`VT-07` 禁止词、`VV-04`/`VV-07` 技术门槛）与人格检查。

### 6.3 作业模型（长任务）

出片要几分钟，站点 build 要几十秒，都不能同步等。

```
POST /api/episodes/{ep}/build
  → { "job_id": "j-0007", "status": "queued" }

GET /api/jobs/j-0007            → 状态 + 已积累的日志
GET /api/jobs/j-0007/events     → SSE：{"line": "…"} / {"status": "…"} / {"exit_code": 0}
```

- 作业在 `api/` 进程内的后台线程跑（`subprocess` 调 `make` / `python3 -m pyv.cli`），
  日志进内存环形缓冲（保留最后 2000 行）。
- 同一期同时只允许一个作业在跑；重复提交返回已有 `job_id` 而不是排队。
- **作业调用的命令必须与命令行手敲等价**（反目标 A3）。`api/` 不自己实现流水线步骤。

### 6.4 作业的命令与工作目录（照抄仓库现状，不发明）

### 7.2 三条铁律

1. **保存只写草稿箱。** 编辑器里的「保存」打 `PUT /api/drafts/{id}`，落在 `drafts/`。
   **「过审」是另一个按钮**，打 `POST /api/drafts/{id}/promote`，
   把草稿**复制**进母稿。前端绝不提供直接写 `docs/`、`video/` 的入口。
2. **平台名不写死。** 平台列表与限额从 `GET /api/platforms` 取，
   平台 id = `platforms/` 下的目录名。前端不 import 任何平台相关的东西。
3. **身份不写死。** 站名、简介、品牌名从 `GET /api/config` 取，
   `front/` 源码里不出现任何品牌字符串。

### 7.3 「过审」这个动作

它是本平台最需要小心的一步，因为它会写母稿层。

**它只做一件事：复制。**（D9）

| `kind` | 复制 | 目标 |
| --- | --- | --- |
| `document` | 1 个 `.md` | `docs/<分类>/<二级>/<期号>.md` |
| `skeleton` | `skeleton.yaml` | `video/episodes/<分类>/<合集>/<文档>/skeleton.yaml` |
| `episode` | 档位目录里的 3 个文件 | `video/episodes/<分类>/<合集>/<文档>/<档位>/` |

- **只复制入库事实**：口播稿、契约、发布元数据、骨架。
  **不复制** `narration.mp3`（本机素材）、`storyboard.json`（产物）、`frames/`（产物）——
  期目录里合法存在这些文件，但它们撞 `video/pipeline/tests/test_assets_are_tracked.py`
  的 `EPISODE_PRODUCT_PATTERNS` 与 `video/.gitignore`，搬进母稿层会让守卫红。
- **复制不是移动**：草稿留在 `drafts/`（`drafts/README.md` §五「底稿留在 `drafts/`，
  不再参与任何派生」）。
- **第一版有三类草稿不给过审按钮**，界面要标清楚原因：
  索引页 `_index.md`（照抄会造站内死链，§九 Q2）、
  bundle 形态的目录稿（要引用解析器，§九 Q3）、
  以及不属于任何已知 `kind` 的东西（形状对不上）。
- **幂等**：重复「过审」是覆盖母稿里的那一个单元，不动母稿里的其他文件。
  覆盖前先比一遍，有差异就在界面上列出来让人确认。
- **复制之后，界面必须明确告诉人还差三步手工**（D9）：
  ① 建/更新审校记录（`review/<镜像路径>.md` 或期目录下的 `review.md`）；
  ② 补 `review/INDEX.md` / `video/review/INDEX.md` 的行
  （这两个守卫要求与磁盘**集合相等**，`video/pipeline/tests/test_review.py`）；
  ③ 提交（文档流的守卫 G-01 要求 `docs/` 里每一篇都有 `status: 已合入` 的记录，
  而「已合入」需要一次标题为 `docs(review): <slug>` 且真改了源路径的提交）。
  平台**不替人做**这三步，也不替人 commit。

### 7.4 两个同名不同义的 `episode` 字段

编辑器里必须分开摆，否则用户改错一个就过不了 `pyv/epmeta.check_meta` 那道闸：

| 在哪 | 记什么 | 例 |
| --- | --- | --- |
| `口播稿.md` front matter 的 `episode` | **文档路径**（三层） | `<分类>/<合集>/<文档>` |
| `contract.json` 的 `episode` | **期路径**（四层） | `<分类>/<合集>/<文档>/<档位>` |

`publish.json` 的 `episode` 与 `contract.json` 的**逐字相等**（同一个身份）。

## 十、验收

### 10.1 模块自己的套件（拆开跑，不合跑）

```bash
cd api   && python3 -m pytest tests/ -q     # api/ 的契约测试
cd front && npm run test                   # vitest
```

### 10.2 身份守卫

`front/` 与 `api/` 源码里不许出现品牌名、站名、具体平台名。
- **现有守卫要扩**：根 `tests/test_instance_identity.py` 的 `CODE_SUFFIXES` 里
  **没有 `.vue`**（前端是 Vue 3），`SCAN_DIRS` 里也没有 `api`/`front`。
  第一版要把 `.vue` / `.ts` 加进后缀表，把 `api` / `front` 加进扫描目录。
- `front/` 侧再加一条 vitest 扫 `src/`。

### 10.3 缝的守卫

- 一条测试断言 `front/` 的源码里**没有** import 到任何后端模块。
- 一条测试断言 `api/` 是唯一 import `video/pipeline/pyv/` 的新模块。
- 一条测试断言 `api/` **没有** import `publish/publishkit/`（D12）。

> **注意归属**：这两条断言「`front/` 没 import 后端」是关于 `front/` 的，
> 放在 **`front/` 的 vitest 里**；断言「`api/` 是唯一 import pyv 的」是关于 `api/` 的，
> 放在 **`api/` 的 pytest 里**。让一个模块的验收替另一个模块说话，
> 与「验收按模块拆开」有张力。

### 10.4 端到端手测（第一版的验收场景）

仓库现在**没有真稿子**（`drafts/` 只有 `distributed/foundations/` 一篇，
`video/episodes/` 是空的），所以手测需要夹具（放 `api/tests/fixtures/`，
**不进 `docs/`、不进 `drafts/`**）：

1. 在 `drafts/` 建一篇空白文档草稿 → 平台里看到它 → 编辑 → 保存 → 文件确实变了。
2. 视频流：在 `drafts/_video/<分类>/<合集>/<文档>/<档位>/` 建草稿
   → 编辑口播稿 → 保存 → 契约校验过。
3. 文档流的审校面板出信号（夹具文档要故意写出一处 AI 味）。
4. 点「出片」→ 平台先 promote 再跑 make → 日志滚动 → 成片出现在预览区。
5. 「过审」把草稿复制进 `docs/` / `video/episodes/`，且**草稿仍在**；
   界面提示还差哪三步手工。

## 十一、这套东西与仓库其余部分的关系

| 仓库概念 | 创作平台里的对应 |
| --- | --- |
| `drafts/` 草稿箱 | 平台的**唯一写点** |
| `review/` 审校判据 | 平台的**审校面板**的数据来源 |
| `docs/` `video/episodes/` 母稿层 | 平台**只读**；写入只发生在「过审」那一刻，且**只复制** |
| `content/units/` 编译产物 | 平台不直接碰，由 `tools/build-*.py` 生成 |
| `platforms/*/outbox/` 出包快照 | 平台的**出包状态表**的数据来源 |
| `platforms/blog/site/` 站点 | 平台**借用**它的 dev server 做文档预览，不改它（除了补 `hexo-server` 依赖） |
| `video/pipeline/pyv/` 渲染引擎 | 平台**调用**它，不改它 |

一句话：**创作平台是这套流水线的观察窗加编辑器，不是流水线的替代品。**
所有真相仍然在 CLI 和文件里；平台只是让它们能被看见、被编辑、被串起来。
