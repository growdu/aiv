# 标题与章节顺序

> **这是什么**：一条**内容**判据——文章内部的小节标题该怎么起、该怎么排。
> 它回答一个问题：读者**只扫标题**的时候，能不能判断出这一篇讲了什么、
> 这一节在哪、值不值得读下去。
>
> **给谁读**：审稿的人、写稿的人（AI 与作者）。
>
> **判据是文档，不是测试**：`tools/review-check.py` 的 `HEAD-01`～`HEAD-06`
> 只是把其中**可计算**的部分固定下来。标题讲得好不好，仍然要人读。

---

## 一、为什么管标题

标题是读者唯一的导航。多数读者读长文的路径是：先扫目录 → 挑几节读 →
读不下去就退回去看目录找别的。标题承担三件事：

1. **说清这一节讲什么**（读者据此决定读不读）；
2. **把这一节放在正确的位置**（读者据此建立整体印象）；
3. **兑现承诺**（标题里有的，正文里得有）。

三件事都靠标题，所以标题的问题不是「小事」：
标题虚了，读者读的是一篇跟自己预期不同的文章。

## 二、四条判据

### 一、层级要断得住

- **一篇一个 H1**（文章标题），且它在最前面。正文里再出现 H1 是层级断了。
- H2 是**并列的大块**，H3 是 H2 下面的小块。**不跳级**（H2 直接到 H4）。
- 一个 H2 下面只有 H3，没有正文——那是把内容塞进了一级标题里，H2 得降级。

### 二、顺序跟读者的疑问顺序一致

读者的疑问是有先后的：

```
问题/背景 → 原理/机制 → 实现/实践 → 验证 → 扩展 → 总结与产物
```

- **收束类标题**（「总结」「小结」「结语」「回顾」）只能出现在最后。
  它后面还有章节，说明顺序乱了——读者会以为文章已经讲完了。
- 阶段之间不要倒着来：先「实践」后「原理」，等于让读者先照着做一遍，
  再回头解释为什么这么做。
- 「本文解决什么」这类开篇定位放在最前面（见
  [`2026-11-13-content-review-design.md`](2026-11-13-content-review-design.md)）。

### 三、标题要概括这一节

判据一句话：**读完这一节，标题能不能一句话说出它讲了什么？**

机械上查得到的一半：**标题里出现的术语，这一节正文里得出现**。
标题写「宕机」、正文写「服务器挂了」，就是两套词——读者要自己对齐，
而且对齐不保证对。

另一半靠人：**标题说的那件事，正文是不是真的在讲？**
（标题说「三个后果」，正文讲了四段不相干的，那也是标题没概括好。）

### 四、标题要精简紧凑

- **不超过 24 字**。目录是拿来扫的，一行扫不完就等于没有目录。
- **不并列太多样**。一个标题里塞四五样东西，读者记不住哪样是重点。
- **不用营销词**：「干货」「揭秘」「一文读懂」「保姆级」「史上最全」「终极」——
  这些词把标题的位置抢了，正文的位置就没了。
- **少用懒词**：「深入」「详解」「初探」「浅谈」「全面」——
  它们本身不算错（`深入 WAL：一次提交落盘了什么` 是好的），
  但**标题得另有「讲什么」的那一半**。光一个「深入 XX」等于没标题。
- **不标题党**：标题承诺的，正文得兑现；正文里的关键结论，标题别替它先说破。

## 三、好坏对照

| 标题 | 判 | 为什么 |
| --- | --- | --- |
| `MVCC 与 WAL：两份元数据` | 好 | 说清两样东西与它们的关系 |
| `存储与内存：页、缓冲池与异步 I/O` | 好 | 点得出具体对象 |
| `一条 SQL 的完整轨迹` | 好 | 一个具体问题 |
| `深入 WAL` | 要改 | 「深入」不是内容——补上另一半：`深入 WAL：一次提交落盘了什么` |
| `一文读懂 PostgreSQL 内核` | 要改 | 营销词 + 没说是哪几个面 |
| `总结` | 要改 | 「总结」不带内容；改成 `一份可以带走的清单` |
| `原理与实践` | 要改 | 两个抽象词拼的对仗名（见《术语纪律与反造词》） |
| `PostgreSQL 内核机制分析` | 要改 | 「机制分析」没有信息量；写清是哪个机制 |

## 四、机械检查

`tools/review-check.py` 的六条信号：

| 信号 | 级别 | 查什么 | 阈值/词表 |
| --- | --- | --- | --- |
| `HEAD-01` | warn | 多个 H1、H1 不在最前、层级跳级 | —— |
| `HEAD-02` | warn | 标题太长 | `HEADING_MAX_CHARS = 24` |
| `HEAD-03` | warn / info | 标题带营销词 / 懒词 | `rules/terminology.json` 的 `title_words` / `title_words_soft` |
| `HEAD-04` | warn | 收束标题在中间、阶段词次序颠倒 | `STAGE_GROUPS` |
| `HEAD-05` | warn | 空节（标题下面没有内容） | —— |
| `HEAD-06` | info | 标题里的术语在这一节没出现 | —— |

适用范围：**对外内容**（`docs/`、`drafts/`）。
`README.md` 是模块说明与流程文档，不是稿子——「## 七、这个目录现在是空的」
这样的空节是刻意的，标题规则不管它。

**信号不是门禁**：命中不等于标题写错了。`HEAD-06` 这类信号只说「值得看一眼」——
标题用了一个词、正文没跟着用，有时是刻意的修辞（标题点题，正文展开）。

## 五、与其它判据的关系

- 《术语纪律与反造词》管**词**（正文与标题共用一份词表）；
  本文管**标题的结构**。两份判据合起来才是「标题这行字怎么写」。
- 「可读性」四条人工要求里的「布局合理」说的是**节的顺序**，
  本文是它在标题这一层的具体化。
- 判据服从稿件：**先改标题**（改成说清内容的样子），不改判据。
