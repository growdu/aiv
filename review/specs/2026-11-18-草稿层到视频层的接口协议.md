# 草稿层到视频层的接口协议

> 这份文档定义 `drafts/` 与 `video/` 之间**唯一的接口**：一篇文章怎么变成视频、
> 这条视频反过来怎么指回那篇文章、每条信息由谁承载。
>
> **接口优先采用目录层级，然后用规则文件。** 与
> 《[草稿层与母稿层的接口协议](2026-11-18-草稿层与母稿层的接口协议.md)》同一条原则：
> 每一条接口信息，先问「目录层级能不能表达」；能，就让层级表达，
> 不另造规则。只有层级表达不了的，才落到 front matter 或独立规则文件里。§四 是总表。
>
> 上位文档：《[顶层设计与目录调整](2026-11-18-顶层设计与目录调整.md)》的 D11、
> 《[草稿层与母稿层的接口协议](2026-11-18-草稿层与母稿层的接口协议.md)》。
> 本文不重复它们，只在一处需要修订的地方明确写出来（见 §五）。
>
> **本层只管「一篇母稿 ↔ 一组视频」。** 视频线自己的规范文档
> （人格、形象与音色、背景音乐……）的改动稿走 `drafts/`（目录即接口，按需新建） →
> 过审 → 覆盖 `video/` 那一份，那是《草稿层与母稿层的接口协议》已经定好的
> 「改动稿先落 `drafts/`」模式（D11、顶层设计 §4.6），本文不重复。

## 一、这份协议不解决什么

- 不定义视频线怎么出片（渲染、混音、旁白合成、平台适配）——那是 `video/pipeline/` 自己的事。
- 不定义一期视频的口播稿怎么写、画面怎么设计——那是三份规范的事。
- 不定义《选题库》里选题好不好——那是创作。
- 不定义视频平台怎么发（抖音、视频号、B 站）——那是平台层的事。
- 不改仓库根的 `tests/`。视频线的守卫在 `video/pipeline/tests/` 里（§九）。

一句话：**这一层只管「文章与视频之间那条缝」。**

## 二、两条流，两个箱子

顶层设计里是两条流：

```
文档流  drafts ──▶ review ──▶ docs   ──▶ 文档类平台
视频流  drafts ──▶ review ──▶ video  ──▶ 视频类平台
```

两条流的**入口同一个**，出口不同。视频线的输入是**一篇文章**，
输出是**一组视频**（一期 = 一个档位目录，见 §三）——中间那层转换，就是本文要定的东西。

视频线读文章有两条路，都从 `drafts/` 出发：

| 读什么 | 从哪读 | 为什么不是直接读 `docs/` |
| --- | --- | --- |
| **素材**（源码分析、设计文档、结论与数字） | `drafts/` | 素材是**素材**，不是审校对象；整树 `rsync` 同步（顶层设计 §4.6） |
| **母稿**（要讲的那篇文章本身） | `drafts/` 里与 `docs/` 同形的那一份 | 改动稿在 `drafts/`（D11） |

> **为什么是副本而不是共享一个目录**：视频线是另一个模块，它不认 `docs/`。
> 两个模块读写同一个目录，等于允许它们同时写同一个文件——
> 那正是顶层设计要拆掉的耦合。所以**读的部分复制一份，写的部分各写各的**。

## 三、一期是什么：一个档位目录

**一期 = `video/episodes/<系列>/<合集>/<文档>/<档位>/` 一个目录。**
档位是坐标的第四层，一篇文档出三档，三档是**三期**，各有自己的口播稿、
契约与旁白。

```
video/episodes/postgresql/getting-started/postgresql基操/
    skeleton.yaml       讲稿骨架：这一篇母稿拆出来的段与 role（三档共用）
    short/              一期：精简版
        口播稿.md        母稿：口播句子 + 字幕表
        contract.json    视觉分镜契约：哪几句配哪张图、图上写什么
        publish.json     发布元数据：各平台的标题、简介、话题与分区
        narration.mp3    旁白（出片必需的输入）
        storyboard.json  时间轴（产物）
        review.md        这一期的审校记录
        frames.md        抽帧清单
        frames/          抽出来的帧（产物）
    mid/                一期：进阶版（文件清单同上）
    full/               一期：完整版（文件清单同上）
```

**文件清单没变，变的是路径。** 骨架不在档位目录里，在**文档目录**里——
它记的是「这篇文档讲什么」，那是三档共享的东西（§五）。

**流水线里没有期号登记表。** 一期在磁盘上是什么，路径说了算；
加一期不用改代码。以前有一张 Python 侧的登记表，Makefile 里还有一份 shell 侧的副本，
两份靠一个测试盯着别漂移——现在没有登记表可漂了。

**认期认的是坐标，不是文件名。** `video/pipeline/pyv/episodes.py` 里两件事是定死的：

| 常量 | 值 | 意思 |
| --- | --- | --- |
| `TIERS` | `("short", "mid", "full")` | 档位名。档位目录只认这三个名字 |
| `DEPTH` | `4` | 坐标的层数：系列 / 合集 / 文档 / 档位 |

所以 `known_eps()` 的判据是「**相对期根四层、末段是档位名的目录**」，
`known_docs()` 的判据是「**三层、下面挂着档位目录的目录**」。
目录名改一个字的目录不是期——它坐标不对。

目录即接口的后果：**期路径就是这一期的身份**。
期路径压平后（斜杠换连字符）是一个文件名片段，`out/` 与 `build/` 用它：

```
postgresql/getting-started/postgresql基操/short
→ postgresql-getting-started-postgresql基操-short.mp4
```

压平的理由很实际：`out/` 下面会长出一层一层的目录，翻起来费劲，
而系列/合集/文档/档位的信息已经全在压平后的名字里了。

## 四、接口总表：每条信息由谁承载

载体分三档，**从前往后用**（与《草稿层与母稿层的接口协议》§二 同一套分档）：

| 档 | 载体 | 什么时候用 |
| --- | --- | --- |
| 一 | **目录层级**（路径） | 层级能表达的全部 |
| 二 | **front matter** | 层级表达不了的少量元数据 |
| 三 | **独立规则文件** | 层级与 front matter 都表达不了的 |

### 总表

| 接口信息 | 载体 | 层级够吗 | 说明 |
| --- | --- | --- | --- |
| 一期视频是哪一期 | **期路径**（期目录相对期根的路径） | ✓ | `video/episodes/<系列>/<合集>/<文档>/<档位>/` |
| 这一期属于哪个系列 / 合集 | 期路径的前两段 | ✓ | §六 |
| 这一期是哪一档 | 期路径的末段（档位目录名） | ✓ | `short` / `mid` / `full` |
| 一篇文章是哪一篇 | 相对路径 | ✓ | `drafts/X` ≡ `docs/X` |
| 这一期讲的是哪一篇文章 | 母稿 front matter `episode` | ✗ | 二档。值 = **文档路径**（三段） |
| 这一期的档位 | 口播稿 front matter `tier` | ✗ | 二档。值 = `short`/`mid`/`full`，与目录名一致 |
| 这一期的期号 | 口播稿 front matter `episode_number` | ✗ | 二档。值 = 期号（`ep01`） |
| 这一期在库里是哪一期 | 《选题库》一节的 `id` | ✗ | 二档（规则文件里）。值 = 期号 |
| 这一期的画面文案与数字 | `contract.json` 的 `params` | ✗ | 二档（机器可读的事实） |
| 这一期的发布元数据 | `publish.json` | ✗ | 二档 |
| 这一期的审校结论 | `review.md` | ✗ | 二档 |
| 这一期的选题（为什么做、口播骨架、数字出处） | 《选题库》一节 | ✗ | **三档。规则文件里唯一的一条** |
| 这一期的坐标 | —— | ✓ | 期路径本身，见 §六 |
| 独立规则文件 | —— | —— | **只有《选题库》一份**，见 §八 |

两条最关键的：

1. **母稿 → 期**：一个字段，一个 hop。
   母稿 front matter 的 `episode: postgresql/getting-started/postgresql基操`
   → `video/episodes/postgresql/getting-started/postgresql基操/short`。
   中间不查表、不扫库——档位是档位目录自己的末段。
2. **期 → 母稿**：期路径去掉末段就是文档路径，文档路径就是母稿的坐标。
   《选题库》那一节的「关联文档」指向母稿的仓库路径，是另一条路（给人读的）。

## 五、三个名字：文档路径 / 档位 / 期号

这是本协议最容易搞混的一处，所以单开一节。**三个名字，各管一件事。**

| | **文档路径** | **档位** | **期号** |
| --- | --- | --- | --- |
| 是什么 | 身份：哪篇文档 | 三档里的哪一档 | 顺序：第几期 |
| 例子 | `postgresql/getting-started/postgresql基操` | `short` | `ep01` |
| 落在哪 | 口播稿与母稿的 front matter `episode`；也是期路径的前三段 | 口播稿 front matter `tier`；也是期路径的末段（目录名） | 口播稿 front matter `episode_number`；《选题库》一节的 `id` |
| 改了会怎样 | 身份变了，期目录要搬 | 这一期变成另一期（目录改名） | 插期会让后面的号往后挪 |
| 谁在用 | 定位文档目录、拼期路径 | 选哪一条片子、守卫比对 | 《选题库》的排序、审校记录上的标签 |

**裁决：母稿记文档路径，不记档位，也不记期号。**

- 母稿要回答的问题是「**这是哪一篇文档**」→ 答案是一个身份 → 文档路径。
- 口播稿要回答的问题是「**这是哪一档、第几期**」→ 档位与期号。
- 母稿不记期号，因为期号会变（插一期，后面全部往后挪），
  而母稿是长期存在的东西。**身份稳定，顺序可变。**
- 母稿也不记档位：一篇文档出三档，母稿指的是**这一篇**，
  不是「它的 short 档」。母稿记下哪一档，那三档就绑死了。

### 这一条修订了上一份协议

《草稿层与母稿层的接口协议》§二 总表里有一行：

> | 期号 | 稿子 front matter `episode*` | ✗ | 二档。视频线的锚点 |

那一行的**取值格式**，它自己的「没解决的」一节写着「留给视频线」。
现在定下来：**视频线里，`episode` 的取值是文档路径（身份），期号另立
`episode_number`，档位另立 `tier`。** 于是同一个键 `episode` 在全库只有一个意思——
「这一期的身份标识」：

| 文件 | `episode` | `tier` | `episode_number` |
| --- | --- | --- | --- |
| 母稿（`drafts/` 与 `docs/` 各一份） | 文档路径 —— 这一篇对应哪篇文档（哪三期） | —— | —— |
| 口播稿（档位目录里） | 文档路径 —— 这一期属于哪篇文档 | 档位 —— 这一期是哪一档 | 期号 —— 第几期 |

上一份协议的 G-07「`episode:` 一致」照旧成立：
`drafts/` 与 `docs/` 的同一篇稿子带同一个 `episode:` 值。

## 六、坐标：期住在母稿的坐标上

一期住在**母稿的坐标上**——同一个系列、同一个合集：

```
docs/source-tracks/postgresql/getting-started/postgresql基操.md   ← 母稿
video/episodes/postgresql/getting-started/postgresql基操/short    ← 那一期
```

规则很简单：**母稿在赛道目录之下的那几段，原样搬到 `video/episodes/` 下，
再加一段档位。**

| 层 | 段 | 例 |
| --- | --- | --- |
| 一级 | 系列 | `postgresql` |
| 二级 | 合集 | `getting-started` |
| 三级 | 文档（一篇母稿） | `postgresql基操` |
| 四级 | 档位 | `short` / `mid` / `full` |

注意 `docs/source-tracks/` 这一层**不进**期坐标：它是文档侧的赛道目录，
视频线的坐标从赛道之下数——一层系列、一层合集、一层文档、一层档位。

**档位在路径里，所以命令行没有档位变量。**
命令是 `make EP=<期路径> align|all|nobrand|vertical|review-text|review-video|review-frames|persona`，
**没有 `TIER=`**。档位是坐标的一段，不是外挂的开关——把它做成变量，
就等于允许「期目录是 short、命令跑的是 full」这种组合存在。

> **搬完了。** 期坐标已经是四层，`known_eps()` 按坐标扫
> （四层、末段是档位名），`known_docs()` 按文档扫（三层、下挂档位目录）。
> 骨架在文档目录（`skeleton_path(doc)`），产物名用压平期路径。

## 七、流程：每一步靠什么承载

从「有一篇文章」到「有视频」，六步：

| 步 | 做什么 | 落在哪 | 过审吗 |
| --- | --- | --- | --- |
| 1 | **选题**：定题目、主钩子、主线、能力域、关联文档、口播骨架、数字出处 | 《选题库》一节 | 过 |
| 2 | **建目录**：建**文档目录 + 三个档位目录** | `video/episodes/<系列>/<合集>/<文档>/{short,mid,full}/` | — |
| 3 | **给母稿打锚**：母稿 front matter 加 `episode: <文档路径>` | 母稿的 `drafts/` 那一份 | 过 |
| 4 | **写骨架**：母稿拆成段，每段标 `role` | 文档目录的 `skeleton.yaml` | 过 |
| 5 | **写口播稿与契约**：口播句子 + 字幕表；哪几句配哪张图、图上写什么 | 各档位目录的 `口播稿.md` / `contract.json` | 过 |
| 6 | **出片 → 审校** | 产物不入库；`review.md` / `frames.md` 入库 | 过 |

**第 3 步是给已发布的母稿补一个字段，走的是「修改」路径**（D11）：
改动稿先落 `drafts/` 那一份，过审后才覆盖 `docs/` 那一份。
不是直接改 `docs/`——那样等于绕过审校。

**第 1 步在第 2 步之前**，因为文档路径是选题时定的：
文档路径一旦进了期目录与母稿，就不该改。选题阶段定坐标，
是为了让「这一期叫什么」从一开始就定死。

### 反向：从一期回到母稿

```
video/episodes/postgresql/getting-started/postgresql基操/short/口播稿.md
    ↓ front matter episode（文档路径）
docs/source-tracks/postgresql/getting-started/postgresql基操.md
```

一级跳，单跳。**中间没有登记表。**

## 八、规则文件层：《选题库》

这一层**唯一需要的独立规则文件是《选题库》**，理由只有一条：
**选题是一个跨期的事实**——主线、能力域、这一季讲什么，
这些东西不属于任何单期，单独放一个文件才对。

《选题库》（`video/选题库.md`）里每一期一条，含：

| 段 | 内容 | 谁定 |
| --- | --- | --- |
| 字段表 | `id`（期号）、标题、主钩子、主线、能力域、状态、适配理由 | 这一期 |
| 关联文档 | 从哪几篇取素材，各取什么 | 这一期 |
| 口播骨架 | 十句，先定下来再写稿 | 这一期 |
| 数字与出处 | 每条陈述的出处与口径 | 这一期 |

**它同时是规则文件**：§「每期都要满足的硬指标」与「机检规则」两节
说的是**所有期**的要求，不是某一期的。机器判据在 `pipeline/pyv/topics.py`，
编号与规则表一一对应。

> **《选题库》现在是空的。** 视频线清空重来，六期全部作废。
> 空库是合法状态——「不预先囤选题」是规矩，不是缺陷。

## 九、守卫：守什么，以及现在守到什么程度

下面这些判据**还没有做成一条编号一条检查器的独立守卫**——
多数已经散落在流水线与测试里，那张表逐条写清现在守到什么程度：

| 编号 | 守什么 | 怎么查 | 现在什么状态 |
| --- | --- | --- | --- |
| V-01 | 母稿的 `episode`（文档路径）指得到一个**真实存在**的期目录（文档目录下有档位目录） | 扫 `video/episodes/` | **有测试守着坐标这一层**（`test_episodes.py`：坐标扫得出来）；母稿→期的指向还没有专门检查 |
| V-02 | 期路径 = 口播稿 front matter 的 `episode`（文档路径）+ `tier`（档位） | 逐期对 | **有测试守着**（`test_episodes.py`：三个名字各读各的） |
| V-03 | 口播稿的 `episode_number` = 《选题库》里那一节的 `id` | 逐期对 | **有测试守着期号怎么读**（`test_episodes.py`）；与选题库 `id` 的对齐还没有 |
| V-04 | 《选题库》一节的「关联文档」路径**真实存在** | `topics.doc-exists` | **已有** |
| V-05 | 契约的句子**恰好覆盖**口播稿的句子一次 | `align` 前置 | **已有** |
| V-06 | 期目录里该有的文件齐全（口播稿、契约、发布元数据、审校记录） | 逐期查 | **有测试守着**（`test_review.py`：每期都有审校记录） |
| V-07 | 产物没被跟踪（`storyboard.json`、`frames/`） | `.gitignore` + 测试 | **已有** |

**V-01 与 V-03 是这套接口的两条命脉**：一条管「母稿指得到期」，
一条管「期在库里对得上号」。它们都只是**等值比较**，不复杂。

已经落地的部分（`video/pipeline/tests/`）：

| 位置 | 守的是什么 |
| --- | --- |
| `test_episodes.py` | 坐标扫得出来（四层、末段是档位名）、三个名字读得到（`episode` / `tier` / `episode_number`）、骨架在文档目录、压平名怎么算 |
| `test_review.py` | 每个期目录都有审校记录、进度表与磁盘上的期一一对应 |
| `test_makefile.py` | 没给 `EP=` 当场报错退出、`EP=` 指的目录不存在也报错、路径不错串 |
| `test_assets_are_tracked.py` | 产物（时间轴、抽出来的帧）不入库 |

**根目录 `tests/` 不动。** 视频线的守卫住在视频线自己的目录里——
它守的是视频线的坐标，不该拖上全站的测试一起跑。

## 十、以《postgresql 基操》走一遍

样例是 `docs/source-tracks/postgresql/getting-started/postgresql基操.md`
（《PostgreSQL 基本操作与基本对象》，2026-11-18 过审进 `docs/`）。

### 样例的坐标

| | 值 |
| --- | --- |
| 系列 / 合集 | `postgresql` / `getting-started` |
| 母稿 | `docs/source-tracks/postgresql/getting-started/postgresql基操.md` |
| 文档路径 | `postgresql/getting-started/postgresql基操` |
| 素材副本 | `drafts/`（草稿箱清空后按需新建，与母稿同相对路径） |

### 步 1 · 选题

作者决定：这一篇值得做视频。题目《客户端连上 PostgreSQL 需要哪几样东西》——
钩子硬（「连接要哪几样东西」），素材现成（四层对象都能自己查出来），
画面好画（一条时间线 + 四层结构）。

《选题库》加一节：

```markdown
## EP01 · 客户端连上 PostgreSQL 需要哪几样东西

| 字段 | 值 |
| --- | --- |
| id | ep01 |
| 标题 | 客户端连上 PostgreSQL 需要哪几样东西 |
| 主钩子 | 连上库、取到一条数据，需要哪几样东西？ |
| 主线 | 机制族 |
| 能力域 | PostgreSQL 内核机制 |
| 状态 | 选题中 |
| 适配理由 | 四层对象（库 → 表 → oid → 文件）都能自己查出来，画面只需要一张时间线加四层结构。 |

**关联文档**

| 文档 | 取什么 |
| --- | --- |
| `docs/source-tracks/postgresql/getting-started/postgresql基操.md` | 四层对象的串联关系与可复现的查询命令 |

**口播骨架**

（十句，先写下来再写稿）

**数字与出处**

（每条陈述指向母稿里的哪一节，标注是「上游公开机制」还是「作者本人实测」）
```

### 步 2 · 建目录

**建一个文档目录 + 三个档位目录**——三档是一篇文档的三个深度，
先建好，坐标就定死了。

```bash
mkdir -p video/episodes/postgresql/getting-started/postgresql基操/{short,mid,full}
```

### 步 3 · 给母稿打锚

在 `drafts/` 那一份（与母稿同相对路径，目录按需新建）
的 front matter 里加一行：

```yaml
---
description: "客户端连上 PostgreSQL 需要哪几样东西，服务端把「库 → 表 → oid → 文件」这四层怎么串起来，以及怎么自己查出来。"
episode: postgresql/getting-started/postgresql基操
---
```

过审后覆盖 `docs/` 那一份。**这一步走的是「修改」路径**——
改动稿先落 `drafts/`，不是直接改 `docs/`。

母稿与期从此互相认得：

```
母稿 front matter episode: postgresql/getting-started/postgresql基操
    → video/episodes/postgresql/getting-started/postgresql基操/short
```

一个字段，一个 hop，不查表。

### 步 4 · 写骨架

母稿拆成段，每段标一个 `role`（`hook` / `mechanism` / `evidence` /
`conclusion` / `aside`），三档共用一份：

```
video/episodes/postgresql/getting-started/postgresql基操/skeleton.yaml
```

骨架记的是「这篇文档讲什么」——三档是同一篇文档的三个深度，
拆一次就够，不必拆三遍。形状见
《[长视频三档](../../publish/spec/09-长视频三档.md)》§5.1。

### 步 5 · 写口播稿与契约

`video/episodes/postgresql/getting-started/postgresql基操/short/口播稿.md`：

```yaml
---
title: "客户端连上 PostgreSQL 需要哪几样东西"
episode: postgresql/getting-started/postgresql基操
tier: short
episode_number: ep01
---
```

正文两节：**口播稿**（十句，每行一句）与**字幕文本**（表格，与句子一一对应）。
`episode` 是文档路径、`tier` 是档位，**两者合起来就是期路径**（V-02）；
`episode_number` 是期号（V-03）。

`.../short/contract.json`：哪几句配哪张图、图上写什么。
**文案与数字写在契约里，不写在场景代码里**；契约里的句子必须**恰好覆盖**口播稿的句子一次。

`mid/` 与 `full/` 各自一份口播稿与契约——三档不是同一份稿子的缩写，
是同一篇文档的三个深度。

### 步 6 · 出片与审校

```bash
cd video/pipeline
make EP=postgresql/getting-started/postgresql基操/short align     # 按旁白对齐出时间轴
make EP=postgresql/getting-started/postgresql基操/short all       # validate → brand → render → compose
make EP=postgresql/getting-started/postgresql基操/short review-text   # 文本层
make EP=postgresql/getting-started/postgresql基操/short review-video  # 成片层
make EP=postgresql/getting-started/postgresql基操/short review-frames # 抽帧 + 清单
make EP=postgresql/getting-started/postgresql基操/short persona      # 按《人格规范》查口播稿
```

产物按压平期路径落名：

```
video/out/postgresql-getting-started-postgresql基操-short.mp4
video/build/postgresql-getting-started-postgresql基操-short/
```

产物（时间轴、片段、成片、抽出来的帧）不入库；
入库的是骨架、契约、旁白、发布元数据、审校记录与抽帧清单。

**素材从配置来。** 立绘、曲库、品牌片这些不在仓库里，在 `video/config.toml`：
相对路径按**配置文件所在目录**解析，环境变量 `VIDEO_CONFIG` 可以指到别处，
脚本问配置要值用 `python3 -m pyv.cli config <key>`。
**没配 = 没配**（流水线降级，不报错）；**配了但文件不在才是错**（`make doctor` 报出来）。

接口是长期的，某一期是消耗品。

## 附：本文的裁决一览

以下是本文里**我做的判断**，不是既有共识，都可以推翻：

| 裁决 | 依据 |
| --- | --- |
| 一期 = 一个档位目录，没有登记表 | 目录就是接口；以前两份登记表靠一个测试盯着别漂移，现在没有可漂的东西 |
| 坐标四层：系列 / 合集 / 文档 / 档位 | 档位是坐标的一段，不是外挂的开关——档位做成变量就允许「目录是 short、跑的是 full」 |
| 文档路径是身份、档位是深度、期号是顺序，三者分开 | 身份稳定，顺序与深度可变；母稿长期存在，不该被期号与档位绑死 |
| 母稿记文档路径，不记档位不记期号 | 一篇文档出三档，母稿指的是「这一篇」，不是「它的某一档」 |
| `episode` 在全库只有一个意思（身份标识） | 同一把钥匙找一个东西；上一份协议把取值格式明确留给了视频线。身份标识现在就是文档路径 |
| 骨架在文档目录、三档共用 | 骨架记的是「这篇文档讲什么」，那是共享的东西；档位目录里放骨架就等于把它拆三遍 |
| 期住在母稿的坐标上，`docs/source-tracks/` 不进期坐标 | 赛道目录是文档侧的分法，视频线的坐标从赛道之下数 |
| 期路径压平后当文件名用 | `out/` 下面会长出一层层的目录；层级信息已经在压平后的名字里 |
| 《选题库》是这一层唯一的独立规则文件 | 选题是跨期事实，不属于任何单期 |
| 空选题库是合法状态 | 「不预先囤选题」是规矩 |
| 这一层只有「一篇母稿 ↔ 一组视频」一条缝 | 视频线自己的规范走的是《草稿层与母稿层的接口协议》已定的模式，不必重写一遍 |
