## 一、要做什么（一句话）

**把 `/work/ai/blog-bak` 里那套已经优化过的 Hexo + matery 站点整体搬进 `platforms/blog/site/`，
替换掉现在的 Astro 实现；搬过来的东西里不写死任何站点身份，内容一篇都不带。**

来源是 blog-bak 那条线上的三次「站点做减法」：去掉左右侧栏、首页做成正好一屏、
分类与标签整套退休、播客系列页退休。那套实现的效果是作者认可的，**它就是目标形态**。

## 二、为什么不是继续修 Astro

Astro 那版是 2026-11-18 从零重做的，做的是「学习流门面」。它做完了自己的事，
但作者在 blog-bak 那条线上把 hexo 站点打磨到了想要的样子，于是选择：**要那个，不要这个**。

代价是白做一版站点实现。这一版比 Astro 版多出来的东西（目录树侧栏、文章大纲、
视频页、时间轴、活动账本）**不搬**——它们是 Astro 版为了「学习流门面」加的，
不是 blog-bak 那套的效果的一部分。

**这不是「换个主题」，是换掉站点的整个实现。** 主题树、模板、构建链、守卫全部重写。

## 三、目标 / 非目标 / 反目标

### 目标

1. **站点长得跟 blog-bak 那套一样**：首页正好一屏（统计条 + 学习路径面板），
   文章页有 TL;DR、代码高亮、mermaid、悬浮目录；归档页按时间翻；学习路径有总览页与赛道页。
2. **通用**：框架源码里没有一个实例名、没有一个实例地址、一个人设。
   名字、简介、导航、页脚、起始日期都在 `platforms/blog/site/data/site.json`。
3. **内容只从 `docs/` 来**：仓库的 `docs/` 是唯一真相；站点渲染的是它编译出来的内容单元。
   搬进来的框架**不带任何文章**。
4. **验收按模块拆开**：站点模块一条命令跑在自己的目录里。

### 非目标

- 不做视频页、不做时间轴、不做活动账本、不做目录树侧栏、不做文章大纲侧栏（作者拍板）。
- 不做部署。CI 只构建 + 传产物（和现在的 `site.yml` 一样）。部署是另一轮的事。
- 不做 GitHub Pages 双挂载（`/blog/` 前缀那套）——现在没有镜像站，不需要。
- 不碰 `review/plans/2026-11-19-接口欠账实施.md` 的那 16 条欠账（那是发布层与契约层的事）。

### 反目标（做出来算失败）

- **框架里漏写死一个实例名**。改配置没改全，页脚还挂着旧站名——这类漏最难发现，
  因为它编译得过去、测试也过得去。必须有一条机器守着的守卫。
- **为了「看起来一样」把 blog-bak 的产品特性一起搬过来**（播客期号块、发布去向光谱、
  打赏、推荐页、Gitalk、计数器、ICP 备案、人设简历）。它们是内容/人设，不是框架。
- **用正则改写正文里的链接**。旧 hexo 时代那个正则重写器会把正文里的方括号吃成巨型链接，
  这是仓库已经记过教训的（见 `platforms/blog/site/README.md` §四）。
  新的重写走 **AST**（remark），不扫文本。
- **把 Astro 版的模块偷偷加回来**。翻版就是翻版。

## 五、身份缝：唯一一份 `data/site.json`

`platforms/blog/site/data/site.json` 是**全仓库唯一的站点身份源**（发布层、公众号署名、
视频作者都从它取——这条已经在仓库里成立，不改）。

形状（沿用现有的骨架，删掉 Astro 独有的部分）：

```jsonc
{
  "name": "站名",              // 站名
  "tagline": "一句短话",       // 导航栏里紧跟站名的那句（blog-bak 的 home_hero_lead）
  "description": "长描述",     // SEO description + 关于页/子页封面用
  "start_date": "2019-06-28", // 站龄（统计条第三张卡）；没有就不出这张卡
  "nav": [ {"key": "...", "href": "/...", "label": "...", "feature": "learning_path"} ],
  "search": { "href": "/archives/", "label": "全库检索" },
  "footer": { "note": "..." }
}
```

- **`home` 块删掉**：Astro 首页有个 hero（标题 + 两句话 + 按钮），blog-bak 那套没有——
  它把首屏让给了统计条和学习路径。留着就是死配置。
- **地址来自环境变量**：站点地址不写死在 JSON 里。构建时取 `SITE_URL`
  （CI 里给，缺省 `http://localhost:4000`），跟 Astro 版一致。
- **注入方式**：`_config.template.yml`（入库，结构）+ `data/site.json`（身份）
  → `tools/apply-site-config.py` → `_config.yml`（生成，不入库）。
  模板读身份有两个通道：`config.*`（hexo 核心要 `title`/`url`/`description`）
  与 `site.data.site.*`（导航、页脚、站名、tagline）。**身份只有一份来源，两条通道都是它的投影。**
- **主题行为**（菜单以外的开关：代码复制、目录悬浮、mermaid 选项、统计信息显示哪些项、
  暗色模式、懒加载、灯箱）在 `_config.matery.yml`，入库、不含身份。

## 六、内容管线

```
docs/ ──根 tools/build-content-units.py──▶ content/units/ ──站点 tools/build-posts.py──▶ source/_posts/
                                                                                        │
                                          tools/apply-site-config.py ──▶ source/_data/site.json
                                          tools/build-learning-path.py ─▶ source/_data/learning.json + source/learning/**
                                                                                        │
                                                                                        ▼
                                                                       hexo generate（主题树）──▶ dist/
```

### 6.1 内容单元 → hexo 文章

`tools/build-posts.py` 读 `content/units/`，给每个 `kind: document` 的单元写一篇
`source/_posts/<id>.md`：

- front matter：`title`、`date`、`author`、`description`、`categories`、`tags`、
  `permalink: /docs/<id>/`、`layout: post`；正文原样带过去。
- `kind: category`（`_index.md`）不写成文章，而写成 `source/docs/<路径>/index.md`
  的**分类页**（`permalink: /docs/<路径>/`），页面上列出该目录下的子文档。
- `kind: video` 的内容单元**不进站点**（站点没有视频页）。它们给发布层用。
- 图片：`docs/` 里的图片复制到 `source/images/`（保持 docs 相对路径）。

**地址形状沿用仓库已批准的那套：`/docs/<id>/`。** 这条是作者拍板的，
发布层与 outbox 也按它拼。hexo 的默认 permalink（`/:year/:month/:day/:title/`）不用，
每篇文章的 `permalink` 由适配脚本写进 front matter。

### 6.2 链接与图片的重写（AST 级）

母稿里的站内链接是相对路径（`./某文档.md`），站上要变成 `/docs/.../`。
这一步在 **hexo 过滤器**里做（`scripts/rewrite-links.js`），用 **remark 解析 AST**：

- 链接节点：相对路径 + `.md` 结尾 → 按「同目录下那个 `.md` 在不在」翻译成 `/docs/<id>/`；
  目标不存在就**原样留下**（于是 404），不去改引用它的那些链接。
- 图片节点：docs 相对路径 → `/images/<docs 相对路径>`。
- **不扫文本**，代码块里的内容一个都不碰。

> 这条是仓库已经吃过亏的地方：旧 hexo 时代的重写是正则，正文里任何不成对的方括号
> （比如区间记号 `[s, s+D)`）都会让它一路吃到后面某个链接的右括号，
> 渲染出一个上千字的巨型蓝色链接。Astro 版用 remark 修好了这个毛病，
> 这一版继续用 remark，**不许退回正则**。

### 6.3 学习流

- 规则表 `data/learning-path.json`（人工策展，8 条赛道 × 阶段）**沿用现有的**，
  编译器 `tools/build-learning-path.py` **沿用现有的**（漏归类即构建失败、可以整个关掉）。
- 扩展它多做两件事：
  1. 每条赛道补上**文章数**（首页面板要显示「214 篇」）；
  2. 渲染学习路径页面：`source/learning/index.md`（总览：赛道地图 + 从哪开始）
     与 `source/learning/<赛道>/index.md`（阶段表 + 阶段下的文章清单）。
- 首页面板与总览页读 `source/_data/learning.json`（`tracks[]`：id / title / icon /
  summary / count / stages[]）。
- **学习流关掉时**（规则表 `enabled: false`）：不映射、不生成页面、
  导航项与首页按钮自动消失——机制照旧。

### 6.4 首页

**跟 blog-bak 一模一样的结构**：

```
┌────────────────────────────────────────────┐
│ 统计条：N 篇文章 ｜ Nw 字 ｜ N 天持续更新    │   ← 第一眼看到的是「这站有多大」
├────────────────────────────────────────────┤
│ 学习路径                                    │
│ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ │
│ │ 赛道卡  │ │ 赛道卡  │ │ 赛道卡  │ │ 赛道卡  │ │
│ └────────┘ └────────┘ └────────┘ └────────┘ │
└────────────────────────────────────────────┘
```

- 统计条的数字全部现算：文章数 = 文章总数；总字数 = 逐篇字数求和；
  站龄 = `site.json` 的 `start_date` 到今天。
- **首页不做入场动画**（blog-bak 那次删掉的：AOS 的 fade-up 会让页面在动画期间
  比视口高出一截，滚动条闪一下）。
- **首页只有一屏**：统计条在最上，学习路径面板铺满视口；
  窄屏（< 993px）换排版。
- 首页**没有** hero、**没有**最新文章列表、**没有**分类标签——blog-bak 那版都已经退休了。

## 七、搬什么 / 不搬什么

### 搬（框架）

- **主题树**：`themes/matery/` 整个目录，**从 blog-bak 的「已打补丁」状态复制**
  （它的 CSS 与模板补丁都已经入库，所以**不带 `patch-theme.py`**——那是 3000 行的
  字符串替换脚本，是这次搬运最大的负债，不进新仓库）。
- **布局**：文章页（TL;DR、目录悬浮、mermaid、代码复制、上下篇）、
  归档页、学习路径页、搜索弹窗、暗色模式、回到顶部、图片懒加载、灯箱、
  404、关于页（改成读 `content/about.md`）。
- **首页**：统计条 + 学习路径面板（重写成读 `site.data.*`）。
- **导航 / 页脚 / 顶栏**：改成读 `site.data.site.*`（站名、tagline、导航、页脚）。

### 不搬（产品特性与人设）

| 不搬的 | 为什么 |
| --- | --- |
| 播客期号块（`episode-block`）、播客索引与 RSS | 视频线的产品，站点这一版没有视频页 |
| 发布去向光谱（`post-publish`）、发布索引 | 依赖 outbox 的产品数据 |
| 推荐页（`recommended`）、3D 轮播 | 内容策展，不是框架 |
| 打赏（reward）、Gitalk 评论 | 第三方账号绑定，通用框架不该预置 |
| GoatCounter / 巴士计数器 | 统计账号绑定 |
| ICP 备案徽章、cn-banner（切换中文站） | 实例身份 |
| 人设：头像、简历、时间线、项目卡、技能条、学历、荣誉 | 人设内容。**关于页改由使用者写 `content/about.md`** |
| 阅读量快照 | 依赖 GoatCounter 账号 |
| 分类页 / 标签页 | blog-bak 那次已经整套退休（页面、菜单、chip 全清），旧地址跳 `/all/` |
| `/database/` `/projects/` 落地页 | 同上，旧地址跳走 |
| `view-counts` / `goatcounter` / `podcast` / `publish_index` 数据表 | 同上 |

## 十四、按实现订正（2026-11-20）

规格写的是**打算怎么做**，实现里有几处落到了别的地方。逐条记下来，
免得下一个读规格的人按 §四/§六 去找文件找不到。

### 14.1 文件挪了位置

| 规格里写的 | 实际在 | 为什么 |
| --- | --- | --- |
| `scripts/rewrite-links.js`（hexo 过滤器） | `tools/rewrite-links.mjs` | 它是**构建期的一次性工具**，不是 hexo 过滤器：改链接要在**写进 `source/_posts/` 之前**做（否则 hexo 的渲染器会把相对地址原样吐出去）。放 `scripts/` 里会被 hexo 当插件加载——插件里没有渲染期该做的事。 |
| `scripts/`（链接重写、mermaid、图片尺寸三个过滤器） | `scripts/` 只有 `mermaid.js` 与 `archives-fallback.js` | mermaid **必须**是过滤器（它要在渲染期把围栏换成 `<div class="mermaid">`）；链接重写与图片尺寸挪去了 `tools/`。 |
| `tools/check-internal-links.py` | —— | 没单独做这条工具。站内死链由 `tests/test_pages.py` 在**产物**上查（`dist/` 里的 href/src），比在源码上查更准：它查的是读者真正会点到的东西。 |
| `source/404.html` | `source/404.md` | hexo 的 404 是**一篇 page**，不是静态文件。写成 `.md` 才能套主题的模板。 |
| `source/all/index.md` | `source/all/index.md`（`layout: false`） | 一致。`layout: false` 让它渲染成一份独立文档（跳转页），不套主题。 |

### 14.2 `site.json` 的形状少了 `search` 块

规格 §五 写的形状里有 `"search": { "href": "/archives/", "label": "全库检索" }`。
**实现里没有这一块**：检索入口跟着归档页走（导航里的「归档」项就是它），
多一个块就多一处能配错的地方。要加的话就是 `nav` 里的一项。

### 14.3 学习流分成了两面

规格 §6.3 说的是「扩展 `tools/build-learning-path.py`」。实现里它编出**两份**：

- **账本** `data/learning-path.compiled.json`——文档**与视频**都在里面。
  发布层与 `platforms/blog/cli.py` 查的是它。
- **站上那一面** `source/_data/learning.json`——**视频被滤掉了**。
  站上没有视频页，赛道里挂着视频单元就等于挂着一堆死链。

两份都由同一个脚本编出来，`count`/`total` 各自算各自的。

### 14.4 视频的处理

规格 §6.1 说「`kind: video` 的内容单元不进站点」。实现补了半句：
**它们仍然在地址表里**（`source/_data/urls.json`）——正文里指向视频的相对链接
要有个地址可换。那个地址归发布层落地，站内不生成页面。

### 14.5 目录页多了一个 layout

`kind: category` 的单元写成 `source/docs/<路径>/index.md`，
`layout: docs-index`（规格里没提这个 layout 名）。它列的是**直接子级**
（路径比它深一段的那些），面包屑用 `<div>`（不是 `<nav>`——Materialize 会把
`<nav>` 压成一条 64px 的红条）。

### 14.6 图片还在 `docs/`

规格 §6.1 说「图片：`docs/` 里的图片复制到 `source/images/`」——实现照做了。
但**根因没解决**（Ruling 14）：图片的**权威**还在 `docs/`，
`content/units/` 里只有 `.md`。两个 adapter 的图片解析基准仍是
「文章目录的上一级」，一换就丢图。这笔账归**编译器抽取**那个模块
（`review/plans/2026-11-19-接口欠账实施.md`）。

### 14.7 `tools/urls.py` 算仓库根的层级

它用 `parents[4]`（`tools/` → `site/` → `blog/` → `platforms/` → 仓库根）。
写少一层就指到 `platforms/` 去了——`rules/urls.json` 不在那儿，
于是规则表永远读不到，**默认规则静悄悄地生效**。这跟
[「红测试别拿 git 版本当万能解释」] 记的是同一类坑：**看起来能跑，其实读的不是那份**。

### 14.8 `tools/sync-content.py` 留着

它是平台层的**已发布接缝**（`platforms/wechat/cli.py` 的 `sync` 命令按这个名字调它）。
实现把它改成一个薄壳，转发给同目录的 `build-posts.py`。
**不删、不改名**——那要连着改下游，不在这一轮里。
