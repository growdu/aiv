# 站点重做：growdu.cn 作为一条学习流

**2026-11-18**。这一篇是 `platforms/blog/` 站点重做的设计文档。

起因：`platforms/blog/site/` 整个目录（321 个文件）已从工作区删除——
hexo 配置、matery 主题、30+ 个构建与闸门脚本、站点数据、`source/`、产物 `public/` 全部不在了。
站点要重做。

**站点的上游接口是 `docs/` 下的目录文档**——只有已过审的内容才在 `docs/` 里，站点只渲染它。
`docs/` 现在只有一篇母稿（未过审的存量已整体撤出，原件留在 `drafts/` 的六条线镜像里等着过审）。
**站点的规模由审校进度决定，不由草稿数量决定**：`drafts/` 不是站点的上游，草稿过审进 `docs/` 之后站点才看得见。
这条边界让站点可以先按「一篇母稿」跑通，再随审校自然长起来。

**这不是一次「换个主题」的改动，是换一套内容组织方式**：
站点的骨架不再是文章时间流，而是**学习流**——赛道 × 阶段的阶梯。

---

## 一、为什么重做

旧站点（hexo + matery）已经跑了很久，它的问题是：

- **首页是文章时间流**。最新 18 篇卡片 + 三个 tab。访客看到的是「一个博客」，不是「一个人」。572 篇存量摆在那儿，体量反而成了劝退。
- **深度没被入口暴露**。真正有分量的是九条赛道（数据库内核、分布式、Linux 与网络、数据面 DPDK·VPP、AI 与工具、工程与语言、人生与成长、博客与自媒体……）和它们的阶段划分，但这套结构只做成了**一个页面**（`/learning/`），其余地方完全看不见。
- **视频是「引用」不是「阵地」**。成片不托管，站点只放旁白 mp3 和跳转链接。
- **工具链与主题绑死**。三十多个 Python 脚本依赖 hexo 的产物形态（`source/_posts/`、`public/`），主题定制靠 `patch-theme.py` 打补丁。

而仓库里已经有的东西，比旧站点值钱：

| 资产 | 位置 | 是什么 |
| --- | --- | --- |
| **人格规范** | `video/人格规范.md` | 一句话人格：「一个把内核讲给你听的老兵：先给地图，再给抓手，最后给边界」；三条主线：造物者 / 方法论者 / 现场验证者 |
| **形象与音色** | `video/形象与音色规范.md`、`video/character/` | 3D 卡通小象主形象（深藏蓝 #2B4C7E + 琥珀黄 #F5A623）、定稿音色 |
| **品牌片** | `video/brand/` | 片头片尾，各 2.833 秒 |
| **选题库** | `video/选题库.md` | 526 行，���季选题 |
| **内容单元层** | `content/units/` | 平台无关的 markdown + front matter，**不依赖 hexo** |
| **学习流规则表** | git 历史 `platforms/blog/site/data/learning-path.json` | 577 行，9 条赛道 × 阶段的**人工策展规则**（含每条赛道的 audience / goal） |

**结论**：站点要变成「一个人的门面」，而这个人（叫 growdu，是小象）已经有完整的形象、人格、内容与生产线。
缺的只是一个把这些串起来的结构。

## 二、目标 / 非目标 / 反目标

### 目标

1. **站点主轴是学习流**：任何人进来，三秒内能看清「这里有哪几条路、每条路走到哪、我该从哪条开始」。
2. **文档与视频同源同位**：视频不是另开一个岛，它就是学习流里的一站；文档页能看到自己在路上的位置。
3. **内容一次编译、多平台共用**：内容单元层继续做接口，站点只是它的一个消费者。**站点的输入只有 `docs/`**。
4. **技术可信度可见**：源码清单、复现命令、口径边界在页面上，不只在仓库里。
5. **自有域名承载全部资产**：成片、音频、文字都住在 `growdu.cn` 下，平台那边只是分发位。

### 非目标

- **不把全量文档搬上首页**。全部上站，但只进检索与分类页，不进推荐流（详见 §五）。
- **不动 `docs/` 的内容真相**。目录即接口的规矩不变，学习流是**视图**，不是新的目录层。
- **不改 `drafts/ → review/ → docs/` 的审核流**。
- **这一轮不追评论系统**。先把学习流跑通，评论放 P2。

### 反目标（做出来算失败）

- **首页变成文章墙**。全量平铺 = 劝退。
- **为了「看起来有体系」而新造一套分类**。赛道必须映射到现有目录，不能另起炉灶。
- **正文占满整屏**。行宽无上限、代码块撑破版心——旧站点的毛病，不能带过来。
- **编译层用正则改正文**。见 §七，这是最容易犯、后果最重的错。

## 三、约束

| 约束 | 说明 |
| --- | --- |
| 域名 | `growdu.cn`，主域名；`growdu.github.io/blog` 作镜像兜底 |
| 服务器 | 自有服务器，CI 用 rsync 部署（现有做法：release 时间戳目录 + 硬链接增量 + 原子切 symlink） |
| 内容真相 | `docs/`（母稿层）；`drafts/` → `review/` → `docs/` 的流程不变 |
| 接口 | `content/units/`（平台无关内容单元）—— 新栈直接消费它 |
| 人格与形象 | 已有规范，站点视觉与文案必须服从，不得另立一套 |
| 验收 | **按模块拆开**：每模块一条「在自己目录里跑」的命令；不搞整站快照、不全套合跑 |
| 技术栈版本 | Astro 当前 7.4.12（npm 实测）。本设计里提到的 API 需在实施时对照官方文档核实 |

## 四、核心模型：两套坐标

```
        真相坐标（目录）                    展示坐标（学习流）
   ┌──────────────────────┐         ┌──────────────────────────┐
   │ docs/source-tracks/  │         │ 赛道（9 条）× 阶段（L1…）  │
   │   postgresql/        │ ──────▶ │                          │
   │     transaction-mvcc/│  策展   │  ← 由规则表算出，不改目录  │
   │       行锁.md        │  规则   │                          │
   │ docs/distributed/    │         │                          │
   └──────────────────────┘         └──────────────────────────┘
        谁是什么、存在哪                   怎么走、先走哪
```

**关键**：目录是仓库，学习流是门面。学习流**不新增目录层**，它由一张**规则表**（`learning-path.json`）把文章映射到「赛道 + 阶段」，规则命中即归属。

规则表从 git 历史恢复（旧版 577 行），**按 `docs/` 目录重写映射**——规则表匹配的是 `docs/` 里的路径（`path_prefix` / `path_exact` 之类），`drafts/` 不参与映射。保留每条赛道的 `summary` / `audience` / `goal`——这三段文案是赛道的门面文字，**不该由代码生成**。

**赛道的集合是固定的（九条），某条赛道当前有没有内容，是随审校进度变化的**。
现在 `docs/` 只有一篇母稿，于是只有「数据库内核 › L1」这一格亮着，其余八条赛道是空的。
这不影响设计成立——**空缺是可见的**（§5.2 灰显未过审的阶段），也正好说明「审校进度」这件事本身是站点内容的一部分。

## 五、页面与导航

四类页面，各有明确职责。版式结论来自浏览器 mockup 讨论（2026-11-18）。

### 5.1 首页 `/` —— 赛道地图

**第一屏**：小象形象 + 人格宣言（「一个把内核讲给你听的老兵」）+ 三个入口按钮（从「数据库内核」开始 / 看全部赛道 / 最近更新）。

**主体**：9 条赛道并列成网格，每张卡片是赛道名 + 一句话 summary + 一行**阶梯缩略**（深蓝 = 可走的阶段，琥珀 = 该阶段有视频，浅蓝 = 后续阶段）。点赛道进赛道页。

**空赛道不占主位**：当前没有已过审内容的赛道收进一个「规划中」的折叠区，不占首屏网格。
（现在 `docs/` 只有一篇母稿，八条赛道都是空的——但这是暂时的：审校推进，格子一格一格亮起来。）

**最近更新**作为次要入口（一个折叠区或底部一栏），不与赛道地图争夺首屏。

### 5.2 赛道页 `/learning/<track>/`

一条赛道 = 一条竖阶梯。

- 顶部：面包屑（学习流 / 赛道名）、赛道标题、summary、audience、goal、阶段数与总篇数。
- 每级一张卡片：**阶段名 + 阶段目标 + 收录篇数 + 代表文章标题（有链接）+ 视频徽标 `▶ EP0x`（琥珀色）**。
- 未过审的阶段**灰显但保留**——让空缺可见，是内容地图的一部分。
- 每级末尾一条「下一阶段 →」。

### 5.3 文档页

三栏（左路线 / 窄正文 / 右相关）：

| 位置 | 内容 |
| --- | --- |
| 左栏 | 这条赛道的阶段列表（当前位置高亮）+ 本阶段其它内容；**可手动折叠成窄边**，状态存 localStorage |
| 正文 | **宽度锁死 680~760px**，行高 1.75；顶部一条学习流位置条（赛道 › 阶段 + 「本阶段 13 篇，第 3 篇」+ 继续往下）；TL;DR 块；正文；图注；源码清单 / 复现命令块；多平台发布位 |
| 右栏 | 本阶段其它内容、相关视频、源码清单；**可整栏收起** |

**收起规则**：
- 手动：两栏各自可收，状态持久化。
- 自动（断点）：≥1440px 两栏开；1100~1440px 只开左栏（学习流位置比「相关内容」重要）；<1100px 两栏收，顶部两个按钮拉出抽屉。
- 自动（滚动）：文章滚到底部时右栏自动收起，把屏幕还给结尾。

### 5.4 视频页 `/videos/<期号>/`

**成片优先**（深度材料收右栏）：

- 顶部：期号徽标 `EP02 · 第一季`、标题、时长、日期、**所属学习流位置**（数据库内核 › L4）。
- 播放器：自有服务器托管的 mp4，**带章节标记**（分镜时间轴）。
- 章节条：可点击的时间码（00:00 问题 / 01:40 CSN 是什么 / 03:20 订阅端排序 / 05:10 边界）。
- 钩子块 + **口径边界**块（红线条线必须出现在页面上，例如「CSN 是 openGauss 的实现，不是 PostgreSQL 18 的能力」）。
- 对应文档（完整版文字稿）链接。
- 多平台发布位（抖音 / B 站 / 视频号 / 公众号 / 头条号）。
- 右栏：这一期的材料（分镜表 / 视觉契约 / 口播稿全文 / 源码清单，**点开才看**）+ 上一期 / 下一期。

### 5.5 其它页面

| 路径 | 内容 |
| --- | --- |
| `/learning/` | 学习流总览：赛道 × 阶段矩阵，每格标篇数、有无视频 |
| `/all/` | 全库检索入口（`docs/` 下的全部已过审文档都上站，只进这里，不进推荐流） |
| `/about/` | 小象是谁：人格三条主线、形象与音色、怎么联系 |
| `/videos/` | 视频系列页：一期一行（期号、钩子、时长、完整版、平台） |

**`docs/` 的上站策略**：`docs/` 下的每一篇都已过审，**全部上站**（可检索、可按分类浏览），
但**首页与赛道页只出现策展过的代表作**（策展表在 `site/data/featured.json`）。
深度靠代表作立住，体量靠可检索兜住。草稿箱里的东西不参与——它还没过审。

## 六、内容管线与目录结构

```
docs/（母稿，已审）  ──┐
                       │  [根 tools/ 编译：产出内容单元 + 站点数据 JSON]
video/（口播稿母稿） ──┘
   │
   ▼
content/units/（平台无关内容单元：markdown + front matter）
   │  [站点适配：front matter 校验（zod）、链接/图片重写（remark AST 插件）]
   ▼
Astro content collections → build → public/ → rsync 自有服务器
```

**站点有两个上游**：文档来自 `docs/` 的目录文档，视频来自 `video/` 的口播稿母稿。
两者都编译成 `content/units/` 里的内容单元，**渲染层只认内容单元**——这样站点不关心某个单元是文章还是视频，
平台适配器也不关心站点用什么生成器。

**旧链路的 `source/_posts/` 这一层直接消失**——hexo 的中间产物不再需要，Astro 直接消费 markdown。

### 目录

```
platforms/blog/
├── capability.toml          # 不变
├── cli.py                   # 不变（status / check）
├── docs/                    # 不变
├── outbox/                  # 不变
└── site/                    # 站点实现（全新）
    ├── astro.config.mjs
    ├── src/
    │   ├── content/         # 从 content/units/ 同步过来的副本（构建产物，不入库）
    │   ├── components/      # TrackMap / StageLadder / VideoPlayer / UnitCard / SourceRef ...
    │   ├── layouts/
    │   ├── pages/           # /  /learning/  /learning/[track]/  /videos/  /all/  /about/
    │   ├── lib/             # remark 插件（链接重写、语言归一化、mermaid）
    │   └── styles/
    ├── data/                # 站点私产（JSON）
    │   ├── learning-path.json   # 学习流策展规则（从 git 历史恢复后重写）
    │   ├── featured.json        # 首页/赛道页的代表作策展
    │   ├── lang-alias.json      # 围栏语言别名表
    │   └── redirects.json       # 旧 URL → 新 URL
    └── tools/               # 站点私有的构建/闸门脚本（沿用旧 tools/ 的思路）
```

根 `tools/` 保持**平台无关**：内容单元编译、学习流计算、发布索引、播客 feed、视频页面数据。

### 编译层的职责边界（硬规矩）

| 层 | 允许做 | 禁止做 |
| --- | --- | --- |
| Python（`tools/`） | 读 markdown、算 front matter、算赛道归属、产出 JSON 与内容单元 | **改正文**（任何形式的正则替换都算） |
| remark 插件（`src/lib/`） | 在 AST 上改 `link.url` / `image.url`、归一化围栏语言、插入 mermaid 容器 | 改代码块内容 |
| Astro | 渲染 | — |

## 七、Markdown 保真层

**实测数据**（2026-11-18，语料 = `drafts/` + `docs/` 共 672 个 md）：
审校还没开始，`docs/` 里只有一篇母稿，`drafts/` 是同批内容的镜像，所以拿它当**语料样本**量格式分布。
**闸门实际作用在 `docs/` 上**（草稿阶段在 `drafts/` 里跑同一套体检，让问题在 review 之前就暴露）。

| 项 | 数量 |
| --- | --- |
| 围栏总数 | 7868 |
| `c` / `mermaid` / `sql` / `shell` / `bash` / `text` / 无标注 | 2441 / 1311 / 932 / 840 / 538 / 462 / 895 |
| 含表格的文件 | 271 |
| 含原始 HTML 的文件 | 13 |
| 含数学公式的文件 | 14 |
| 围栏里出现 markdown 链接样式的 | 5（4 个文件） |
| 畸形围栏（开围栏行里跟了内容） | 约 9 |
| 语言标注种类 | 40+，含拼错的 `mermaind`(2) / `dockfile`(2)、`C`(17) / `C#`(10) / `cmd` / `text` / `conf` 等 |

**图比字多**：1311 张 mermaid + 3000+ 段代码。排版上必须把它们当「块」处理（宽度受限、横向滚动、图注），不能当正文流。

### 七条规矩

1. **正文改写只在 AST 上做**。旧站点的 `rewrite_images` / `rewrite_links` 是无视围栏的全局正则，会改到代码块里的内容（那 5 处就是活例子）。新链路用 remark 插件改 `url` 字段。
2. **mermaid 客户端懒加载**。Astro 无内置支持。用 mermaid ESM + IntersectionObserver，进视口才初始化。理由：1311 张图分散在几百个页面，单页通常只有 1~3 张，客户端负担被分摊；构建期 SVG 需要 chromium 或 jsdom（部分图型会挂），性价比低。**mermaid 源码留在 HTML 里**（SEO 可读）。若某页图特别多（如架构总览），可对该页单独构建期渲染。
3. **代码高亮用 Shiki**（Astro 内置，构建期高亮、零客户端 JS），比旧站点的 Prism 运行时高亮更快、主题可换。
4. **语言别名表**（`site/data/lang-alias.json`）：`C`→`c`、`C#`→`csharp`、`text`/`plaintext`→`plaintext`、`cmd`/`bat`→`batch`、`conf`/`cfg`→`ini`、`sh`→`bash`、`make`→`makefile`、`dockfile`→`dockerfile`、`mermaind`→`mermaid`。**未知语言回退 plaintext 并告警**，不许静默。
5. **围栏体检**（站点闸门，复活并扩展旧 `check-markdown.py`）：围栏奇偶、围栏嵌套、**开围栏行只允许语言标注**（把 9 处畸形围栏在 review 阶段揪出来）、mermaid 首行规范、表格列数一致。**体检失败 = 构建失败**，但报告要指到文件与行号。
6. **公式**：`remark-math` + `rehype-katex`。
7. **原始 HTML**：Astro 默认透传（13 个文件用到），内容是我们自己的，不做 sanitize。

## 八、视频

### 托管

成片 mp4 托管到自有服务器：`/var/www/blog/media/video/<EP>.mp4`（独立目录，nginx 单独给缓存与 Range 支持）。
**不进 git**（仓库里已经躺着几百篇 markdown，不该再背视频）——CI 里作为 artifact 传到服务器。

旁白 mp3 继续托管（RSS 的 `<enclosure>` 需要自己域名下的稳定直链）。

已有的品牌片（片头片尾，各 2.833 秒）同样托管，作为视频页与系列页的固定包装。

### 一期六期的现状

六期视频的**契约、口播稿、发布台账都在仓库里**，成片与音频是产物（本地 `out/`）。
新站点上线前需要**重新渲染一次成片**并上传服务器（或从本机现存成片取）。这是 P1 的第一个动作。

### 视频在学习流里的位置

## 十一、旧站点的处置

工作区里那 321 个删除**还没有提交**。这一轮要做三件事：

1. **把删除提交成一个明确的 commit**（`refactor(site): 撤掉旧 hexo 站点实现，重做为学习流门面`），作为重做的起点。
2. **从 git 历史回收资产**（不进 git 历史分支，直接落成新文件）：
   - `data/learning-path.json` → 学习流规则表的种子（重写映射，保留赛道文案）
   - `tools/` 里那批闸门脚本的**逻辑**（围栏体检、链接检查、块存在性检查）→ 移植到新 `site/tools/`
   - `data/redirects.json`、`category-redirects.json` → 旧 URL 的索引（作为「旧 URL → 404 / 重定向」的清单来源，见 §十一）
   - `data/view-counts.json` → 阅读量起点
3. **不回收的**：matery 主题本身、`patch-theme.py`（主题打补丁的路子整体作废）、hexo 专属的 filter/helper。

### 旧页面怎么办（**要作者拍板，不是技术问题**）

`docs/` 的存量已整体撤出（commit `8632f8c7`，撤出 1681 个文件、约 28.8 万行，原件留在 `drafts/` 镜像里），
但**线上 `growdu.cn` 还挂着那些旧页面**。新站按 `docs/` 重建后，那些 URL 会 404。

三条路：

| 选项 | 做法 | 代价 |
| --- | --- | --- |
| A 撤下 | 不做重定向，旧 URL 直接 404（配软 404 页） | 存量页面的外链与搜索权重一次性丢失；老书签失效 |
| B 保页面 | 撤出的存量页面仍然渲染（哪怕不进学习流推荐） | 与「只放已过审内容」的规矩冲突，得为存量开一条例外通道 |
| C 重定向 | 每条旧 URL 指向新的分类页/学习流页 | 语义不匹配的重定向反而有害，但权重能传出去 |

**我倾向 A + 软 404**，理由：存量是**有意**撤出的（没过审），为没过审的内容保留页面等于把审校闸门作废；
权重丢失是一次性的，而「未过审内容还挂着」是长期的。**但这是你的判断，不是我的**——旧页面如果有外部流量，A 和 C 的差别会很大。

> 注意：这条**不是** P0 的硬性前置（没有它站也能上线），但要**上线前有结论**，否则会悄悄丢一批外链。
> 另外 `git show HEAD:platforms/blog/site/data/redirects.json` 里那份旧重定向表仍然有效（那是 hexo 时代的 URL 之间的映射），
> 新站可以把它作为「旧 URL → 404」清单的来源。

### 14.2 URL 方案（**定下来了**）

| --- | --- |

**只有一处决定 URL 形状**：`site/src/lib/urls.ts`。文档与分类的单元 id 尾巴带 `_index`、
视频的单元 id 开头带 `video/`——那是内容单元里的形状，不是 URL 里的形状，翻译在这一层做。
（第一轮就因为漏抹了一次，攒出一批 `/videos/video/row-lock/` 的死链，

### 14.3 实现里的几个判断

- **Markdown 处理器**：Astro 7 默认的 Sätteri（Rust 写的）不支持 JS 插件，
  而链接重写与 mermaid 转换都得在 AST 上做，所以显式换成
  `@astrojs/markdown-remark` 的 `unified()`。代价是多装一个包，收益是保真层按原计划落地。
- **Shiki 排除 mermaid**：`syntaxHighlight: { type: 'shiki', excludeLangs: ['mermaid'] }`。
  流程图不是代码，不该被高亮器碰。
- **别名表去掉自指项**：Shiki 遇到 `plaintext -> plaintext` 这种自指别名会直接报
  Circular alias，所以别名表加载时统一过滤掉同名的项。
- **正文第一个 H1 摘掉**：母稿开头的 `# 标题` 跟页面顶部渲染的 title 重复，
  在 AST 上摘掉（`site/src/lib/remark-drop-first-h1.mjs`）。正文本身一个字没改。
- **旧站点的视频地址顺手翻译**：口播稿里互相引用用的是
  `/2026/11/12/video/row-lock/` 这种旧形状，渲染时翻成 `/videos/row-lock/`。
- **旧 hexo 站点的产物目录换了**：Astro 的输出目录是 `dist/`，`public/` 变成静态资源源码
  （favicon 入库，同步进来的 `images/`、`js/` 不入库）。`.gitignore` 已跟着改。

### 14.6 平台层与 CI 对齐新设计（2026-11-18 第二轮）

站点重做改了构建链，**平台层与 CI 就得跟着改**——它们是照着「站点 = hexo + matery」
写的。平台层照着旧站点写，等于让站点的新设计在两层之外没人认。

#### 14.6.1 平台层改了什么

| 文件 | 改了什么 |
| --- | --- |
| `platforms/blog/__init__.py` | 常量改成新的链路（`DOCS_DIR` / `CONTENT_UNITS_DIR` / `OUTBOX_DIR` / `MAX_CATEGORY_DEPTH`）。**删掉 `EXCLUDED_DIR_NAMES`**——它是一份 `sync-hexo.py` 的排除清单复制品，随旧站点一起死了。新编译器**不排除任何目录**：真规则是「目录链断了 = 编译直接失败」 |
| `platforms/blog/cli.py` | 重写成零依赖（不读 YAML）。`check` 不再自己判断「能不能进站」，而是**问编译器**（`tools/build-content-units.py --only <id>`）——规则只有一处 |
| `platforms/blog/capability.toml` | 流水线注释改成新链路；`review = "precheck"` 列的闸门换成真有的那几个；删掉指向不存在的 `tools/check-internal-links.py` 的引用；限额注释按 Astro 的实测重写（693 KB / 66 个文件，不是旧的 167 MB / 2400 个） |
| `platforms/blog/docs/01-站点即第三方平台.md` | §一~§七 按新链路重写 |
| `platforms/blog/outbox/README.md` | content_id 的定义改成「相对 `content/units/` 的路径」；kind 加上 video；地址规则指向 `site/src/lib/urls.ts`；产物路径改成 `site/dist/` |
| `tools/paths.py` | 加 `SITE_DIST`；`SITE_PUBLIC` 的含义纠正（它是静态资源**源码**，不是产物）；hexo 时代的常量集中成一组，注明是 publish / wechat / toutiao 的欠账 |

**编译器加了一个只读入口**：`tools/build-content-units.py --only <id>` 打印单个内容单元的
JSON（成功 0 / 失败 1）。平台层要回答「这一篇能不能进站」，不该把编译器的规则抄一份——
抄一份就会漂移。

#### 14.6.2 CI 改了什么

- **新增 `.github/workflows/site.yml`**：两个 job。
  - `verify`（纯 Python，几秒钟）：编译内容单元 → 编译视频内容单元 → `--check` 比对 →
    围栏体检（只扫 `docs/`）→ **学习流编译**（漏归类即失败）。
  - `build`（要 Node）：编译内容单元 → `npm ci` → `npm run build`（`SITE_URL=https://growdu.cn`）
    → **站点契约测试** → 产物作为 artifact 挂上。
- **删掉 `hexo.yml` 与 `site-guard.yml`**。前者引用的 `sync-hexo.py`、`adapt-units.py`、
  `_config.matery.yml`、`themes/matery/`、`patch-theme.py`、`copy-vendor.py`、
  `subset-icons.py`、`source/sw.js` **全部不存在**——它每次 push 必红，却一直没人看见。
  后者的 `::error::` 注解写法并进了 `site.yml`。
- **改 `contracts.yml`**：站点那几步换成根编译器（`build-content-units.py` +
  `build-video-pages.py`），pip 那行加上 `-r requirements/site.txt`。
- **新增 `requirements/site.txt`**：站点模块与根编译器的依赖（`pyyaml` + dev）。

三条**不能忘的教训**（都写在 workflow 的注释里）：

1. **每个 job 都要有 `timeout-minutes`**——能堵死队列的不是「在跑的 run 不取消」，
   而是**某个 job 挂死不退出**：run 不结束 → 并发组不释放 → 后面全卡在 pending。
2. **`fetch-depth: 0`**——编译器用 `git log` 取母稿最早一次提交的时间当日期，
   浅克隆会把日期算错。
3. **站点契约测试必须在 build job 里**——它守的是**产物**（`dist/`），
   `site/tests/test_pages.py` 在没有 `dist/` 时会**跳过**（不是通过）。
   放到 verify job 里等于把死链守卫静悄悄地关掉了。

还有两处**看着对、实则会在 CI 上一直红**的接线，是这一轮踩出来的：

4. **围栏体检只扫 `docs/`，不扫 `drafts/`。** `drafts/` 是草稿箱，里面躺着
   560 多篇没过审的存量镜像，格式问题有 **79 条**。站点只编译 `docs/`，
   闸门就该跟它对齐——一起扫的话闸门永远红着，等于没有闸门。
   （本地跑不带参数的版本仍然扫 `docs/` + `drafts/`，那是开发者自查草稿用的。）
5. **学习流跑的是「编译」而不是 `--check`。** `learning-path.compiled.json`
   是**构建产物，不入库**（`.gitignore` 第 10 行）——CI 的全新 checkout 里
   它不存在，`--check` 在那儿必然报「学习流数据不存在」，每次 push 都红。
   真正的闸门是**编译本身**：漏归类在两种模式下都失败。
   同理，`build-content-units.py --check` 在 CI 里比的是「这一行编出来的」
   与「上一行编出来的」（守的是**编译器的幂等性**与**无残留**）；
   内容单元同样不入库，它在本地那层意思才是「你改了母稿却忘了重编」。

> 顺带一提：旧的 `site-guard.yml` 跑的是**根级 `tests/`**，那些测试以前只在本机跑，
> CI 里没有任何地方执行它们，于是「测试全绿」和「CI 绿」是两件事。
> 根 `tests/` 现在由 `contracts.yml` 的「母稿 / review 层测试」那一步负责。

#### 14.6.3 部署：**知识还在，job 不在这一轮**

作者拍板：新 CI **只构建 + 校验，不部署**。部署归上线那一轮。

所以部署链的知识**不能丢**，它记在这里（也在
[`internal/blog/部署到服务器.md`](../../internal/blog/部署到服务器.md)，那份文档的
hexo 专属章节需要在新站上线时改写）：

| 环节 | 做法 |
| --- | --- |
| 产物位置 | rsync `dist/` → `/var/www/blog/releases/<时间戳>/` |
| 增量 | `--link-dest=<上一个 release>`：没变的文件**直接硬链接**过去，只有变化的那几个过网络。不加这一条时每次都要全量传，站点滞后多久全看跨太平洋链路的脸色（实测同一条命令跑出过 38 秒、也跑出过 20 分钟还没完） |
| 原子切换 | `ln -sfn ... current.new && mv -Tf current.new current`——访客不会看到半截文件 |
| 保留 | 保留最近 **10** 个 release，回滚只需把 symlink 指回旧目录，秒级生效，不用 reload nginx |
| ssh 参数 | `-p <port> -o BatchMode=yes -o ConnectTimeout=20`——`BatchMode` 让认证失败立刻报错，**不要去等密码提示**（那是「整个 job 挂住、并发组不释放、站点冻住」的元凶）；`ConnectTimeout` 让网络不通只等 20 秒 |
| 主机指纹 | `ssh-keyscan -T 10`；**`known_hosts` 为空就判死**——否则 ssh 会卡在「是否信任这个主机」的问句上，非交互环境里表现为整个 job 挂住 |
| 并发组 | 部署那种「必须跑完」的活用 `cancel-in-progress: false`（最新推送优先）；`site.yml` 现在的 `true` 是因为它只构建不部署 |
| Secrets | `DEPLOY_HOST` / `DEPLOY_PORT` / `DEPLOY_USER` / `DEPLOY_SSH_KEY` |

上线那一轮要做的事，按顺序：把部署 job 接进 `site.yml`（消费 `site-dist` artifact）→
在 nginx 里配 `root /var/www/blog/current`（**未知路径回真 404**，不要 fallback 到
`/index.html`——那是软 404）→ 签发证书 → 决定 §十一 的 A/B/C → 首跑。
