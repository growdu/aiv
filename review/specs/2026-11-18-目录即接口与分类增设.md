## 一、意图与边界

顶层规则（流水线、分层、D11 的草稿优先）已经定死。本文只补一件事：

> **要加一个分类、一块二级内容、一期视频的时候，到底动哪几处。**

不在本文的范围里：

- 不改流水线的形状（`draft → review → docs / video → 平台`）；
- 不改内容坐标系四维（方向 / 系列 / 期号 / 档位）的定义（见《层间接口与内容坐标系》）；
- 不动视频三档、平台能力声明、YouTube；
- 不把存量回炉走一遍 `draft → review`（D8）。

## 二、核心条款：接口是目录

**一级目录 = 一个分类。二级目录 = 一块二级内容。一篇文档 = 一期。**

```
drafts/<分类>/<二级内容>/<期号>.md            工作区
docs/<分类>/<二级内容>/<期号>/index.md        文档流母稿（front matter: episode: <期号>）
video/<分类>/<二级内容>/<期号>.md              视频流母稿（口播稿 + 字幕表）
```

**三棵树同形。** 分类不声明三遍——它**只存在于目录里**：

| 东西 | 真相在哪 | 性质 |
| --- | --- | --- |
| 分类是谁 | 一级目录的名字 | 目录派生 |
| 二级内容是谁 | 二级目录的名字 | 目录派生 |
| 期号是谁 | 母稿 front matter 的 `episode:` | **声明式（唯一出处）** |
| 分类的**中文名** | `docs/<分类>/_index.md` 的 `title:` | 分类页的显示名 |
| 二级内容的**中文名** | `docs/<分类>/<二级内容>/_index.md` 的 `cascade.categories` | 分类链的一环 |
| 目录归哪条赛道的哪个阶段 | `platforms/blog/site/data/learning-path.json` 的 `path_prefix` | **映射表**（今天唯一的跨层处，见 §五） |

> **同一件事只写一遍。** 方向与系列**不写进 front matter**——
> 它们在路径里，一眼看得见。抄进 front matter 就是第二份真相。
> （这条沿用《层间接口与内容坐标系》§2.2，不在本文重复论证。）

## 三、三种操作，各动哪几处

### 3.1 加一个分类（一级目录）

| 步 | 层 | 做什么 | 落点 |
| --- | --- | --- | --- |
| 1 | 工作层 | 开目录，写分类提案 | `drafts/<分类>/_index.md` |
| 2 | 工作层 | 二级内容开在它下面，稿子落位 | `drafts/<分类>/<二级内容>/<期号>.md` |
| 3 | 审核层 | 过分类审校（§四） | `review/categories/<分类>.md` |
| 4 | 内容层 | 同形复制，母稿带 `episode:` | `docs/<分类>/<二级内容>/<期号>/index.md` |
| 5 | 视频层 | 同形复制口播稿（要出视频才做） | `video/<分类>/<二级内容>/<期号>.md` |
| 6 | 站点策展 | 给这个目录加赛道归属 | `platforms/blog/site/data/learning-path.json` |
| 7 | — | 验收（§六） | — |

**第 4 步是这一层的「声明」落点。** 新分类的 URL 命名空间从这一刻起就是永久的
（§五「不删除任何历史 URL」）。

### 3.2 加一块二级内容（二级目录）

同上，只是落在二级这一层。**源码方向下多一条约束**：二级目录 = 学习路径的一个阶段。

> **不变量（仅限源码方向赛道）**：阶段 ↔ 系列目录 **1:1**。
> `postgresql` L1–L8 ↔ 8 个系列目录；`linux` L1–L5 ↔ 5 个；`dpdk` L1–L4 ↔ 4 个。
> 教学顺序与系列划分天生一致——「循序渐进」不需要另维护，它就是目录的顺序。
> 守卫见 §五。（《层间接口与内容坐标系》§2.4 提的同一条，落地在本文。）

**这条不变量不能写成全站通则**：`engineering`（6 目录 / 4 阶段）、`distributed`（6 / 4）当场就红。

### 3.3 加一期（文档）

在某个二级内容下放一篇文档，front matter 写 `episode: <期号>`。
期号是**全局唯一**的，`episode_no` 在同一系列内不跳号。

## 四、慎重建目录

> **在 `drafts/` 下建目录，是一个策展动作，不是一个文件操作。**

建一级目录 = **新增一个对外可见的分类**。它带来三件不会自动消失的事：

1. **URL 命名空间是永久的。** 分类页一旦生成，地址就是它的身份；
   改名等于让所有指向它的链接失效（站外也失效）。
2. **三边要同形。** `docs/` 与 `video/` 要跟着长出同形的一层；
   只长一边，这棵树就不同形，坐标就对不上。
3. **要登记映射。** `learning-path.json` 得给这个目录一条规则。
   **空分类不被任何守卫管**——它没有文章，也就没有「文章必须归到某条赛道」这条断言兜着。

所以规矩是：

- **先把稿子放在既有分类里**，确认它确实撑得起一个分类了，再开目录；
- **开目录要过审**（下面这六问）；
- **一次只开一层**，别顺手开三级。

**分类审校六问**（`review/README.md` 的文章审校口径不适用于分类——分类没有正文）：

1. 这个分类**该不该立**？还是既有分类的子类？
2. 它的**中文名**叫什么？跟邻居分得开吗？
3. 它的**层级**（一级还是二级）定对了吗？
4. 它跟**邻近分类的边界**在哪？有没有重叠？
5. 目录归**哪条赛道的哪个阶段**？顺序讲得通吗？
6. 要不要**出视频**？出了的话是哪一期？

> **反例留档**：`docs/base/` 这类混主题目录，曾经把好几条主线的文章混在一个目录下，
> 拆的时候「该拆该合」只能靠人判断。现在所有目录都挂在一条明确的线下，
> 一条线一个话题。

## 五、今天唯一的跨层处，和它要收掉的方式

`platforms/blog/site/data/learning-path.json` 住在**平台层**，却按**内容层的路径前缀**
匹配内容（`path_prefix: "source-tracks/postgresql/logical-replication/"`）。
这是**跨层通信**——每加一个分类都在放大它。

**目标**：目录 → 坐标由编译器派生，坐标随内容单元走到平台层，
平台层按坐标生成赛道页，不再按路径前缀猜。

- 中间态（今天）：按现状手写 `path_prefix` 映射；
- 收口：《层间接口与内容坐标系》**M1**（赛道改名）+ **M4**（内容契约扩字段）
  + **M5**（母稿改字段）落地后，赛道归属变成内容单元的字段，这条接缝消失。

在收口之前，**规程不变**（§三第 6 步照做），只是那一行是全流程唯一的跨层手写处。

## 六、验收

按模块分开跑，不合跑（见《验收按模块拆开》）：

```bash
# 分类树的守卫（新增）
python3 -m pytest platforms/blog/site/tests/test_categories.py -q

# 学习路径：文章有赛道、赛道有阶段、阶段有文章
python3 -m pytest platforms/blog/site/tests/test_learning_path.py -q

# 分类页与学习路径页真的生成出来了
python3 platforms/blog/site/tools/build-learning-path.py

# 站内链接通
python3 platforms/blog/site/tools/check-internal-links.py
```

**新分类的分类页必须真的存在**——不能只断言 `_index.md` 里有 `title:`。
只写 `title:` 不写 `cascade.categories`，二三级分类会**静默消失**，
文章全挂到一级赛道，**没有一个测试会报错**。

## 七、守卫

新增 `platforms/blog/site/tests/test_categories.py`，四条：

| 编号 | 判据 | 豁免 | 不做会怎样 |
| --- | --- | --- | --- |
| `CAT-01` | 每个 `docs/` 顶层目录有 `_index.md` 且带 `title:` | 无 | 分类名退化成英文目录名 → **URL 变了**，老链接集体失效 |
| `CAT-02` | 每个分类目录的 `_index.md` 带 `cascade.categories` | 显式豁免名单（今天只有 `docs/life/`） | 二三级分类**整条消失**，文章全挂到一级赛道 |
| `CAT-03` | `title:` 与 `cascade.categories[0]` 是同一个名字 | 同上 | 页面标题一个名、分类链另一个名 |
| `CAT-04` | 源码方向赛道：阶段 ↔ 系列目录 1:1 | 非源码方向赛道不适用 | 学习路径的顺序跟目录的顺序脱钩 |

**豁免名单要显式写出来**，不写「所有例外都豁免」——
口子必须窄，否则守卫会退化成「报告」。

**`CAT-04` 不能写成全站通则**：`engineering`（6 目录 / 4 阶段）、
`distributed`（6 / 4）当场就红。
源码方向是**派生**出来的——一个赛道的所有阶段都带 `path_prefix`，
且这些前缀都在同一个 `source-tracks/<系列>/` 底下，它才是源码方向的赛道。

四条都**做过变异验证**：把 `title:` 改掉、把 `cascade:` 删掉、
把两个名字改成不一样、在系列目录里多开一个目录——
对应的那一条当场变红，改回去又绿。
