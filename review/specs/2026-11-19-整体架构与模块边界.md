## 一、这套架构要解决什么

**一句话：让「内容」与「发布」这两件会一直变的事，各自住在自己的模块里；
模块之间只通过文件上的接口说话。**

要解决的四个问题，都是「会一直变」的：

| 会一直变的 | 所以架构要给它什么 |
| --- | --- |
| 内容（写、审、改、删） | 一个**唯一**的真相与一条单向的路：草稿 → 审 → 母稿 → 内容单元 |
| 平台（加平台、改限额、换发布方式） | 一个**目录即接口**的注册表：加平台只动 `platforms/` |
| 身份（站名、品牌、账号、地址） | 一条**缝**：框架源码里不许出现站名，值全在使用者那一侧 |
| 验收（加模块、改接口） | **各模块各跑各的**：谁改了什么，只有谁的套件会红 |

### 这一版明确不做

- **不做内容。** 仓库里现在一条面向读者的内容都不剩——这是「只做框架，不做内容」的直接结果。
- **不做整站快照验收**（页面清单 / 死链基线放 `/tmp`，会被清）。
- **不做「全套测试合跑一遍」当验收。**
- **不做通用的插件系统。** 六个平台是目录，不是注册表里的条目。
- **不把浏览器自动化做成通用发布框架。** `browser/` 只服务那几个没有公开 API 的平台。

### 2026-11-19 补记：视频线的文档也不发了

`docs/` 归零不是「清内容顺手清的」，是 owner 拍板的**架构决定**：

| 问题 | 决定 | 理由 |
| --- | --- | --- |
| 视频线的规范（人格 / 形象与音色 / 背景音乐 / 5 份模块 README）要不要发到站点？ | **不发** | 它们是**模块内部说明书**（怎么搭一条视频流水线），不是面向读者的稿子 |
| 那怎么让站点上有这条线的内容？ | **要发就写进 `docs/`** | `docs/` 是母稿层，唯一的内容真相；稿子从那儿来，不从模块说明书来 |
| 「发布副本」机制（`video/scripts/sync_publish_docs.py` + 守卫 `video/pipeline/tests/test_publish_copy.py`）怎么办？ | **整套删掉** | 发布路径写死在视频线的脚本里，等于这条线替站点挑了分类树的位置——那不是它该管的事 |

连带的结果：

- `docs/` 现在只有一个 `.gitkeep`；`tools/build-content-units.py` 编出 **0** 个内容单元；
- 站点构建出来是 **52 个页面**的**空架子**（首页、关于页、时间线等框架页，无文章）；
- `platforms/blog/site/data/learning-path.json` 里指向 `^life/aiv($|/)` 的两条学习流规则删了；
- 视频线的文档留在 `video/` 里，`video/README.md` 明写「这些文档不进站点」。

**这一条同时定下了一条通用规矩**：模块的文档不是稿子，模块不该替站点决定发什么。
「一条线要不要在站点上有页面」由**站点那侧的分类树**说了算，不是由这条线的脚本说了算。

## 二、九个模块

| # | 模块 | 住在哪 | 它拥有（写） | 它不碰（读别人的内容） |
| --- | --- | --- | --- | --- |
| 1 | 草稿层 | `drafts/` | 在改的稿子 | 不发布 |
| 2 | 母稿层 | `docs/` | **唯一的内容真相**：已过审的稿子与分类页 | 不发布 |
| 3 | 审校层 | `review/` | 什么算「已过审」的判据：规则、范围划分、审校记录 | 不碰正文 |
| 4 | 编译器 | `tools/build-content-units.py` → `content/units/` | 内容单元这一层产物 | 只读 `docs/` |
| 5 | 站点 | `platforms/blog/`（含 `site/`） | 六个平台之一的 adapter + Astro 工程 | 只读内容单元与母稿 |
| 6 | 平台适配层 | `platforms/{wechat,toutiao,douyin,bilibili,channels}/` | 每个平台一份能力声明与出包逻辑 | 只读内容单元 |
| 7 | 契约与发布层 | `publish/` | 能力模型、内容契约、发布清单、调度、规格 | 只读能力声明与内容单元 |
| 8 | 视频线 | `video/` | 视频生产：人格 / 形象 / 音色 / 片头片尾 / 流水线 | 不读 `docs/` 的文章 |
| 9 | 发布执行器 | `browser/` | 把「人在平台后台手动做的事」做成命令 | 只读出包目录 |

> **1–3 是内容侧，4 是内容侧的出口，5–7 是发布侧，8–9 是视频与执行侧。**
> 视频线（8）自成一条闭环：它的产物是**内容单元**（`content/units/video/`），
> 于是它跟发布侧的接口跟文档视频走的是同一条，不另开一道门。

## 三、模块之间只通过四处说话

### 缝 1：内容单元（`content/units/`）

编译器写，所有 adapter 读。**它是构建产物，不入库**（`.gitignore`），
CI 里现编。

- 一篇文档 = 一个内容单元 = 一个 markdown + 一份 front matter；
- 正文**一个字都不改**——编译器只推导与拷贝 front matter；
- id = 相对 `content/units/` 的路径（不带 `.md`）；
- 分类页是 `kind: category` 的单元，id 去掉 `_index` 尾巴。

### 缝 2：能力声明（`platforms/*/capability.toml`）

adapter 写，契约层**按目录扫出来**（`platforms/*/capability.toml`，
**目录名就是平台 id**）。契约层因此不需要为任何平台写代码，
也不需要知道有哪些平台。

视频线也读这一份声明的 `[limits]` 段（`video/pipeline/pyv/epmeta.py`
的 `load_limits`）——同样**只读文件，不 import**。

### 缝 3：身份（各模块自己的配置）

框架源码里**不许出现站名**（`platforms/blog/site/tests/test_site_config.py` 守着）。

| 谁的 | 缝在哪 | 环境变量 |
| --- | --- | --- |
| 站点 | `platforms/blog/site/data/site.json` | `SITE_URL`（Astro 构建与 CI 用同一个） |
| 视频线 | `video/config.toml`（`[brand].*` / `[character].*`） | `VIDEO_CONFIG`（指向另一份配置） |
| 发布层 | `publish/deploy/*.template`（`com.example.*`） | —— |

### 缝 3 还欠着的：**平台适配层还没接上**

缝 3 的规矩是「框架源码里不许出现站名」。这条规矩现在**只被一个模块守着**
（`platforms/blog/site/tests/test_site_config.py`，只管站点），
别的模块没人管，于是实例身份还留在这些地方：

| 地方 | 写死了什么 | 该从哪儿来 |
| --- | --- | --- |
| `platforms/wechat/cli.py` | `DEFAULT_SOURCE_URL = "https://growdu.cn"` | `SITE_URL` |
| `platforms/wechat/cover.py` | `_BRAND = "growdu.cn"` | `SITE_URL` 的主机名 |
| `platforms/toutiao/{cli,publish,contract}.py` | `source_url = "https://growdu.cn"` | `SITE_URL` |
| `platforms/toutiao/assets.py` | 下载外链图的 Referer 头写死 `https://growdu.cn/` | 随请求走，框架不该替请求指定 Referer |
| `platforms/wechat/brand.py` | 默认署名 `"growdu"` | 站点身份（`site.json` 的 author） |
| `tools/build-content-units.py` | 母稿没写 author 时补 `"growdu"` | 同上 |
| `video/brand/scripts/make_audio.sh` | 片头片尾旁白写死整句 | `video/config.toml` 的 `[brand]` |
| `video/brand/scripts/render.sh` | 底板文件名 `growdu_intro_*.png` | `[character].slug` |
| `platforms/wechat/deploy/launchd.plist.template` | 标签 `com.growdu.weixin` | `com.example.*`（同发布层别的模板） |
| `video/brand/scripts/render_brand.py` | 胶囊副标题硬接了半句 `· 分享技术之美` | `[brand].tagline` 整句 |

**这不是「内容没删干净」，是缝没接上**：值还在源码里，就还在源码里。
补法有两种——让这些模块从缝上取值，或者给它们各自的缝。
**但先要定的是那条规矩的适用范围**：是「全仓库框架代码都不许出现站名」
（那就得有一条仓库级的守卫盯着），还是「只有站点不许」。

### 缝 4：验收（各模块各跑各的）

每个模块一条命令，跑在自己的目录里。命令清单与实测数字见
[`acceptance/README.md`](../../acceptance/README.md)。

### 还没成缝的一处：**URL 规则**

站点的 URL 规则现在**只在站点的 TypeScript 里**
（`site/src/lib/urls.ts`，注释里明写「站点里只有这一处决定链接长什么样」）。
但根 `tools/` 的视频编译器与 `publish/` 的契约层**都要算同一个地址**，
它们算出来的是 hexo 时代的形状（见 §五 第 10 条）。

于是「一篇文章的地址是什么」现在有**两份答案**，而其中一份是死的。
**要么把 URL 规则提成一处共享的规则（新的缝），要么让站点从那边取
（现有的缝上加一个接口）——这不是「抄一下 `urls.ts`」能了的事，
抄一份就是又造一个漂移源。**

## 四、依赖方向

**现在仓库里两个模块互相 import 的地方是 0 处。** 这不是巧合，是规矩：

- 契约层**不** import 站点层，站点层**不** import 契约层——
  两边唯一的接缝是同一份 `capability.toml`；
- 契约层**不** import 任何 adapter（它按目录扫）；
- adapter 之间**不**互相 import（各发各的平台）；
- 上层要下层的东西，**只准通过文件要，不准通过 import 要**——
  这条让「加一个平台」「换掉一个平台」都只是目录的事。

方向：

```
docs/ ──编译──▶ content/units/ ──▶ 各 adapter（站点 / 微信 / 头条 / 抖音 / B站 / 视频号）
   ▲                  │                        │
   │                  ▼                        ▼
drafts/         platforms/*/capability.toml   publish/（按目录扫，不 import）
                                                  │
review/（判据）                                    ▼
                                             browser/（只服务没有公开 API 的平台）
```

### 1. URL 规则：**提成一处共享的规则** ✅

站点的 URL 规则现在**只在站点的 TypeScript 里**（`site/src/lib/urls.ts`，
注释里明写「站点里只有这一处决定链接长什么样」）。但根 `tools/` 的视频编译器
与 `publish/` 的契约层**都要算同一个地址**，它们算出来的是 hexo 时代的形状
（§五 第 10 条）。

**定了：走 A——提成一处共享的规则。**

| 走法 | 长什么样 | 代价 | |
| --- | --- | --- | --- |
| **A：提成一处共享的规则** | 规则落成一份**两边都能读的文件**（独立目录，不混进构建产物），站点与发布层都从它取 | 多一处地方要维护；但「一份真相」这件事是真的 | **✅ 定了** |
| B：站点从根 `tools/` 取 | 规则住在根 `tools/`，站点构建时读它 | 站点成了「依赖仓库根一个文件」的下游——**耦合方向反了** | 否 |

**落点**：共享规则住在一个**入库的独立目录**里（不放 `content/units/` 旁边——
那是被 `.gitignore` 掉的构建产物，不是一份入库的真相）。
规则本身的形式：**一份 JSON**——站点（TypeScript）与发布层（Python）都读 JSON，
不用一边生成、一边消费。

**连带定下的**：落地地址统一成 **`/docs/<id>/`**（站点现行的形状）。
`/YYYY/MM/DD/<content_id>/`（发布层现行的、hexo 时代的）**不再产出**——
两处都改成它。

### 2. 期身份：**四层 + 成片分目录 + outbox 扁平** ✅

三处对不上（§五 第 11 条）：

- **期身份**：`contract.json` 的 `episode` 是**三层文档路径**（`系列/合集/文档`），
  adapter 命令行传的是**四层期路径**（多一档档位）；
- **成片的路径**：流水线出的是压平的 `out/系列-合集-文档-档位.mp4`，
  adapter 找的是 `out/系列/合集/文档/档位.mp4`；
- **快照文件名**带斜杠，落成嵌套目录，而 outbox 是**扁平**的 JSON 目录。

**定了：四层期身份 + 成片分目录 + outbox 扁平。**

| 项 | 定了 | 理由 |
| --- | --- | --- |
| 期身份 | **四层**（`系列/合集/文档/档位`） | 跟现在的坐标一致，`episodes.ep_id()` 那套已经在用 |
| 成片 | **分目录**（`out/系列/合集/文档/档位.mp4`） | 跟期目录同构，一眼看出成片属于哪一期 |
| outbox | **扁平**（`outbox/系列-合集-文档-档位__bilibili.json`） | 它是入库目录，嵌套会让 git 路径带上中文层级 |

> ⚠️ 这条不落地，抖音 / 视频号 / B站三个 adapter 的「出包」这一步就跑不通。
> 现在跑不通，但**没人看见**——这三个模块今天才进 CI。

### 3. 分类归档页的地址：**编译器算映射，不长新路由** ✅

微信 adapter 拼 `{站点}/categories/{slug}/`，而 Astro 站点**没有** `/categories/`
路由（分类页在 `/docs/<id>/`）。公众号文章里的「阅读原文 → 分类归档」因此是软 404。

**定了：站点不长 `/categories/` 路由。** 分类名 → 分类内容单元 id 的映射
由**编译器**算出来写进内容单元（编译器知道分类链 `cascade.categories`，
也知道对应的分类单元 id），adapter 拿那个 id 拼 `/docs/<id>/`。

这条与第 1 条**共用同一份共享规则**——映射放在那份 JSON 里，
站点与 adapter 都从它取，站点负责渲染、adapter 负责拼地址，两边不各算一份。

### 4. 站名规矩：**全仓库** ✅

「框架源码里不许出现站名」这条规矩现在**只被站点一个模块守着**
（`site/tests/test_site_config.py`），别处的实例身份还写在源码里
（清单见 §三「缝 3 还欠着的」）。

**定了：全仓库。** 任何模块的框架代码里都不许出现站名，值全在使用者那一侧。
→ 补一条**仓库级**的守卫，逐模块扫实例身份。

> 这跟第 1 条是同一件事的两面：**身份归使用者，框架只留一条缝。**
> 站点那条缝是 `site.json`，视频线那条缝是 `video/config.toml`，
> 发布层那条缝是 `publish/deploy/*.template`——每个模块有自己的一份，
> 但**框架源码里一个都不许写死**。
