# 草稿层与母稿层的接口协议

> 这份文档定义 `drafts/` 与 `docs/` 之间**唯一的接口**：什么能过去、过去的时候
> 带走什么、过去之后两边该是什么关系。
>
> 上位文档：《[顶层设计与目录调整](2026-11-18-顶层设计与目录调整.md)》的 D11、
> 《[目录即接口与分类增设](2026-11-18-目录即接口与分类增设.md)》。
> 本文不重复它们，只在两处需要勘误的地方明确写出来（见 §九）。

## 一、这份协议不解决什么

- 不定义站点怎么构建、怎么发布、怎么同步到第三方平台。
- 不定义视频线怎么分合集、视频稿怎么写。
- 不定义 `learning-path.json` 怎么维护（它在内容层与赛道之间，不在草稿层与母稿层之间）。
- 不改 `tests/`。任何守卫（§八）都是**下一步**的事，本协议只把「要守什么」定下来。

一句话：**这一层只管稿子怎么从「在改」变成「已过审」。**

## 二、两层的语义

| | `drafts/` | `docs/` |
| --- | --- | --- |
| 定位 | 工作区 | 已过审母稿的唯一落点 |
| 允许的状态 | 完整 / 半成品 / 缺素材 | **只有已过审** |
| 允许「未过审」吗 | 允许，这就是它存在的意义 | **不允许** |
| 谁写 | 作者与协作者 | 只由「合入」动作写入 |
| 方向 | → | ←（单向） |

**方向是单向的。** 改动先落 `drafts/`，过审后复制进 `docs/`。
不允许从 `docs/` 往回改稿——往回改等于绕过审校。

`docs/` 里**没有「未过审」这个状态**。这不是约定，是不变量：
`docs/` 里每一个 `.md` 都必须能指向一份「审校状态：已合入」的审校记录。

## 三、`drafts/` 里装的是三类东西，不是一类

这是本协议最重要的一条修正。旧的说法按**目录**分（「`source-tracks/` 是素材，
整树 rsync」），实测证明这个分法是错的：

> `drafts/source-tracks/` 下 325 个 `.md` 与 192 张 `.png` 混在同一批目录里。
> 整树 rsync 会把**没过审的稿子**推进 `docs/`，直接违反 D11。

正确的分法按**内容性质**分，跟它在哪个目录无关：

| 类 | 判定 | 内容 | 要不要过审 |
| --- | --- | --- | --- |
| **稿子** | `.md` 且不是 `_index.md` | 文章正文 | **要**，逐篇过 |
| **分类页** | 文件名是 `_index.md` | 目录索引 | **要**，但规则不同（§六） |
| **素材** | 一切非 `.md` 文件 | 图片、代码、附件、样例数据 | 不审内容，但要跟着稿子走（§五） |

素材的判定不看它在 `source-tracks/` 还是 `engineering/`——它就在那儿，
但它是「这篇稿子的素材」，不是「这个目录的素材」。

## 四、形态映射：形状不转换

**实测（2026-11-18）**：`drafts/` 与 `docs/` 是**同形镜像**——
426 篇扁平稿（`<名>.md`）+ 136 篇 bundle 稿（`<名>/index.md`），两边完全一致，
零个名字冲突。`drafts/` 里没有把 flat 转成 bundle 的痕迹，`docs/` 里也没有。

**裁决：形状不转换。** `drafts/` 的形状就是 `docs/` 的形状。

理由：

1. 转换要改 426 个文件名，而稿子之间全是相对链接——改形状就是改链接，
   426 篇的相对链接改写是一个必然出错、且错了不易发现的动作。
2. 形状不一致本身就是「两棵树对不上」的故障源。同形镜像的校验是
   `diff -r` 一次的事，异形则需要一张映射表，而映射表必然腐烂。
3. bundle 形态本身是有用的：8 个 bundle 自带自己的图片（`image-1.png` 等），
   目录就是它的素材边界。

> **对《目录即接口与分类增设》§二的勘误**：那一节写
> `drafts/<期号>.md` → `docs/<期号>/index.md`（flat → bundle）。
> 这条**与实际不符**，按本文 §四 改为**同形**。原句应视为笔误，
> 不是一条待实施的迁移计划。

bundle 与 flat 的选择标准（给以后新增稿用）：

- **flat**（`<名>.md`）：稿子没有专属素材，或素材放在公共位置。
- **bundle**（`<名>/index.md`）：稿子有**专属**素材（自己的图、自己的代码目录），
  或者带 `episode:` 字段。
- 两种形态**不冲突**：0 篇 flat 与 bundle 同名。将来若冲突，以 bundle 为准
  （把 flat 改名为 `<名>-文.md` 之类），不要让两棵树都猜。

## 五、复制单元：不是「复制这一个文件」

`drafts/README.md` §四 写「第 3 步是『复制这一个文件』」。这句话对 flat 稿子
成立，对 bundle 和带素材的稿子不成立。精确化：

| 稿子形态 | 复制单元 | 复制内容 |
| --- | --- | --- |
| flat `<名>.md`，无素材 | 1 个文件 | `<名>.md` |
| flat `<名>.md`，引用了同目录素材 | 1 个文件 + N 个素材文件 | `<名>.md` + 它引用到的**同目录**素材 |
| bundle `<名>/index.md` | **1 个目录** | `<名>/` 整个目录（`index.md` + 自带素材） |
| 分类页 `_index.md` | 1 个文件 | `_index.md` |

**素材归属规则**：一个素材文件属于**引用它的那篇稿子**。
判定方法是机械的——正文里的 Markdown 图片引用与链接。

实测：426 篇扁平稿里，只有 18 个目录含图片引用；**悬空引用 0 条**
（引用到的文件都真实存在）；孤儿图片 19 个（另有大批 vendored 树
如 `theme-example-Sierra/`、`docker_image/`，本来就不是文章素材）。

这个规则有个直接后果：**目录不是素材的边界，引用才是**。
所以「整树 rsync」这种做法没有适用场景——
它会把同目录下没审的稿子一起搬过去。素材只能**逐个按引用挑**，
或者以 bundle 为单位整目录搬（bundle 的目录就是它的素材边界）。

## 六、分类页的特殊规则

分类页（`_index.md`）也是稿子，也要过审，但它的过审规则和文章不同。

**规则 1：分类页列的文章必须都已过审。**
`docs/` 里没有的稿子，不能出现在 `docs/` 的分类页里，否则站内链接是死链。
分类页与它列的文章要**一起过审**。

**规则 2：分类页在 `drafts/` 与 `docs/` 里允许内容不同。**
这是**唯一**允许两边不一致的稿子类型。

- `drafts/` 的分类页 = 在改的版本（全量策展、待补的条目）
- `docs/` 的分类页 = 已过审的版本（只列已过审的文章）

理由：分类页的内容是「当前已过审集合」的投影。它**必然**落后于
`drafts/` 里的策展——除非全部母稿都过审了。允许两边不同，
是让这件事显式化，而不是让它变成一个 bug。

> 其余所有稿子（flat 与 bundle）过审后，两边**逐字节一致**。
> 这条是 G-05 守卫的依据。

**规则 3：分类页的链接清单应当派生，而不是手写。**
手工维护的清单，漏一行就是站内少一条链接，多一行就是死链。
「应当派生」这件事属于构建层，是下一步；但**在协议层先立规矩**：
分类页过审时，它的链接清单必须与「`docs/` 里实际存在的稿子」**完全一致**，
不多不少。核对手工。

## 七、审校记录的命名

审校记录放在 `review/`，与稿子在同一棵相对树上：

| 稿子 | 审校记录 |
| --- | --- |
| `drafts/a/b/c.md` | `review/a/b/c.md` |
| `drafts/a/b/c/index.md` | `review/a/b/c.md`（**丢掉 `/index.md`**） |
| `drafts/a/b/_index.md` | `review/a/b/_index.md`（**保留 `_index.md`**） |

两条不冲突：bundle 稿的记录是 `c.md`，分类页的记录是 `_index.md`，
文件名不同。而且 bundle 目录名叫 `_index/` 的情况不存在，所以不撞。

素材目录不需要审校记录。

记录内容按 `review/README.md` 的模板写。关键字段：

- **原文**：写 `drafts/` 里的路径（审的是 `drafts/` 那一份）。
- **审校状态**：`建议中` / `已确认` / `已合入`。
- **事实待核**：三条标记语义见 `review/README.md`——`- [x]`、`- [不适用]`、
  未销掉的。**未销掉的事实阻塞「已合入」**。

「已合入」的语义是：**与本次改动相关的**待核事实都销掉了，
不是全篇事实都核实过。所以标「不适用」是合法的。

## 八、`episode:` 字段

`episode:` 是**视频线的锚点**，实测全库只有 6 个文件带它，
全部是 bundle 形态，全部在 `drafts/source-tracks/postgresql/`。

协议层的三条：

1. **可选。** 不是每一篇稿子都要有。「一篇文档 = 一期」是目录即接口的说法，
   不是「每篇都要写期号」。只有要配视频的稿子才带 `episode:`。
2. **写在母稿的 front matter 里**，不写在目录名里。视频线读的是 `docs/` 的母稿，
   字段跟着母稿走。
3. **取值格式由视频线定义**，本协议不管。草稿层只保证：带 `episode:` 的稿子
   过审进 `docs/` 时，这个字段**原样带过去**，不被改写。

> **已知的跨层耦合**：视频线依赖 `docs/` 母稿里的 `episode:`。
> 这是本协议**唯一**承认的、草稿层与母稿层之外的依赖。
> 本协议保证母稿存在且字段完整；它不保证视频线的东西齐了。

## 九、守卫：现在一个都没有

实测：`tools/` 里只有 `review-check.py` 和 `draft-descriptions.py` 提到 `drafts/`；
5 个 workflow 里**没有任何针对 `drafts/` 的检查**。
也就是说，§二 的不变量（`docs/` 里只有已过审内容）**目前没有任何机器保障**，
纯靠人记着。

协议层先把「要守什么」定下来，实现是下一步：

| 编号 | 守什么 | 判据 |
| --- | --- | --- |
| G-01 | `docs/` 里每个稿子都有「已合入」的审校记录 | `review/` 里有对应记录，且状态是「已合入」 |
| G-02 | `docs/` 里每个分类页都有「已合入」的审校记录 | 同上 |
| G-03 | 稿子引用的素材跟着进了 `docs/` | 正文里的相对引用在 `docs/` 侧解析得到 |
| G-04 | 分类页的链接不悬空 | 分类页里每条站内链接，`docs/` 里有对应文件 |
| G-05 | 已过审的稿子两边逐字节一致 | flat/bundle 稿：`diff` 无差异 |
| G-06 | 形状一致 | `drafts/` 的 `foo.md` 对 `docs/` 的 `foo.md`；`foo/index.md` 对 `foo/index.md` |
| G-07 | `episode:` 一致 | 同一篇稿子两边的 `episode:` 相同 |
| G-08 | 不越级写入 | `docs/` 里不得出现 `drafts/` 没有的稿子 |

G-05 **不适用于分类页**——§六 规则 2 明确允许分类页两边不同。
这条例外是 G-05 唯一需要小心的地方。

G-03 是目前唯一有点难的：flat 稿子的素材可能在同目录，也可能在别处，
判定要靠解析正文引用。bundle 形态因为目录就是边界，G-03 在 bundle 上是平凡的。

## 十、一次「合入」是什么

合入是**原子的**，一个单元一次提交：

1. `review/` 里补一份审校记录，状态写「已合入」，事实待核都销掉或标「不适用」。
2. 按 §五 把复制单元复制进 `docs/`。
3. 稿子里的相对链接在 `docs/` 侧仍然解析得到（G-03）。
4. 如果这篇稿子被某张分类页列出，那张分类页也要一起过审并更新（§六 规则 1）。

**一件不做**：不因为「顺手」把别的稿子也带过去。
存量不回炉——本协议只管往后走的新流程。

## 十一、这条协议没解决的（留给下一层）

| 问题 | 归哪一层 |
| --- | --- |
| 分类页的链接清单自动派生 | 构建层 |
| 孤儿素材（19 个 + vendored 树）怎么处置 | 素材层 |
| `learning-path.json` 的 `path_prefix` 怎么维护 | 内容层 ↔ 赛道层 |
| 视频线的合集/系列结构、`episode:` 取值格式 | 视频线 |
| §九 八条守卫怎么实现、放在 CI 哪一步 | 构建层 |
| 站点构建的连带问题（分类页死链、视频线缺期号母稿） | 构建层 |
