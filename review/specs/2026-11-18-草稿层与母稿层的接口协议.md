# 草稿层与母稿层的接口协议

> 这份文档定义 `drafts/` 与 `docs/` 之间**唯一的接口**：什么能过去、过去的时候
> 带走什么、过去之后两边该是什么关系。
>
> **接口优先采用目录层级，然后用规则文件。** 每一条接口信息，先问「目录层级
> 能不能表达」；能，就让层级表达，不另造规则。只有层级表达不了的，才落到
> front matter 或独立规则文件里。§二 是这条原则的总表。
>
> 上位文档：《[顶层设计与目录调整](2026-11-18-顶层设计与目录调整.md)》的 D11、
> 《[目录即接口与分类增设](2026-11-18-目录即接口与分类增设.md)》。
> 本文不重复它们，只在两处需要勘误的地方明确写出来（见 §十二）。

## 一、这份协议不解决什么

- 不定义站点怎么构建、怎么发布、怎么同步到第三方平台。
- 不定义视频线怎么分合集、视频稿怎么写。
- 不定义 `learning-path.json` 怎么维护（它在内容层与赛道之间，不在草稿层与母稿层之间）。
- 不改 `tests/`。任何守卫（§九）都是**下一步**的事，本协议只把「要守什么」定下来。

一句话：**这一层只管稿子怎么从「在改」变成「已过审」。**

## 二、接口总表：每条信息由谁承载

载体分三档，**从前往后用**：

| 档 | 载体 | 什么时候用 |
| --- | --- | --- |
| 一 | **目录层级**（路径） | 层级能表达的全部 |
| 二 | **front matter**（稿子/索引页自己的头） | 层级表达不了的少量元数据 |
| 三 | **独立规则文件** | 层级与 front matter 都表达不了的 |

### 总表

| 接口信息 | 载体 | 层级够吗 | 说明 |
| --- | --- | --- | --- |
| 一篇文章是谁 | 相对路径 | ✓ | `drafts/X` ≡ `docs/X` |
| 它属于哪个分类 / 系列 / 站 | 目录路径 | ✓ | §三 |
| 这篇是稿子还是索引页 | 文件名 `_index.md` | ✓ | 检查器按它分流规则 |
| 这篇是稿子还是说明文件 | 文件名 `README.md` | ✓ | 说明文件**不进 `docs/`** |
| 稿子的形态（flat / bundle） | 文件名 / 目录 | ✓ | §五 |
| 它有没有过审 | 在不在 `docs/` 里 | ✓ | §二 |
| 审校记录在哪 | `review/<镜像路径>` | ✓ | §七 |
| 它在序列里的第几步 | 文件名 `NN-` 前缀 | ✓ | 作用域是**系列**，见 §三 |
| 它属于哪条赛道 | —— | ✗ | 别的层（`learning-path.json`），本协议不管 |
| 审校状态 | 记录 front matter `status` | ✗ | 二档 |
| 它审的是哪一篇 | 记录 front matter `src` | ✗ | 二档（bundle 会丢 `/index.md`） |
| 它的一句话摘要 | 稿子 front matter `description` | ✗ | 二档 |
| 分类的中文名 | 索引页 front matter `title` | ✗ | 二档。目录只给 ID，中文名在这里 |
| 期号 | 稿子 front matter `episode*` | ✗ | 二档。视频线的锚点 |
| 独立规则文件 | —— | —— | **本层一个都不需要** |

最后一行是关键结论：**草稿层与母稿层之间没有独立的规则文件**。
层级说了它是什么、属于哪、是不是过审；剩下的几件小事（状态、摘要、中文名、
期号）装在各自的 front matter 里。

如果哪天需要一份独立规则文件，那件事多半**不属于这一层**——
比如「这篇属于哪条赛道」是内容层与赛道层之间的缝。

## 三、两层的语义与坐标

### 两层

| | `drafts/` | `docs/` |
| --- | --- | --- |
| 定位 | 工作区 | 已过审母稿的唯一落点 |
| 允许的状态 | 完整 / 半成品 / 缺素材 | **只有已过审** |
| 允许「未过审」吗 | 允许，这就是它存在的意义 | **不允许** |
| 谁写 | 作者与协作者 | 只由「合入」动作写入 |
| 方向 | → | ←（单向） |

**方向是单向的。** 改动先落 `drafts/`，过审后复制进 `docs/`。
不允许从 `docs/` 往回改稿——往回改等于绕过审校。

`docs/` 里**没有「未过审」这个状态**。这不是约定，是不变量：
`docs/` 里每一个稿子都必须能指向一份「审校状态：已合入」的审校记录。

### 坐标：层级的每一段是什么意思

```
drafts/<分类>/<系列>/<站>/<篇>.md
         │    │   │   │
                      └ 篇
                  └ 站
              └ 系列
         └ 分类
   └ 草稿层
```

| 段 | 是什么 | 实测 |
| --- | --- | --- |
| 分类（一级目录） | 一条线 | 清空前是 6 条：distributed / engineering / life / notes / platform-meta / source-tracks，每条都有 `_index.md`；草稿箱已清空，目录按需新建 |
| 系列（二级目录） | 一条线下的一个大方向 | 32 个，30 个有 `_index.md` |
| 站（三级目录） | 系列下面的一站 | PostgreSQL 这条线铺满了 8 个站（`getting-started` / `index-and-query` / …），每站一个 `_index.md` |
| 篇（文件或目录） | 一篇文章 | 426 篇扁平 + 136 篇 bundle |

**层级深度按线而定**：PostgreSQL 是四层（分类 → 系列 → 站 → 篇），
别的线目前多为三层。层级可以先空着，但**索引链不能断**（§六）。

### 序列目录 `learning-path/`

站下面可以再开一个 `learning-path/` 目录，放这条线**有先后顺序**的步骤：

```
drafts/<分类>/<系列>/
  <站>/
    learning-path/
      01-build-and-codebase.md
      02-process-architecture.md
```

- 文件名的 `NN-` 前缀就是序号，**顺序由层级表达**。
- **序号的作用域是系列**，不是站：PostgreSQL 全系列 01–14 连续、无洞、无重复
  （实测），步骤按站分布——01/02 在起步与全景，03/07 在索引与查询，
  04/05 在存储引擎，06/08 在事务与并发，09/11 在 WAL 与恢复，
  10/14 在扩展与性能，12 在复制与高可用，13 在逻辑复制。
- 「作用域是系列」这件事**路径表达不了**，它是一条规则，写在本文 §三 里，
  不另立规则文件。

不在 `learning-path/` 里的稿子是**专题篇**，不参与编号。
本文的样例《postgresql 基操》就是一篇专题篇——
它放在 `getting-started/` 下，不进 `learning-path/`。

## 四、四类文件

按**层级位置与内容性质**分，不按扩展名单一刀切：

| 类 | 判定 | 内容 | 要过审吗 | 进 `docs/` 吗 |
| --- | --- | --- | --- | --- |
| **稿子** | `.md`，不是 `_index.md` / `README.md` | 文章正文 | **要**，逐篇 | 是 |
| **索引页** | 文件名 `_index.md` | 目录索引 | **要**，规则见 §六 | 是 |
| **说明文件** | 文件名 `README.md` | 给人和协作者看的说明 | 不要 | **否** |
| **素材** | 一切非 `.md` 文件 | 图片、代码、附件 | 不审内容 | 随稿子走 |

两点要说清楚：

1. **分类只存在于目录里，中文名在索引页的 front matter。** 目录给的是 ID
   （`source-tracks`），中文名（「源码主线」）在 `docs/source-tracks/_index.md`
   的 `title:`。分类只声明一遍。
2. **说明文件不进 `docs/`。** `drafts/` 现在只有 1 个 `README.md`
   （`drafts/README.md`；那几棵镜像树里的说明文件已随内容清空删除），
   它是工作区的说明，不是对外内容。
   `docs/` 里一个都不该有——站点会把 `docs/` 下每个 `.md` 都当文章发出去。

### 素材的归属

一个素材文件属于**引用它的那篇稿子**。判定是机械的：正文里的 Markdown
图片引用与链接。

实测：426 篇扁平稿里只有 18 个目录含图片引用，**悬空引用 0 条**；
孤儿图片 19 个（另有大批 vendored 树，如 `theme-example-Sierra/`、
`docker_image/`，本来就不是文章素材）。

所以**目录不是素材的边界，引用才是**。这直接否掉了「整树 rsync」——
它会把同目录下没审的稿子一起搬进 `docs/`。

## 五、复制单元：不是「复制这一个文件」

「复制这一个文件」这句话对扁平稿成立，对 bundle 和带素材的稿子不成立。
精确化：

| 稿子形态 | 复制单元 | 复制内容 |
| --- | --- | --- |
| 扁平 `<名>.md`，无素材 | 1 个文件 | `<名>.md` |
| 扁平 `<名>.md`，引用了同目录素材 | 1 个文件 + N 个素材 | `<名>.md` + 它引用到的**同目录**素材 |
| bundle `<名>/index.md` | **1 个目录** | `<名>/` 整个目录（`index.md` + 自带素材） |
| 索引页 `_index.md` | 1 个文件 | `_index.md` |

### 形态不转换

**实测（2026-11-18）**：`drafts/` 与 `docs/` 是**同形镜像**——
426 篇扁平 + 136 篇 bundle，两边完全一致，零个名字冲突。

**裁决：形状不转换。** `drafts/` 的形状就是 `docs/` 的形状。

理由：

1. 转换要改 426 个文件名，而稿子之间全是相对链接——改形状就是改链接，
   426 篇的相对链接改写是一个必然出错、且错了不易发现的动作。
2. 形状不一致本身就是「两棵树对不上」的故障源。同形镜像的校验是
   `diff -r` 一次的事，异形则需要一张映射表，而映射表必然腐烂。
3. bundle 形态本身有用：136 个 bundle 里有 8 个自带图片
   （`image-1.png` 等），目录就是它的素材边界。

> **对《目录即接口与分类增设》§二的勘误**：那一节写
> `drafts/<期号>.md` → `docs/<期号>/index.md`（flat → bundle）。
> 这条**与实际不符**，按本文改为**同形**。原句应视为笔误，
> 不是一条待实施的迁移计划。

### 形态怎么选（给以后新增稿用）

- **扁平**（`<名>.md`）：稿子没有专属素材，或素材放在公共位置。
- **bundle**（`<名>/index.md`）：稿子有**专属**素材，或带 `episode:` 字段。

两种形态**不冲突**（0 篇同名）。将来若冲突，以 bundle 为准
（把扁平那个改名为 `<名>-文.md` 之类），不要让两棵树都猜。

## 六、分类页：唯一允许两边不同的

索引页也是稿子，也要过审，但它的规则不同。

**规则 1：索引页列的东西必须都已过审。**
`docs/` 里没有的稿子，不能出现在 `docs/` 的索引页里，否则站内链接是死链。
索引页与它列的东西要**一起过审**。

**规则 2：索引页在 `drafts/` 与 `docs/` 里允许内容不同。**
这是**唯一**允许两边不一致的稿子类型。

- `drafts/` 的索引页 = 在改的版本（全量策展、待补的条目）
- `docs/` 的索引页 = 已过审的版本（只列已过审的东西）

理由：索引页的内容是「当前已过审集合」的投影。它**必然**落后于
`drafts/` 里的策展——除非全部母稿都过审了。允许两边不同，
是让这件事显式化，而不是让它变成一个 bug。

> 其余所有稿子（扁平与 bundle）过审后，两边**逐字节一致**。
> 这条是守卫 G-05 的依据。

**规则 3：索引页的清单应当派生，不是手写。**
手工维护的清单，漏一行就是站内少一条链接，多一行就是死链。
「应当派生」属于构建层，是下一步；但**协议层先立规矩**：
索引页过审时，它的清单必须与「`docs/` 里实际存在的东西」**完全一致**，
不多不少。核对手工。

**规则 4：索引链不能断。**
分类页 → 系列页 → 站页 → 篇，一环都不能少。
层级的深度可以按线而定（有的线只有三层），但**每一级的索引页都要在上一级里被列出**。

## 七、审校记录

审校记录放在 `review/`，与稿子在同一棵相对树上：

| 稿子 | 审校记录 |
| --- | --- |
| `drafts/a/b/c.md` | `review/a/b/c.md` |
| `drafts/a/b/c/index.md` | `review/a/b/c.md`（**丢掉 `/index.md`**） |
| `drafts/a/b/_index.md` | `review/a/b/_index.md`（**保留 `_index.md`**） |

两条不冲突：bundle 稿的记录是 `c.md`，索引页的记录是 `_index.md`。
素材目录与说明文件不需要审校记录。

### front matter

记录的头是**机器可读的那一半**：

```yaml
---
status: 已合入
src: source-tracks/postgresql/getting-started/postgresql基操.md
---
```

| 字段 | 取值 | 谁用 |
| --- | --- | --- |
| `status` | `建议中` / `已确认` / `已合入` | 守卫 G-01 |
| `src` | 相对 `drafts/` 的路径 | 记录是从哪一篇来的 |

`src` 之所以要写，是因为**层级表达不了它**：记录的路径是 `review/<镜像路径>`，
而 bundle 形态的稿子（`<名>/index.md`）的记录是 `<名>.md`——少了 `/index.md`，
从记录路径反推不出源路径。扁平稿与索引页能反推，但统一写上省掉分支。

正文里原来那行 `- 审校状态：…` 不再重复写——它在 front matter 里，
两处写会漂。

其余内容按 `review/README.md` 的模板写。**事实待核**的三条标记语义也在那里：
`- [x]`（已核）、`- [不适用]`（本次没改，不阻塞）、未销掉的（**阻塞「已合入」**）。

## 八、流程：每一步靠什么承载

| 步 | 做什么 | 靠层级 | 靠规则文件 |
| --- | --- | --- | --- |
| 1 | 在 `drafts/<分类>/<系列>/<站>/<篇>.md` 写稿 | ✓ 路径就是位置 | `description` 写一句话 |
| 2 | 在 `review/<镜像路径>` 写审校记录 | ✓ 记录跟着稿子走 | `status` / `src` |
| 3 | 跑机械检查 `tools/review-check.py` | ✓ 文件名决定跑哪套规则 | 判据词表在脚本里 |
| 4 | 合入：把**复制单元**复制进 `docs/` 同相对路径 | ✓ | — |
| 5 | 更新索引链：所在站页 → 系列页 → 分类页 | ✓ 链就是层级 | 清单内容是手写的（暂时） |
| 6 | 查守卫 G-01~G-08 | ✓ | `status` / `src` |

第 3 步是**人工审校之外的第二道**。判据在脚本里，稿子服从判据——
但反过来也一样：判据漏了一种正当写法，就该改判据，不该让每一篇都去迁就。
（这条例外要有据可依：本文 §十一 记了本轮实际发生的一次。）

第 5 步「索引链」是这次跑流程才发现的：**一篇稿子过审了，不等于读者能走到它**。
顶层分类页漏列系列，链就断在第一环。

## 九、守卫：现在一个都没有

实测：`tools/` 里只有 `review-check.py` 和 `draft-descriptions.py` 提到 `drafts/`；
5 个 workflow 里**没有任何针对 `drafts/` 的检查**。
§二 的不变量（`docs/` 里只有已过审内容）**目前没有任何机器保障**。

| 编号 | 守什么 | 判据 | 数据来源 |
| --- | --- | --- | --- |
| G-01 | `docs/` 里每个稿子都有「已合入」的审校记录 | 记录存在且 `status: 已合入` | 记录 front matter |
| G-02 | `docs/` 里每个索引页都有「已合入」的审校记录 | 同上 | 记录 front matter |
| G-03 | 稿子引用的素材跟着进了 `docs/` | 正文里的相对引用在 `docs/` 侧解析得到 | 层级 + 正文 |
| G-04 | 索引页的链接不悬空 | 每条站内链接，`docs/` 里有对应文件 | 层级 |
| G-05 | 已过审的稿子两边逐字节一致 | 扁平/bundle 稿：`diff` 无差异 | 层级 |
| G-06 | 形状一致 | `drafts/` 的 `foo.md` 对 `docs/` 的 `foo.md`；`foo/index.md` 对 `foo/index.md` | 层级 |
| G-07 | `episode:` 一致 | 同一篇稿子两边的 `episode*` 相同 | front matter |
| G-08 | 不越级写入 | `docs/` 里不得出现 `drafts/` 没有的稿子 | 层级 |
| G-09 | 索引链不断 | `docs/` 里每一级索引页都在上一级被列出 | 层级 |

G-05 **不适用于索引页**——§六 规则 2 明确允许索引页两边不同。
这条例外是 G-05 唯一需要小心的地方。

G-03 是唯一有点难的：扁平稿的素材可能在同目录，也可能在别处，
判定要靠解析正文引用。bundle 形态因为目录就是边界，G-03 在 bundle 上是平凡的。

G-09 是这次跑流程才补上的：稿子过审不等于读者能走到它。

## 十、以《postgresql 基操》走一遍

这是本文档的**样例**：一篇稿子从写出来到进 `docs/` 的完整路径。
每一步标出「靠层级」还是「靠规则文件」。

### 样例的坐标

```
drafts/<分类>/<系列>/<站>/<篇>.md
        └ 分类 └ 系列 └ 站 └ 篇（专题篇，不在 learning-path/ 里）
```

### 步 1 · 写

稿子落在 `drafts/` 下与母稿同相对路径的那一份（目录即接口，按需新建）。
**层级**定死了它属于「源码主线 / PostgreSQL / 起步与全景」。
front matter 里写 `description`（索引页的一句话就靠它）。

稿子形态选**扁平**：这篇没有专属素材。

### 步 2 · 审

审校记录落 `review/` 下与稿子同相对路径的那一份（规范见 `review/README.md`，
索引见 `review/INDEX.md`）——路径与稿子**镜像**。
front matter 写 `status: 已合入` 与 `src:`（指向那篇稿子）。

审出 13 条优先修改，其中 5 条是**事实硬错误**，逐条对过
PostgreSQL 17.4 源码（`/work/cwork/postgresql`，`REL_17_4-106-ga5b535fe0ad`）：

- 「视图是表的一部分在内存中的缓存」——硬错。视图是存下来的查询，没有物理存储

### 步 3 · 机械检查

```bash
python3 tools/review-check.py drafts/         # 草稿箱里那一篇（目录即接口，按需新建）
```

第一遍报了 2 个信号：STR-02（开头没说明解决什么问题）、STR-03（结尾没产物）。
人工审校时这两处其实都做了——开头有「这篇解决什么」，结尾有「三件最容易搞错的事」。
**是判据不认这两种说法。**

判据在规则文件那一层，稿子服从判据：

- 「## 这篇解决什么」→「## **本文**解决什么」（命中 `POSITIONING_RE`）
- 「## 收尾：三件最容易搞错的事」→「## **小结**：三件最容易搞错的事」（命中 `TAKEAWAY_WORDS`）

改完零信号。

> **这一轮同时改的是规则文件本身**：`tools/review-check.py` 原来把稿子的规则
> 套到索引页上，于是每张索引页都被报「缺编写人信息表」「二级章节不足 3 个」
> 「技术深度只命中 1/5」。索引页是一张清单，那些判据对它不适用。
> 改法是按**文件名**分流：`_index.md` 走索引页规则，其余 `.md` 走稿子规则。
> 分流依据同样来自层级。

## 十一、本轮实际发生的一次判据调整

记在这里，因为它是「规则文件那一层」怎么用的实例：

> 稿子写了「这篇解决什么」和「收尾：三件最容易搞错的事」，人工审认为都到位，
> 但 `tools/review-check.py` 只认 `POSITIONING_RE`（`本文…解决`）和
> `TAKEAWAY_WORDS`（含「小结」「清单」「排查」…），于是报 STR-02 与 STR-03。

处理办法是**改稿子**（改成判据认的说法），不是改判据——因为判据本身覆盖得够宽
（「小结」本来就在词表里），是这两篇用了词表外的说法。

**什么时候该反过来改判据**：当一种写法正当、普遍、且检查器漏了它。
本轮就发生过一次——索引页被套上稿子的判据。那是判据用错了地方，
所以改成按层级分流，而不是往词表里堆词。
