# review/specs/ —— 审校判据与架构规格（权威文档）

> **这是什么**：**什么算「已过审」的权威判据**所在地。一条稿子要进 `docs/`/`video/`，
> 得过这里的判据；模块边界、接口协议、架构现状也写在这里。判据是**文档，不是测试**——
> 测试只是把其中可计算的部分变成断言。

---

## 一、结构

```
review/specs/
├── 2026-11-*.md        # 按日期命名的判据与设计文档（接口协议、目录架构、整体边界…）
├── ops/                # 运维与重构方案（部署、同步公众号、html/md 版本管理…）
└── platform/           # 平台/流水线相关的判据（video-line / multiplatform / content-model …）
```

- 根级文件是**主线判据**：如 `2026-11-19-整体架构与模块边界.md`（架构现状与欠账）、
  `2026-11-18-草稿层与母稿层的接口协议.md`、`2026-11-18-顶层设计与目录调整.md`。
- `ops/` 管运维侧，`platform/` 管各平台/各流水线的判据（见 `_index.md`）。

## 二、AI 如何使用本目录

- **改任何内容前，先读这里的判据**——它决定你的改动合不合格。
- 判据文档**不下结论为测试**：读上下文的人（AI）判断是否「空泛」「够不够深」；
  只有可机械计算的指标才固化成 [`../../tools/review-check.py`](../../tools/) 的信号。
- 新增判据 → 用 `YYYY-MM-DD-主题.md` 命名，与既有文件不冲突。
- 这份目录是**审校层的核心**，[`../README.md`](../README.md) 是审校层的总入口。
