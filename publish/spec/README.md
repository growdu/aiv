# publish/spec/ —— 契约的权威规格

> **这是什么**：发布契约的**权威文档**。这里是「契约长什么样」的唯一真相——
> 代码（`../publishkit/`）是这些规格的实现，规格变了代码跟着改，不是反过来。

---

## 一、规格清单

| 文件 | 是什么 |

| `00-架构设计.md` | **总纲**：模块边界、四条缝、依赖方向、内容契约字段表（§4.1/§4.2）、退出码 |

## 二、AI 如何使用本目录

- 改发布逻辑前，**先读 `00-架构设计.md`**——它定义模块边界与依赖方向，是契约层的宪法。
- 这里是**判据文档，不是测试**：规格说「必须怎样」，测试只是把其中可计算的部分变成断言。
- 改内容契约字段 → 改 `00-架构设计.md` §4.1/§4.2，再改 `../publishkit/contract.py` 的实现，
  让两边一致（`check-content-contract.py` 会卡违规）。
- 新增一份规格 → 在根目录用 `NN-主题.md` 编号，与本目录既有文件编号不冲突。
