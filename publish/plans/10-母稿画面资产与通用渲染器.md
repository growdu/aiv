> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **状态（2026-11-23 收尾）**：本计划 32 个步骤 —— 完成 **32** · 作废 **0** · 待做 **0**。
> `- [x]` = 落地了且能验证（行尾注明怎么验的）；`- [-]` = 没落地但已被后来的决定作废（行尾给原因）；
> `- [ ]` = 没落地且现在还该做。

**Goal:** 让「母稿即素材库」这句话在画面这一层成立——母稿里的 mermaid 图、代码块、表格，
不用手写场景模块，直接变成画面；章节卡与要点卡也有一份通用版式。

**Architecture:** 在 `pyv/` 下面新增一层**通用渲染器**（`pyv/generic/`），四个模块
（`gen_mermaid` / `gen_code` / `gen_table` / `gen_card`）都实现同一套渲染器接口
（`render(ctx, t, w, h, params)` + `REQUIRED`），由 `pyv/derive.py` 的
`GENERIC_RENDERERS` 按画面类型点名。**内容从母稿取**：契约里只带一个引用
（`ref = {doc, nth}`），渲染器在渲染期解析出母稿里的那一块——契约里不抄第二份内容。

**Tech Stack:** Python 3.11、cairo（已装）、pygments 2.20.0（已装）、mermaid-cli 10.9.1（经 npx，需要网络）、pytest。

**上游规格：** [../spec/09-长视频三档.md](../spec/09-长视频三档.md) §六（画面：母稿即素材库）。

## Global Constraints

- **每个 commit 完成立即提交**；每个 commit 必须配套**单元测试 + 集成测试**，
  且在**只含该 commit 内容的干净检出**上独立跑通全部测试。
- **入库的是事实，不入库的是产物。** 渲染出来的 PNG、成片、时间轴不入库；
  mermaid 的 PNG 缓存落在 `build/`（可被环境变量改到别处）。
- **不静默成功、不静默截断。** mermaid 渲染不出来时，画面上要**看得见**地
  降级（显示图表源码 + 失败原因），不许无声跳过；代码块放不下时收字号，
  收到下限还放不下就明说「还有几行没画上」。
- **阈值独立取值。** 守卫里的阈值写成**字面量**，不许 `from pyv.xxx import CONSTANT`；
  一致性由另一条测试单独钉住。
- **改完守卫要注入缺陷验它会红。**
- **层间零 import。** 视频线不许 import 平台层（`platforms/*`）的代码。
- **文案归契约，版式常量留代码。** 通用渲染器里不许写死中文文案；
  系统提示用 ASCII（内置字体是按「仓库用到的字符」子集化的，
  往画面模块里加汉字就意味着要重跑字体子集脚本）。
- **中文 commit message 不用 bash heredoc。** 写 `/tmp/msg*.txt`，再 `git commit -F`；
  提交后按码位查 `U+FFFD`。
- **测试不依赖网络。**

## 关键口径（先定，再写代码）

### D1：mermaid 渲染器，视频侧自持一份

规格 §6.2 说 `gen_mermaid` 依赖「`platforms/wechat/mermaid.py` 的渲染器」。
**但视频线不能 import 平台层**（层间零 import：生产者是上游，适配器是下游）。

所以视频侧自持一份 `pyv/mermaid.py`（同样的做法：mermaid-cli 10.9.1、探测系统 Chrome、
按源码 hash 磁盘缓存、失败返回原因）。两份实现的**版本号与关键参数要对拍**——
测试**读文件**（`platforms/wechat/mermaid.py` 的源码文本），不 import 那个模块。

### D2：通用渲染器不进 `pyv/scenes/`

`pyv/scenes/` 里的每个模块都被两条按目录扫的守卫盯着：

- `tests/test_contract.py::test_the_baseline_covers_every_scene_module`
  ——逐像素基准里的渲染器集合必须**等于**目录里的模块集合；
- `tests/test_font_subset.py::test_every_visual_segment_is_covered_by_the_runtime_probe`
  ——运行时探针画的模块集合也必须**等于**目录里的模块集合。

通用渲染器的逐像素基准**要一期真实的期目录才抓得出来**（母稿内容 + 契约都得在），
而视频线今天没有期——**内容不入库**是仓库的老规矩。
硬塞进 `pyv/scenes/` 就要么往基准里塞假哈希，要么逼着作者在本机重抓一遍。

所以通用渲染器放 `pyv/generic/`，**自带一套守卫**（元素级关系守卫，
见 Task 9）：字不压字、字在自己那块底色里、两个画幅都画得出来、
画出去的字都在字体里。等有了真实期目录、基准抓得出来，再搬进 `pyv/scenes/`。

**这是对规格 §6.1「新增四个通用渲染器（`video/pipeline/pyv/scenes/`）」的偏离**，
记在这里，也记在代码注释里。

### D3：内容从母稿取，契约里只带引用

契约里的画面参数带 `ref = {doc, nth}`（`doc` 相对仓库根，`nth` 是同类块里的序号）。
渲染器在渲染期解析引用，解析不到就报错（`pyv/derive.py` 在派生期已经查过一遍，
渲染期再查一次是防「派生之后母稿被改了」）。

### D4：降级要看得见

mermaid 渲染失败（约 8% 的图会失败，规格 §6.2）时，画面上要画出**图表源码**
与**失败原因**，不许静默跳过——跳过会让观众看到一段没有画面的旁白。

### D5：两个画幅都要画得出来

横版 1920×1080（视频号 / B站）与竖版 1080×1920（抖音）都必须能用。
竖版的四条规矩见 `pyv/layout.py` 的 `V`：字号不缩、框变宽、每行字过一遍 `fit_size`、
底部只留字幕。

### D6：mermaid 的 PNG 缓存

默认落在 `video/pipeline/build/mermaid/`（产物，不入库），可用环境变量
`PYV_MERMAID_CACHE` 指到别处。缓存键是源码的 sha256 前 16 位。
