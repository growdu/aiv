# 竖版（抖音档）版式改造：右侧安全区 + 内容集中

**日期**：2026-11-15
**范围**：`aiv/pipeline/pyv/scene_layout.py` 与各场景的竖版画法
**不动**：横版（1920×1080）一个字都不改——横版发的是视频号/B站，不叠平台 UI

---

## 一、为什么改

从 `aiv/out/pg-parallel-decode__vertical.mp4` 抽帧（每 4 秒一帧）看下来，
竖版有五个实打实的问题：

1. **画面下缘 25%–38% 全是空白。** 内容区只排到 `0.645`（1238px），
   字幕烧在 1393–1450，再往下 420px 让给抖音 UI——**真正能用的只有上 60%**。
   s03（核阵列）那场最极端：内容到 59% 就结束了，下面 41% 是白纸。
2. **元素显小，流程读不出来。** s04 的三条带之间各留 154px / 144px 白，
   箭头细长，链路像三段不相干的图。
3. **右下角文字会被平台 UI 挡住。** 内容右缘到 x=1015，而抖音的点赞/评论/
   分享栏正落在右下——s04 的「收口输出」就在那个位置。
4. **底部两行字打架。** 说明行（caption）与字幕上下紧挨，而两者的内容
   往往是一句话（csn/s02 说明「按时间戳排，并不可靠」，字幕「并发提交
   时间顺序不可靠」）。
5. **主流程被拆散。** s03 是「核阵列 / 只用到 1 核 / 大事务 / 小事务高并发 /
   都跟不上」五个互不相干的行；s04 是三条带加两段白。谁是主角不明确。

## 二、平台 UI 预留是工程保守值

抖音没有公开的「安全区」规格。下面两个数字都是**工程上的保守取值**，
不是平台文档里的数字——与其等审核时才发现被压住，不如自己留出：

| 预留 | 取值 | 依据 |
| --- | --- | --- |
| 底部（文案区 + 导航栏） | 420px（`palette.VERTICAL_UI_BOTTOM`） | 已有的保守取值，字幕就烧在它上面 |
| 右侧（点赞/评论/分享栏） | 120px | 栏位在 1080 宽画面的右下角，取一条保守窄带 |

## 三、共用版式：从三条规矩到四条

规矩写在 `pyv/scene_layout.py`——各场景各写各的版式，**规矩不许各写各的**。

### 规矩一：字号不缩，框变宽（不变）

竖版画布只有 1080 宽，横版是 1920。同一档字号在竖版里相对画面更大——
手机上看，文字要顶得住。相应地，框要占满宽度，元素改成纵向堆叠。

### 规矩二：字要放得下（不变）

统一用 `fit_size()` 收字号——**宁可字小一点，也不能出框**。

### 规矩三（新增）：底部只留字幕

竖版**不再画说明行**。底部那一行字是字幕的位置：说明行与字幕讲的是同一句话，
两行叠在下面只会互相干扰（s02 的字幕甚至和标题一字不差）。

- 横版的说明行**保留**——横版底部没有字幕，也没有平台 UI。
- 各场景竖版里的 `scene_layout.caption(...)` 调用一并删掉（六个期共 25 处）。
- 契约里的 `caption` 字段**不动**：横版还在用它。

### 规矩四（新增）：右侧让出按钮栏

内容右缘收到 x=960（1080 − 120）。左边距不变（65px），
所以内容宽度从 950 收到 895——**窄 55px，换右下角不被挡住**。

### 竖版的四个位置（比例相对画面高度 1920）

| 位置 | 旧 | 新 | 像素 | 说明 |
| --- | --- | --- | --- | --- |
| 标题基线 | 0.085 | **0.075** | 144 | 所有场景统一 |
| 内容区上沿 | 0.125 | **0.130** | 250 | 内容从这里开始 |
| 内容区下沿 | 0.645 | **0.700** | 1344 | 内容到这里为止（字幕带 1393 起） |
| 字幕带 | 1393 | 1393 | — | 不变 |

标题字号 64 → **68**。内容下沿与字幕带之间留 49px 余量。

## 四、s03 / s04 重排

这两个是「内容分散」的主因：结构本身让主线读不出来，光调常量救不了。

### s03 核阵列（`pyv/scenes/s03_cores.py`）

横版是「左核阵列 + 右压力」左右分栏；竖版上下堆叠之后变成五个孤立的行。
改法：**两组压力并排放**，变成「一片核 + 一个对比 + 一句结论」三块。

| 块 | 旧 | 新 |
| --- | --- | --- |
| 核阵列 8×4 | 格 92×80，间距 24/18，250–614 | 格 96×88，间距 18/20，**250–662** |
| 只用到 1 核 | 纯文字，y=685 | 浅橙底 chip，48 粗，**700–776** |
| 大事务 / 小事务高并发 | 上下堆叠，770–1083 | **两列并排**，417 宽 + 60 列距，830–1200 |
| 都跟不上 | 52 粗，y=1165 | **60 粗**，y=1290 |

小块从一行 7 个改成 4+3 两行（93×130），才排得进 417 宽的列里。

### s04 三层线程拓扑（`pyv/scenes/s04_parallel.py`）

横版是「来源在左、分支在中、汇聚在右」三栏并排；竖版改成上下三段后，
三条带之间各留一大段白，链路断了。

| 块 | 旧 | 新 |
| --- | --- | --- |
| reader 带 | 0.140–0.220（154） | **250–530（280）** |
| 箭头段 1 | 0.220–0.300（154 空档） | **530–630（100）** |
| worker 卡 ×4 | 0.300–0.440（269 高） | **630–930（300 高）**，标签 40 粗居中 |
| 箭头段 2 | 0.440–0.515（144 空档） | **930–1030（100）** |
| walsender 带 | 0.515–0.595（154） | **1030–1310（280）** |

箭头段从 154/144 收到 100，链路连成一条；带高从 154 涨到 280，
文字（"reader" 48→52、"读 WAL" 30→34）也放得下。

## 五、守卫（`tests/test_vertical_layout.py`）

竖版画面有两条底线，再加两条新规矩：

| 守卫 | 判据 |
| --- | --- |
| 不许被裁（原有） | 墨迹不碰画布四边（留 3px） |
| 不许压字幕（原有，收紧） | 墨迹下缘 **≤ 1344**（原 1393） |
| 不许进按钮栏（新增） | 墨迹右缘 **≤ 960** |
| 规矩写在代码里（加强） | `scene_layout.py` 必须写明「右侧」与「字幕」 |

## 六、验证

1. `make test`：aiv 套件（Windows 基线 953 passed / 5 failed / 16 skipped，
   5 个失败是仓库原有的 Windows 兼容问题，不是回归）。
2. `make vertical` 重出竖版成片 → 抽帧逐场对比改前改后。
3. 横版：代码路径未动 + 横版用例全绿。

## 七、不做什么

- 不改横版，不改契约文案，不改字幕文案。
- 不改品牌片（竖版本来就不套品牌片）。
- 不动抖音 UI 预留的保守取值——那是另一件事（有实测再改）。
