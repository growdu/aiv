# 设计：视频审核（Video Review）落地机制

- 日期：2026-11-16
- 范围：`video/` 视频生产线（`video/pipeline/`）产出的成片（一期 = 一个档位目录）
- 规范来源：[../README.md](../README.md)（唯一权威，本文只描述「怎么落地」）
- 状态：已批准

---

## 1. 背景

文档侧有一套成熟的审校机制（`review/README.md` + `tools/review-check.py` + `review/INDEX.md` +
`review/<支柱>/<slug>.md`）：**机器出信号 → 人/Agent 判断 → 落记录 → 确认后才改正文**。
它解决的是「同一篇文章今天判有 AI 味、明天判没有，谁都说不清依据」。

视频侧没有这套东西。检查散落在流水线各处，各管一段：

| 已有检查 | 位置 | 管什么 |
| --- | --- | --- |
| 人格 9 条 | `pyv/persona.py` | 口播稿的禁词、绝对化断言、能力域、句宽句长 |
| 字幕宽度与禁词 | `pyv/timeline.py` | 字幕行 ≤ 14 宽、禁止词 |
| 契约校验 | `pyv/contract.py` | 句子恰好被覆盖一次、参数齐全 |
| 文字出框与重叠 | `pyv/inkbox.py` | 墨迹包围盒、列相交 |
| 跨机版式指纹 | `pyv/fingerprint.py` | 版式一致性 |
| 平台技术门槛 | `pyv/preflight.py` | 分辨率、码率、关键帧、faststart |
| 混音验收 | `pyv/bgm.py` | 稳态 duck 深度、电平差、真峰值 |
| 发布元数据 | `pyv/epmeta.py` | 标题、简介、封面、各平台字段 |

**问题不是「没有检查」，是「没有一个入口、没有一个结论、没有一条状态机」**：
出片之后要人工把七八个命令挨个跑一遍，结论散在终端里，
「这一期审过没有、审到什么程度、改了哪里」没有地方查。

## 2. 目标与非目标

**目标**：把成片审核做成一件和文档审校同构的事——

1. 一个**确定性检查器**，只出信号、不下结论，两层分开：
   **文本层**（口播稿 / 字幕表 / 画面契约）与**成片层**（抽帧 / 音轨 / 技术参数）；
2. 一套**记录契约与进度表**，让「一期一条记录、状态可查、确认后才改」变成机器可校验的约定；
3. 一个**抽帧给人看**的环节——机械信号查不出「画面讲得清不清」。

**非目标（明确不做）**：

- 不让审核器自动改稿或自动改渲染代码（与文档侧同一条纪律：两阶段，确认后才落地）；
- 不引入 LLM API 调用（仓库无凭据基础设施，模型不可复现）；
- 不审「画面好不好看」这类审美判断（那是人的事，工具只负责把值得看一眼的地方标出来）；
- 不把成片审核塞进 CI——CI 只跑契约测试，成片审核要本机的成片产物。

## 3. 架构

```
video/episodes/<期路径>/口播稿.md ────┐
video/episodes/<期路径>/contract.json ┼──► [文本层 VT-*] ──┐
video/选题库.md（母稿·出处）──────────┘                    │
                                                   ├──► 审核报告（信号 + 显式说明跳过了什么）
video/out/<期路径压平>.mp4 ──────────► [成片层 VV-*] ──┘              │
       └─ 抽帧 ───────────────────► [抽帧清单] ─► Agent/人看画面
                                                                  │
                                                                  ▼
                                    video/episodes/<期路径>/review.md
                                                                  │
                                                            [你确认]
                                                                  ▼
                                            改稿 / 改代码 → 重出片 → 状态推进
```

**期路径**：一期 = 一个档位目录，期路径就是它相对 `video/episodes/` 的四段
`系列/合集/文档/档位`；**期路径压平** = 把斜杠换成连字符后的一个片段，
`video/out/` 与 `video/build/` 里的文件名用它。

### 3.1 为什么分两层，不做成「一个审核器出完整结论」

与文档侧同一条理由：机械启发式（连接词密度、重复句、空白帧、静音段）适合机器，
但「这句像不像人讲」「这张图讲清了没有」需要上下文和眼睛。

工具只出信号，判断留给人和 Agent。**这一条比省下的那点时间重要得多**——
工具的启发式一旦变成「内容的标准」，创作就被检查器牵着走了。

### 3.2 两层的关系

文本层与成片层不是并列的两套检查，而是**前后接力**：

| | 文本层 | 成片层 |
| --- | --- | --- |
| 审的是 | 「要讲什么」 | 「做出来是什么样」 |
| 输入 | 口播稿、字幕表、契约、母稿 | 成片 mp4、时间轴 |
| 查得出 | AI 味、数字没出处、字幕丢数字 | 画面空白、字幕没烧上、旁白断音、时长/关键帧/电平 |
| 查不出 | 画面讲得清不清 | 文案腔调 |
| 改完要 | 改稿 → 重新 align → 重新出片 | 改渲染代码 → 重新出片 |

**改稿会改到画面**：文本层判红 → 改口播稿 → 契约的句子数/覆盖关系可能变 →
`align` 重算时间轴 → 片段重渲。**所以文本层的结论必须落回成片层再审一遍**，
只审文本不审成片，等于审了一份没出片的稿子。

### 3.3 抽帧清单：稀疏，不逐帧

抽帧策略：**每个视觉段抽 2 帧（段中点 + 段尾 85%）**，加**每个关键帧**。

- 逐帧扫描不可行（35 秒 24fps = 840 帧，完整版 18 分钟 = 2.6 万帧）；
- 段中点是最可能「画面已经画完、字幕已经烧上」的时刻；
- 段尾帧补上「结论还在淡入」的时段——**各场景的结论都在段内 48%~84%
  之间淡入**，只抽中点会把动画中间态当成「漏字」（实测：段中点上结论框
  已经画出来了，框里的字还没显影；到段尾才完整——**段尾帧才是「结论淡完之后」的样子**）；
- 关键帧是编码器的切分点，往往正好是段边界——**段边界是最容易出错的地方**
  （前一段的最后一帧没画完、后一段的第一帧没接上）。

**段的归属按成片的帧网格算，不按时间轴上的名义秒**：时间轴上的段边界是
浮点秒，成片却是按帧拼起来的（每段 `round(duration * fps)` 帧），真实切点
比名义值早最多一帧（24fps 下 42 ms）且逐段累积；关键帧常常正好落在真实切点上。
按名义秒归属，清单会把「下一段的画面」拿去核对「上一段的文案」，
一整片假漏字（实测这样错判的关键帧不止一处）。

抽帧产物（PNG）不入库（`video/.gitignore` 已拦 `frames/`），入库的是**清单**：
每帧对应哪一段、什么时间码、这段**应该**出现什么文案。清单是给人看的对照表。

「应该出现什么」从**契约的 `params` 递归摊平**里取所有字符串——契约里的文案
不只在顶层（`s03.modes`、`s05.bit_labels` 都是嵌套列表），只取顶层会漏掉
一半以上该有的字。

## 4. 检查器：`video/pipeline/pyv/review.py`

### 4.1 契约

- 纯标准库 + PIL（读抽帧的像素）；与 `pyv/` 其余模块一致，不引新依赖；
- **只读**：不修改任何被检文件，不写仓库内文件（帧与报告写到指定目录）；
- **信号不是门禁**：命中信号不返回非零退出码。历史问题不该永久卡住流水线。

### 4.2 CLI

```bash
python -m pyv.cli review text   --episode <期路径>
python -m pyv.cli review text   --episode <期路径> --json
python -m pyv.cli review video  --episode <期路径> --json
python -m pyv.cli review frames --episode <期路径> --out /tmp/frames
```

- `--json`：输出 JSON；默认输出人读摘要。
- `--episode`：期路径（`系列/合集/文档/档位`，相对 `video/episodes/`）。
  走 Makefile 时是 `make review-text EP=<期路径>`（同 `review-video` / `review-frames`）。
- 退出码：`0` 正常；`1` 参数或 IO 错误。**信号本身不导致非零退出。**

### 4.3 规则集

编号一经发布不再变更。文本层 `VT-*`（Video Text），成片层 `VV-*`（Video Visual）。

#### 文本层

| 编号 | 判据 | 严重级 | 对应文档侧 |
| --- | --- | --- | --- |
| `VT-01` | **句首以连接词开头**的句占比 > 15%（词表与 `tools/review-check.py` 的 `CONNECTORS` 相同） | warn | `AIF-01` |
| `VT-02` | **空泛评价**（`VAGUE_WORDS`）出现在句中，且该句无数字 | warn | `AIF-02` |
| `VT-03` | 结尾三句出现**泛化收尾语**（`GENERIC_ENDINGS` / 「随着…的发展」） | warn | `AIF-04` |
| `VT-04` | **近似重复句**（difflib ≥ 0.85，长度与中文字数门槛同 `AIF-05`） | warn | `AIF-05` |
| `VT-05` | 口播里的**数字在母稿与出处表里找不到** | warn | 视频独有 |
| `VT-06` | 口播句里的数字**在对应字幕里丢了** | warn | 视频独有 |
| `VT-07` | **源字幕表**（`video/episodes/<期路径>/口播稿.md` 的「字幕文本」节）里有禁止词或单行超宽 | error | `timeline.BANNED_SUBSTRINGS` / `MAX_SUBTITLE_LINE` |

`VT-01`~`VT-04` 与文档侧规则**一一对应且口径相同**——词表与阈值是**同一份常量**
（`pyv/review.py` 从 `tools/review-check.py` 借词表时必须抄同一份字面量，
一致性由 `video/pipeline/tests/test_review.py` 单独钉住，见 §4.5）。

**为什么视频侧没有 `AIF-03`（超长段落）**：口播稿一句一意群，段落级的长度判断
换成**句长**（`persona.sentence-length` 已经在管），不重复造。

**为什么只搬 `AIF-01`/`02`/`04`/`05`，不搬 `STR-*`/`MET-*`/`DEP-*`**：
后三组判的是**文章形态**——开头 5 段有没有说明问题、结尾有没有可带走的产物、
有没有「编写人 / 编写内容 / 编写时间」信息表。短视频里没有这些形态。
在口播稿上试过（`python tools/review-check.py video/episodes/<期路径>/口播稿.md`）：
搬过来的 `AIF-*` 四条确实一条都不用报；而 `STR-02`「开头 5 段没有说明文章解决什么问题」、
`STR-03`「结尾没有可带走的产物」、`MET-01`「缺少编写人信息表」条条都报——全是误报。
**能搬的是「话怎么说的」，不能搬的是「文怎么组织的」。**
（结论要在新语料上重新验一遍：语料清空之后，别拿旧语料的结论当依据。）

**为什么 `VT-07` 查的是源字幕表而不是 storyboard**：`make validate` 查的是上一次
`align` 出来的 storyboard。源字幕表改了但还没重跑 `align` 时，那个门禁看到的
还是旧字幕——改完稿没重跑 align 就出片，是最常见的「改了但没生效」。
禁止词与宽度阈值来自 `pyv/timeline.py`（唯一一份），审核层不另抄。

#### 成片层

| 编号 | 判据 | 严重级 | 复用 |
| --- | --- | --- | --- |
| `VV-01` | 抽到的帧**近乎纯色**（像素标准差过小）→ 画面漏画或黑场 | warn | 新增 |
| `VV-02` | 帧的**底部字幕带里没有暗色像素** → 字幕没烧上 | warn | 新增 |
| `VV-03` | 正文区间里**旁白中间静音** > 1.0 s | warn | 新增 |
| `VV-04` | 成片时长与时间轴**对不上**（差 > 0.15 s） | error | 新增 |
| `VV-05` | 关键帧最大间隔超限 | warn | `preflight.keyframe_gaps` |
| `VV-06` | 混音电平不合格 | warn | `bgm.measure_mix` + `check_mix` |
| `VV-07` | 平台技术门槛不合格 | error | `preflight.check_video` |

`VV-05`~`VV-07` **不重写**：直接调已有的函数，判定只有一份。
平台清单只有一个来源（`epmeta.PLATFORM_SPECS`），不在这里再抄一份。

两条口径钉在这里：

- **`VV-01`/`VV-02` 不判品牌片头/片尾的帧**。品牌片是共享素材，片头第一帧
  的黑场是淡入、不是漏画；每期都报一条假警，规则就成了噪声。跳过几帧，
  报告里写明。
- **`VV-03` 的阈值是量出来的**：语料里的句间间隙落在自然分布的一段区间里，
  0.6 s 卡在尾巴上（约两成正常换气会被误报），因此取 **1.0 s**——远小于
  一句口播的中位时长，只会在「少了一句」的时候响。阈值不许再往下压。
  一致性由 `test_narration_gaps_stay_below_the_silence_threshold` 钉住。
  （语料清空之后阈值要**重新量一遍**：以新语料量出来的分布为准，别拿旧分布当依据。）

### 4.4 「跳过」必须显式

成片层需要本机产物（成片、时间轴、旁白、BGM）。产物不在时**不静默跳过**：
报告里有一条 `notes`，写清「跳过 VV-03：旁白不在本机」。

理由与仓库其它地方一致：**「没查」和「查了没问题」是两件事，混起来就成了假装绿。**

### 4.5 阈值独立取值

守卫里的阈值写成**字面量**，不许从生产模块 import 常量；
一致性由另一条测试单独钉住。

否则生产常量一改，守卫跟着改，永远是绿的。

### 4.6 跨模块一致性钉住

`video/pipeline/tests/test_review.py` 里两条测试：

1. `test_text_rule_vocabulary_matches_the_document_checker`：
   `pyv/review.py` 的 `CONNECTORS` / `VAGUE_WORDS` / `GENERIC_ENDINGS` 与
   `tools/review-check.py` 的同名常量**逐字相同**；
2. `test_text_rule_thresholds_match_the_document_checker`：
   `CONNECTOR_RATIO` / `DUPLICATE_THRESHOLD` / `DUPLICATE_MIN_LEN` /
   `DUPLICATE_MIN_CJK` 与文档侧**数值相同**。

`tools/review-check.py` 在仓库根、不是包，测试用 `importlib` 按路径加载它。

## 5. 记录契约与进度表

### 5.1 记录

`video/episodes/<期路径>/review.md`，一篇一期。状态机与文档侧同构：

| 状态 | 含义 |
| --- | --- |
| `待审` | 还没跑检查器 |
| `已出信号` | 机器跑过了，信号进了记录 |
| `已看帧` | 抽帧清单里的每一帧都被人或 Agent 看过，结论写进记录 |
| `建议中` | 改稿/改代码的建议列出来了，等确认 |
| `已确认` | 建议被采纳，改动已定 |
| `已合入` | 改动已重出片，且成片层复审通过 |

**信号数不是「问题数」**：与文档侧同一句话——信号为 0 不等于没问题，
机械信号干净的一期照样可能需要改。

### 5.2 进度表

`video/review/INDEX.md`，一行一期：期号、标题、状态、文本层信号数、成片层信号数、
待确认项、批次。**只维护一份**，不另设队列文件。

### 5.3 边界

- `video/review/` **只记录审核过程与结论**，不是对外发布内容，不进 `docs/`；
  也不进 `video/scripts/sync_publish_docs.py` 的发布白名单
  （与文档侧 `review/` 不发布同一条纪律）；
- 审核记录里的判断必须可回溯：机器信号指向具体位置，人工判断写明理由；
- 涉及数字、版本、机制的结论必须能追到母稿。

## 6. 抽帧与 Agent 判断

### 6.1 清单格式

`review frames` 输出一份 Markdown 清单，每行一帧：

| 帧 | 时间码 | 视觉段 | 这段应该出现什么 | 口播 | 文件 |

「这段应该出现什么」从**契约的 `params`** 里抽所有字符串值（**递归摊平**，
嵌套列表里的文案也要抽）——那是画面上真正要写的字，也是判断「画面画对没有」
的对照物。

### 6.2 Agent 怎么用

Agent 逐帧读 PNG，回答三个问题，写进记录：

1. 画面上**有没有**该有的字（漏字 = 渲染 bug 或契约参数没接上）；
2. 字**对不对**（契约里的文案与画面上画的不一致 = 版式或参数错）；
3. 这一帧**讲不講得清**（画面与口播是不是一回事）。

第 3 条是机械信号查不出来的部分，也是整个审核流程里最贵的一步。

### 6.3 抽帧的已知局限

- 抽帧看不全**动效中间态**（元素飞在半空、动画没收敛）；段中点与段尾之间
  的过程抽不到；
- **段首的关键帧画面本来就是空的**（动画从零起），关键帧只能查段边界接没接错，
  不能单独用来判断「有没有漏字」；
- 字幕带的暗像素判据在**画面底部本来就有深色内容**时会漏报（假阴性）；
- 抽帧不看**音画对位**（谁的声音配哪张图）——那需要逐帧看时间轴与音轨，
  本轮不做。

**这三条写进规范**：审核结论的有效性有边界，别把它当成「成片没问题」的证明。

## 7. 与既有守卫的关系

| 已有守卫 | 审核层做什么 |
| --- | --- |
| `persona.py`（9 条） | **并入**文本层报告（不重写），审核记录里与人格结论同表 |
| `timeline.py`（字幕宽度/禁词） | `VT-07` **查源字幕表**（阈值与判定不重写），补上 storyboard 门禁看不到的那一半：源文件改了还没重跑 `align` |
| `preflight.py`（平台门槛） | `VV-07` 调用，不重写 |
| `bgm.py verify` | `VV-06` 调用，不重写 |
| `inkbox.py` / `fingerprint.py` | **不进审核层**：它们在渲染层已经卡住了（渲染前就报错） |

**不重复造轮子的判据**：一道检查如果在流水线里已经是**门禁**（渲染前就抛异常），
审核层就不必再查一遍——审核层查的是「渲染层的门禁管不到的东西」：
讲得清不清、AI 味、以及成片这个**整体**的毛病（时长、空白帧、字幕没烧上）。

## 8. 实施顺序

| 批次 | 内容 | 验收 |
| --- | --- | --- |
| 1 | 规范 + 设计 + 进度表 + 每一期的初始记录 | 文件入库，状态都是「待审」 |
| 2 | `pyv/review.py` 文本层 + CLI + Makefile + 测试 | 单测；`VT-*` 七条各有注入缺陷验证会红 |

| 4 | 实跑（文本层 + 抽帧 + Agent 看帧）+ 记录落结论 | `video/review/INDEX.md` 一行一期，状态推进 |

## 9. 风险

| 风险 | 后果 | 对策 |
| --- | --- | --- |
| 本机没有 ffprobe | 成片层整体跑不了 | `make doctor` 已报；审核层遇到缺失时显式说「跳过 VV-xx」而不是假装绿 |
| `VT-05` 数字出处误报多 | 信号噪声大 | 规则只查**带单位或两位以上**的数字；信号不是门禁；报告里列出抽取到的短语供人判断 |
| `VT-06` 字幕与口播本来就不逐字对应 | 误报 | 只报「口播里的数字在字幕里完全没有」，不报字面差异 |
| 抽帧看不清动效中间态 | 漏报 | 写进规范的已知局限（§6.3）；必要时补抽段首帧 |
| Agent 看帧的结论不可复现 | 审核不可信 | 结论必须写进记录并说明理由；机器信号是复现的那一半 |
| 审核层与流水线守卫重复 | 两处口径漂移 | `VV-*` 一律调已有函数，不重写；`VT-01`~`VT-04` 的词表与阈值由测试钉住 |
