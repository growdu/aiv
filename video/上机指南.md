# 上机指南：在一台 Linux 机器上跑通出片流水线

这条流水线原来只在 macOS 上跑得起来——不是因为代码难移植，而是因为三件事
被默认了：**字体**、**素材**、**依赖**。三件事都补齐之后，一台干净的
Ubuntu/Debian 机器 clone 完就能直接出片。

```bash
git clone https://github.com/<owner>/<repo>.git
cd <repo>

# 装依赖（需要 root）
sudo bash video/pipeline/scripts/bootstrap_linux.sh

# 自检：这台机器还缺什么、怎么补
cd video/pipeline && make doctor

# 出片（期路径 = 系列/合集/文档/档位，四层，相对 video/episodes/）
make EP=<系列>/<合集>/<文档>/<档位> align
make EP=<系列>/<合集>/<文档>/<档位> all
make EP=<系列>/<合集>/<文档>/<档位> mix-verify
```

---

## 一、装什么

`bootstrap_linux.sh` 按包管理器（apt / dnf / pacman / zypper）装齐：

| 类别 | 包 | 为什么 |
| --- | --- | --- |
| 外部工具 | `ffmpeg`（含 `ffprobe`） | 编码、拼接、混音、抽帧 |
| 外部工具 | `fontconfig` | Linux 上 cairo 靠它按字体族名解析字体 |
| 外部工具 | `make` | 流水线的入口 |
| 中文字体 | `fonts-noto-cjk` | **渲染必需**，见 §三 |
| Python | `pycairo` `numpy` `Pillow` `scipy` `pytest` | 见 `video/pipeline/requirements.txt` |

Python 依赖**优先用系统包**（`python3-cairo` 等）：pip 编译 pycairo 需要
cairo 的开发头文件，自己编译容易踩坑。系统包装不上时脚本会自动退回 pip。

装完必须自检一遍：

```bash
cd video/pipeline
make doctor
```

`doctor` 会逐项报「环境 / 素材 / 可选工具」，缺什么给什么，**每条都带可执行的
修复命令**（装哪个包、跑哪条合成命令）。有硬性缺失时退出码非 0。

## 二、素材从哪来

**素材是使用者自己的。** 立绘、曲库、品牌片、旁白——版权是他们的，
口径也是他们的，所以它们不进仓库，只在 `video/config.toml` 里声明位置：

```toml
[assets.mascot]
image = ""                  # 立绘（透明底 PNG）；空 = 不画形象
plain = ""                  # 无标牌立绘（可选）

[assets.music]
dir = "music/tracks"        # 曲库目录
bed = ""                    # 正文铺底那首；空 = 不铺 BGM
library = "music/library.json"

[assets.brand]
clips = "brand/clips"      # 品牌片（片头/片尾 mp4）
audio = "brand/audio"      # 品牌成品音轨
windows = "brand/brand_windows.json"
```

相对路径按**配置文件所在目录**（`video/`）解析，绝对路径照用。
同一个仓库要跑两套片子，用环境变量 `VIDEO_CONFIG` 指到另一份配置。

**素材缺失不是错误**：没配就是没配，流水线降级出片（不画形象 / 不铺 BGM /
不带品牌片），照样出片。**配了但文件不在**才是错——`make doctor` 会把
「压根没配」与「配了但找不到」分开报，并给出修复命令。

只有一样东西跟着仓库走：**内置字体子集**
（`video/pipeline/assets/fonts/AIVSansCJKSC-{Regular,Bold}.otf`）。
它是规则级的——两台机器用同一份字体文件，跨机的版式才一致，
见 §三。

**不入库的还有产物**：成片（`out/`）、片段（`build/`）、
时间轴（`episodes/<期路径>/storyboard.json`）、
发布包、旁本（`*.spoken.txt`）。它们由素材算出来，跟着素材走。

`video/pipeline/tests/test_assets_are_tracked.py` 盯着这件事：
内置字体与授权台账必须被跟踪，用户素材一旦被误提交，测试立刻变红。

## 三、字体：两台机器用同一份文件

**装一次就行**：

```bash
cd video/pipeline && python3 scripts/install_font.py
```

它把仓库内置的字体子集（`AIV Sans CJK SC`，上游 Noto Sans CJK SC 的
SIL OFL 1.1 子集，按仓库用到的 778 个字符子集化，Regular 320KB / Bold 328KB）
装进 **OS 认的字体目录**：

| 平台 | 装到 | 额外步骤 |
| --- | --- | --- |
| macOS | `~/Library/Fonts/` | CoreText 自动拾取（刚装完要等一两秒） |
| Linux | `~/.local/share/fonts/` | `fc-cache -f` |

**为什么不能只把字体放在仓库里**：实测（2026-11-16）cairo 在 macOS 上走
CoreText、**不认 fontconfig 目录**——字体放进 `~/.local/share/fonts/` 后
`fc-list` 找得到，cairo 的 `select_font_face` 找不到（宽度回落到 `.notdef`）。
所以必须装进 OS 的字体目录。

**装上之后，两台机器用同一份字体文件**，于是：

| | 跨机 |
| --- | --- |
| 文案、字幕、版式 | **完全一致** |
| 文字的步进宽度、收字号结果 | **一致**（同一份字体文件 + 统一关掉 hinting，实测差 ≤ 0.812px） |
| 逐像素 | **不一致**——cairo 在 macOS 走 CoreText、Linux 走 FreeType，栅格化不同 |

所以验收分两层：

| 守卫 | 在哪跑 | 守什么 |
| --- | --- | --- |
| 逐像素基准 | **作者本机**（同平台、同字体） | 画面一个字都没变 |
| 布局指纹 | **两台机器都跑** | 坐标、字号、步进宽度、轮廓包围盒——跨机可比 |

逐像素基准**绑在平台与字体上**：`tests/fixtures/scene_baseline.json` 的
`capture.font` 与 `capture.platform` 记着基准是在哪款字体、哪个平台上抓的，
换一台就跳过并说明原因，而不是红、也不是假装绿。

**跨机交给布局指纹**（`tests/test_layout_fingerprint.py`）。它记四类量——
落笔坐标、字号、步进宽度、轮廓包围盒——这四类**是字体的性质**，
不是栅格化的产物。

**这条守卫成立有两个前提**（都是 Linux CI 上暴露出来才补上的）：

1. **hinting 关掉**（`pyv/fonts.py::select_font`）。Linux 上 cairo 走
   fontconfig，默认开着 autohinter——轮廓点吸附像素网格、度量取整，
   「步进宽度」就变成了「字体文件 × 栅格化后端」的产物。实测开着时一行字
   能差 **68px**。关掉之后，FreeType 量出来的步进与字体文件的 hmtx
   **逐项相等**。
2. **粗体是真的 Bold 字形**（两个字重都入库）。只装常规字重的话，cairo 会
   **合成**粗体，而合成是各后端自己的做法：实测两个后端的轮廓包围盒差
   **3.14px**。

修好之后的跨机实测（同一份字体文件）：

| 量 | 跨机最大差 |
| --- | --- |
| 落笔坐标 x / y | **0.000** |
| 字号 | 0.027 |
| 步进宽度 | 0.812 |
| 轮廓包围盒 | 0.711 |

步进与轮廓那点差来自 **CoreText 对少数拉丁字形多给几个 em 单位**
（'A' +8、'V' +10、'Y' +13、'f' +5，单位是 1/1000 em）——字体文件本身
自洽，FreeType 严格照 hmtx 走。

所以换机器、换渲染后端，这四类量基本不变——**跨机的版式一致是可以量的**，
而跨机的像素仍然不比。容差写死在测试里（坐标 0.01px、字号 0.2px、
步进 2px、轮廓 2px），每一项都写了依据。

版式动了（字号改了、坐标挪了），指纹立刻红——这条守卫**注入验证过**
（把 `s03_cores` 的字号 +2、坐标 +3px，两次都红）。

`AIV_FONT_FAMILY=<族名>` 仍然可以显式指定字体族（最高优先级），
但**默认走内置字体**——系统字体只是退路。

想要指定别的字体就用环境变量：

```bash
AIV_FONT_FAMILY="Source Han Sans SC" make EP=<期路径> render
```

验收口径按**视觉等价**（同一套视觉系统、文案一字不变），不按逐像素一致。

### 另两处 macOS 痕迹

- `video/brand/scripts/make_audio.sh` 用了 macOS 自带的 `say` 合成片头片尾旁白，
  **Linux 上跑不了**。它是历史路径：现行做法是 `make_audio_brand.py`（纯 ffmpeg，
  跨平台），出片链路不需要这个脚本。
- `video/brand/scripts/fix_plates.py` 原本硬编码 `/System/Library/Fonts/` 下的
  Avenir Next / Hiragino Sans GB，现在参数化了：macOS 用系统字体，Linux 退到
  DejaVu Sans / Noto Sans CJK SC。

## 四、哪些脚本在 Linux 上跑不了（以及为什么没关系）

| 脚本 | 状态 | 说明 |
| --- | --- | --- |
| `video/voice/scripts/synthesize_narration.py` | **需要联网** | 调 MiniMax TTS（`mcode-tools` CLI）。每期的旁白都在本机，不合成 |
| `video/character/scripts/generate_character.py` | **需要联网** | 调图像生成。立绘是使用者的素材，不生成 |
| `video/music/scripts/fetch_music.py` | **需要联网** | 从 archive.org 下载曲库。曲库是使用者的素材，不下载 |
| `video/brand/scripts/generate_poses.py` | **需要联网** | 调图像生成。品牌片是使用者的素材，不生成 |
| `video/brand/scripts/generate_backgrounds.py` | **需要联网** | 调图像生成。同上 |
| `video/brand/scripts/make_audio.sh` | **macOS 专有** | 用 `say` 合成旁白，历史路径 |

也就是说：**出片链路（align → validate → brand → render → compose → mix-verify）
在 Linux 上完全离线可跑**。只有「重新生成素材」才需要联网与 MiniMax 账号。

## 五、常见问题

**Q：渲染时报「找不到可用的中文字体」。**
装 `fonts-noto-cjk`，然后 `fc-cache -f`；或者把任一中文字体放进
`~/.local/share/fonts/` 再 `fc-cache -f`。也可以用 `AIV_FONT_FAMILY` 指定族名。

**Q：`make: python: No such file or directory`。**
`make PY=python3 ...`（或直接 `make doctor`，它会告诉你缺什么）。仓库里的
Makefile 会自动探测 `python3`，看到这条说明你的 Makefile 是旧版。

**Q：`doctor` 说某期旁白缺失。**
它会给出合成命令。跑那条命令即可（需要联网 + `mcode-tools`）。

**Q：`doctor` 说「配了但找不到」。**
那是配置写错了：`video/config.toml` 里声明了路径，文件却不在那个位置。
改配置，或者把素材放到位——**没配**不算错（会降级出片），**配错**才算。

**Q：跑出来的画面和 macOS 上不一样。**
正常——字体不同，见 §三。文案、字幕、版式规则都一致。
